## 产品概览

EasyAIoT 电力运维云平台在既有 IoT 底座（设备接入、物模型、时序数据、告警、视频、远程控制、可视化和移动端）上构建电力行业能力，形成「监测—告警—处置—运维—分析」闭环。平台面向高低压配电房多站点集团企业、电力运维服务商及其客户，让一个值班人员能远程掌握多个站点的设备、环境、视频、告警、运维和能源情况，并在安全控制边界内完成事件处置和经营分析。

产品范围分六大业务领域 + 平台基础能力，按 M1～M6 六个里程碑分阶段交付。电力运维仅支持 standard/full 两档（full 是 standard 的严格能力超集），mini 不在建设、交付和验收范围。

## 里程碑总览

|---|---|---:|---|

| M2 无人值守 | M1、统一告警、通知/视频联调 | 6～8 周 | 告警、通知、视频证据和处置形成闭环 |

| M6 高级分析 | M5、电价和电能质量样本 | 8～12 周 | 需量、电费、电能质量和综合月报可用 |

## 领域一：站点设备与数据采集（PRD-01，目标 M1）

### 站点与电力对象
- 支持企业、园区、站点、配电房、线路、回路、设备层级建模（PRD-01 §4.1）
- 设备可关联上级回路、产品模板、协议网关、地理位置和摄像机（PRD-01 §4.1）
- 支持高压柜、综保、变压器、直流屏、低压柜、电容柜、电表、水表、气表及环境传感器类型（PRD-01 §4.1）
- 对象编码创建后不可直接修改，变更须保留映射关系（PRD-01 §4.1）

### 电力物模型模板
- 模板包含属性、事件、服务、单位、精度、枚举、读写类型和采样建议（PRD-01 §4.2）
- 支持厂家模板继承标准模板并保留差异项（PRD-01 §4.2）
- 模板发布生成版本，已绑定设备不被未确认升级自动改变（PRD-01 §4.2）
- 支持点表导入、校验、预览和错误下载（PRD-01 §4.2）
- 厂家模板记录所继承标准模板版本，升级生成差异由用户选择合并；租户私有模板隔离，系统标准模板只读共享（PRD-01 §4.2）

### 协议与边缘采集
- 支持 RS485-Modbus RTU 的串口、波特率、数据位、停止位、校验位和站号配置（PRD-01 §4.3）
- 支持寄存器地址、功能码、数据类型、字节序、倍率、偏移和轮询周期配置（PRD-01 §4.3）
- 支持现有 Modbus TCP、OPC UA、MQTT 接入（PRD-01 §4.3）
- 配置发布到站点采集运行端返回版本和应用状态；M1 运行端为 `iot-sink collector profile`，EDGE 延至 M2（PRD-01 §4.3）
- 站点 collector 断网时缓存数据，恢复后按原始时间补传（PRD-01 §4.3）
- 同一物理串口请求串行化；发布前校验串口独占冲突、站号冲突、轮询时长和总线负载，无法满足时拒绝发布（PRD-01 §4.3）
- 寄存器 scale/offset 只负责协议解码，CT/PT 计量倍率由计量点应用，禁止两层重复换算（PRD-01 §4.3）

### 数据质量
- 每条数据包含设备、测点、采集时间、接收时间、值和质量码（PRD-01 §4.4）
- 质量码区分正常、超时、无效、越界、人工修正和补传（PRD-01 §4.4）
- 支持数据中断、时间漂移、固定值和异常跳变检测（PRD-01 §4.4）
- 质量异常不被普通业务告警误判为设备真实越限（PRD-01 §4.4）

### 实时与历史查询
- 实时页面显示值、单位、质量、更新时间和告警状态（PRD-01 §4.5）
- 支持多设备、多测点曲线对比（PRD-01 §4.5）
- 支持原始、分钟、小时、日粒度（PRD-01 §4.5）
- 支持最大、最小、平均、累计值和导出（PRD-01 §4.5）
- 查询统一依赖 TelemetryStore：standard 用 PostgreSQL 分区表，full 用 TDengine，业务层不感知差异（PRD-01 §4.5）
- 历史查询分页或异步导出并受 capability 配额约束；standard 默认最多 10 测点、31 天、10 万条（PRD-01 §4.5）

### 权限与审计
- 查看、配置、发布采集任务和修改物模型分别授权（PRD-01 §6）
- 实施人员只能访问被授权站点（PRD-01 §6）
- 点表导入和配置发布记录操作者、差异和结果（PRD-01 §6）

### 容量准入与部署档位
- 点位数、最小轮询周期、串口数、缓存字节数和历史查询上限由 capability manifest 声明，发布前做容量准入（PRD-01 §8）
- 电力采集仅支持 standard/full；mini 不部署电力采集任务、缓存、时序或菜单/API（PRD-01 §8）
- standard/full 使用同一设备身份、点表、collector、MQTT 消息和查询契约；full 仅提高规模与保留能力（PRD-01 §8）
- 配置发布支持回滚到上一版本（PRD-01 §8）

## 领域二：监控告警与安全控制（PRD-02，目标 M2-M3）

### 告警规则
- 支持大于、小于、区间、变化率、状态组合和多测点复合条件（PRD-02 §4.1）
- 支持持续时间、迟滞、恢复阈值、重复抑制和规则有效时段（PRD-02 §4.1）
- 支持信息、一般、重要、紧急四级（PRD-02 §4.1）
- 支持按设备模板下发默认规则并允许设备级覆盖（PRD-02 §4.1）
- 规则变更版本化，不影响既有告警历史解释（PRD-02 §4.1）
- 复合规则仅允许受控 AND/OR 条件组和白名单运算符，条件数、嵌套深度、时间窗和执行预算有硬上限（PRD-02 §4.1）

### 告警生命周期
- 告警状态机：ACTIVE、ACKNOWLEDGED、PROCESSING、ESCALATED、IGNORED、RECOVERED、FALSE_ALARM、CLOSED（PRD-02 §4.2）
- 告警恢复不自动删除告警（PRD-02 §4.2）
- 重复命中聚合到同一活动告警并更新次数和最后发生时间（PRD-02 §4.2）
- 维护模式只抑制通知，不删除采集和规则记录（PRD-02 §4.2）
- IGNORED 临时抑制通知须记录原状态、原因、操作者、截止时间，到期按策略恢复（PRD-02 §4.2）
- FALSE_ALARM 不可逆终态并要求独立复核，不得删除原始告警和证据（PRD-02 §4.2）
- 设备、视频、AI 告警统一映射到同一告警主记录和状态机，遵循 ADR-010（PRD-02 §4.2）

### 通知与值班
- 支持站点值班表、班组、人员和替班（PRD-02 §4.3）
- 支持 APP、站内信、短信、电话、企业微信等可配置渠道（PRD-02 §4.3）
- 通知记录发送、送达、失败、重试和确认状态（PRD-02 §4.3）
- 关键告警未确认时按时间和角色逐级升级（PRD-02 §4.3）
- 渠道故障不阻止告警创建（PRD-02 §4.3）
- 通知持久化后异步发送，故障按渠道退避，恢复后仅在有效窗口补发，过期触发备用渠道/升级（PRD-02 §4.3）

### 事故追忆
- 告警详情展示统一事件时间线（PRD-02 §4.4）
- 关联告警前后可配置时间窗内的遥测数据（PRD-02 §4.4）
- 关联现场图片、抓拍、录像、人员确认和设备操作（PRD-02 §4.4）
- 支持导出不可修改的事故报告及证据校验信息（PRD-02 §4.4）
- 事故追忆窗口受 TelemetryStore 查询与证据保留配额约束，超范围采用异步生成（PRD-02 §4.4）

### 安全遥控
- 适用于高低压开关、刀闸、电容柜投切、风机等高风险控制；低风险可配置简化流程但须授权与审计（PRD-02 §5.1）
- 流程：申请→状态与联锁预检→独立人员复核→进入有效执行窗口→执行人二次确认→下发命令→设备回执→状态复核与审计归档（PRD-02 §5.2）
- 申请人与审核人不得为同一人（PRD-02 §5.3）
- 服务端校验权限、站点范围、设备在线状态和联锁条件（PRD-02 §5.3）
- 批准默认有效 5 分钟、上限 15 分钟，只允许执行一次；目标动作/设备/联锁/操作票变化使批准失效（PRD-02 §5.3）
- 页面二次确认显示设备、动作、当前状态和影响（PRD-02 §5.3）
- 命令具有唯一 ID，禁止重复执行；超时不得自动重发非幂等动作（PRD-02 §5.3）
- 保存申请、审核、执行、回执和最终状态全链路（PRD-02 §5.3）
- 现场可配置硬禁用，平台不得绕过（PRD-02 §5.3）
- iot-device 是申请、审批、联锁、命令执行、回执和审计的唯一责任模块；其他模块通过 /device/control/** 发起（PRD-02 §5.3）

### 非功能与部署档位
- 告警创建 P95 不超过 5 秒（PRD-02 §7）
- 告警消费者幂等，支持积压和死信监控（PRD-02 §7）
- 安全遥控审计日志不得由普通业务用户删除（PRD-02 §7）
- 本域仅支持 standard/full；mini 不部署电力告警规则、通知或遥控能力（PRD-02 §7）
- standard 若未满足完整遥控依赖，必须整体关闭遥控 capability，不得提供简化安全版本（PRD-02 §7）
- full 在同一实现上只增加跨站治理、事故证据和集中审批能力，不降低或复制安全门禁（PRD-02 §7）

## 领域三：可视化 SCADA 与视频联动（PRD-03，目标 M2）

### 信息架构
- 分层可视化：集团总览→区域/园区→站点看板→（一次系统图、设备监控、环境监控、告警中心、视频监控、能源概览、运维概览）（PRD-03 §3）

### 站点看板
- 展示站点容量、电压等级、运行状态、在线设备、关键负荷和活动告警（PRD-03 §4.1）
- 展示温湿度、SF6、烟雾、水浸和入侵状态（PRD-03 §4.1）
- 展示当日/当月用能、最大需量和用能趋势（PRD-03 §4.1）
- 展示待巡检、未关闭缺陷和超期工单（PRD-03 §4.1）
- 指标点击进入来源页面，禁止只展示不可追溯数字（PRD-03 §4.1）

### 一次系统图
- 提供母线、进线、馈线、开关、刀闸、变压器、电容器和计量表图元（PRD-03 §4.2）
- 图元可绑定遥信、遥测、告警和控制服务（PRD-03 §4.2）
- 颜色和动画表达状态时同时提供文字或图标，避免只依赖颜色（PRD-03 §4.2）
- 支持在线编辑、版本保存、预览、发布和回滚（PRD-03 §4.2）
- 发布版本与草稿隔离，编辑错误不影响生产展示（PRD-03 §4.2）
- 控制操作必须跳转或调用安全遥控流程，不允许图元直接绕过审批（PRD-03 §4.2）
- 草稿采用版本号和乐观锁防静默覆盖；发布/回滚只改变生产指针，不删除其他草稿和历史版本（PRD-03 §4.2）

### 历史曲线与报表入口
- 一次图和看板可从设备或测点进入历史曲线（PRD-03 §4.3）
- 支持时间范围、粒度、多测点、统计值和导出（PRD-03 §4.3）
- 页面展示数据质量和缺失区间（PRD-03 §4.3）

### 视频联动
- 摄像机可绑定站点、区域、设备和预置位（PRD-03 §4.4）
- 告警发生时触发预置位、抓拍或指定时长录像（PRD-03 §4.4）
- 告警详情直接播放对应时间段录像（PRD-03 §4.4）
- 视频不可用时保留告警并展示失败原因（PRD-03 §4.4）
- 联动配置按站点、告警规则和摄像机授权；并发数、预置位占用、录像时长受 capability 配额（PRD-03 §4.4）
- 同一告警多个视频动作分别记录结果，失败不回滚或阻止告警创建（PRD-03 §4.4）
- PRD-02 与 PRD-03 共用同一 alarmId 和证据引用，不复制事故记录（PRD-03 §4.4）

### 非功能与部署档位
- 画面数据刷新频率可配置（PRD-03 §7）
- 实时画面优先使用 WebSocket 增量订阅；standard 单画面默认最多 500 个实时点、最快 1 秒刷新；断线重连先获取版本化快照再续订（PRD-03 §7）
- 多屏展示不得绕过登录和临时访问授权（PRD-03 §7）
- 视频凭据不得暴露在页面源码或持久 URL 中（PRD-03 §7）
- mini 不提供电力看板、SCADA 或电力视频联动（PRD-03 §7）
- standard 提供 WEB 内置站点总览、基础一次图查看、实时视频和基础告警抓拍关联；不提供画面编辑、发布、脚本或 FUXA 运行时（PRD-03 §7）
- full 在同一数据/API 契约上增加 VISUALIZE 大屏编辑发布、FUXA Web SCADA、预置位联动和事故录像证据（PRD-03 §7）
- 所有看板、一次图和视频钻取使用稳定资源 deep link，目标页面重新校验权限（PRD-03 §7）

## 领域四：设备档案与运维闭环（PRD-04，目标 M4）

### 设备档案
- 档案关联现有设备 ID，不重复建设设备主数据（PRD-04 §3）
- 包含厂家、型号、序列号、投运日期、质保期、供应商和联系人（PRD-04 §3）
- 附件支持图纸、说明书、试验报告、合格证、维保记录和其他分类（PRD-04 §3）
- 附件支持版本、上传人、有效期和权限（PRD-04 §3）
- 质保到期、试验到期和维护到期支持提醒（PRD-04 §3）
- 设备二维码可打印、吊销和重新生成（PRD-04 §3）
- 扫码后先鉴权，再展示该用户有权查看的设备信息（PRD-04 §3）

### 巡检标准与计划
- 巡检模板包含设备类型、检查项、步骤、方法、合格标准、必填证据和异常等级（PRD-04 §4.1）
- 计划支持日、周、月、Cron 或一次性周期（PRD-04 §4.1）
- 支持站点、路线、设备范围、班组、人员和完成时限（PRD-04 §4.1）
- 计划变更不修改已生成的历史任务（PRD-04 §4.1）

### 移动巡检执行
- 支持扫码确认设备（PRD-04 §4.2）
- 支持数值、单选、多选、文本、照片、视频、语音和签名结果（PRD-04 §4.2）
- 支持弱网离线执行和联网同步（PRD-04 §4.2）
- 可要求 GPS、站点围栏或蓝牙等到场证据，方式由站点配置（PRD-04 §4.2）
- 异常检查项可一键创建缺陷（PRD-04 §4.2）
- 离线动作使用客户端生成且重试不变的幂等 ID；服务端按任务版本校验，状态已前进时不被旧数据覆盖（PRD-04 §4.2）
- 附件在业务记录确认后独立续传，未确认成功前不得清理本地副本（PRD-04 §4.2）

### 缺陷管理
- 缺陷来源包括巡检、告警、人工上报和工单发现（PRD-04 §5）
- 包含设备、现象、等级、风险、图片、发现人和发生时间（PRD-04 §5）
- 支持确认、定级、分派、整改、验收、驳回和关闭（PRD-04 §5）
- 重大缺陷可自动创建抢修工单并通知负责人（PRD-04 §5）
- 缺陷关闭后保留全过程和关联工单（PRD-04 §5）
- 缺陷等级固定为一般、严重、危急；站点策略为各等级配置响应、整改、验收和升级时限；危急缺陷默认立即通知并进入抢修评估，降级须说明原因并审计（PRD-04 §5）

### 工单管理
- 类型包括抢修、检修、试验、保养和其他（PRD-04 §6）
- 支持草稿、审批、派单、接单、到场、处理中、暂停、转派、待验收、完成和取消（PRD-04 §6）
- 支持 SLA、优先级、预计时间和超期升级（PRD-04 §6）
- 记录人员、工时、材料、步骤、结果、证据和安全措施（PRD-04 §6）
- 验收不通过可退回处理，所有往返留痕（PRD-04 §6）
- 完成后支持客户或主管评价（PRD-04 §6）

### 跨域关联规则
- 告警、缺陷和工单通过稳定 ID 建立可追溯关联，各自保持独立状态机和责任人（PRD-04 §6.1）
- 告警恢复或关闭不自动关闭缺陷/工单；只追加关联事件并提示责任人复核（PRD-04 §6.1）
- 工单完成不自动关闭告警；可提交处置结果，由具备权限人员依据设备状态和证据关闭（PRD-04 §6.1）
- 缺陷只有在所有阻断性关联工单完成或经批准取消后才可关闭；关闭缺陷不改写原巡检结果（PRD-04 §6.1）

### 人员位置与隐私
- 定位必须由用户明确授权（PRD-04 §7）
- 只在工作任务和配置时段采集（PRD-04 §7）
- 用户可查看当前采集状态（PRD-04 §7）
- 管理者只能查看有组织权限人员的任务相关位置（PRD-04 §7）
- 历史轨迹按配置周期自动删除（PRD-04 §7）
- 不授权定位时按业务策略限制签到能力，不得隐蔽采集（PRD-04 §7）
- 首选到场证据不可用时按站点策略降级到备用证据或人工签到；记录失败原因、使用方式和可信度等级（PRD-04 §7）
- 高风险任务是否允许降级由策略预先确定，执行人员不得临时绕过（PRD-04 §7）

### 核心闭环
- 巡检计划→巡检任务→APP 执行→发现异常→缺陷→工单→处理→验收→关闭与评价→统计与月报（PRD-04 §8）

### 权限与部署档位
- 档案查看、档案维护、巡检配置、巡检执行、缺陷定级、工单派发和验收分别授权（PRD-04 §9）
- 工程师不得验收自己负责的高风险工单，除非配置明确允许且审计记录原因（PRD-04 §9）
- 附件下载使用临时授权地址（PRD-04 §9）
- APP 离线数据加密保存，成功同步后清理（PRD-04 §11）
- 工单历史采用追加式记录，不覆盖原动作（PRD-04 §11）
- standard：设备档案/二维码/基础巡检/缺陷/简化工单（无暂停、转派、独立验收、评价、备件、绩效）（PRD-04 §12）
- full：standard 全部 + 完整工单 SLA、暂停/转派/独立验收、评价、备件、绩效、跨站档案治理、完整离线作业、轨迹、签名、多媒体证据（PRD-04 §12）
- mini 不部署 iot-maintenance 电力能力、移动端电力入口或相关任务（PRD-04 §12）
- 定位、审计、权限和离线数据安全要求不得因 standard 档位而降低（PRD-04 §12）

## 领域五：能源管理与电能质量（PRD-05，目标 M5-M6）

### 能源组织与计量
- 支持企业、园区、站点、楼栋、楼层、车间、产线、回路等组织节点（PRD-05 §3）
- 计量点绑定设备测点，定义能源类型、倍率、方向、用途和结算周期（PRD-05 §3）
- 支持总表、分表和虚拟计量点（PRD-05 §3）
- 计量拓扑校验循环关系和重复计量（PRD-05 §3）
- 组织和计量关系按有效期管理，历史统计使用当时有效关系（PRD-05 §3）
- 计量点保存 currentRatio、voltageRatio、unitFactor、表计输出侧标记和公式版本；归一值后按公式计算业务值（PRD-05 §3）
- 倍率与组织关系变更创建带 effectiveFrom 新版本，经确认生效，不覆盖历史；生效时刻精确到秒，站点时区录入、UTC 保存（PRD-05 §3）

### 自动抄表
- 按计划生成抄表任务并读取指定时刻或周期值（PRD-05 §4）
- 支持失败重试、补抄、人工补录和复核（PRD-05 §4）
- 周期冻结值一经确认不可直接覆盖，修正必须产生新版本和原因（PRD-05 §4）
- 识别倒走、突变、长时间不变、缺失和倍率变化（PRD-05 §4）
- 支持电、水、气不同的累计值和单位（PRD-05 §4）
- 抄表计划复用平台调度、幂等、重试和可观测能力，但由能源域拥有抄表任务、读数和冻结状态（PRD-05 §4）

### 分类分项与对比
- 按组织、区域、能源类型、回路、设备和时间聚合（PRD-05 §5）
- 支持日、周、月、年及自定义周期（PRD-05 §5）
- 支持同比、环比、基线和目标偏差（PRD-05 §5）
- 支持单位面积、单位产量等强度指标；产量等外部数据通过接口或导入提供（PRD-05 §5）
- 所有结果可查看计算口径和数据完整率（PRD-05 §5）

### 最大需量
- 支持配置需量计算窗口和滑动方式（PRD-05 §6）
- 记录最大需量值、发生时间和对应时段（PRD-05 §6）
- 支持合同需量、目标需量和越限告警（PRD-05 §6）
- 缺失数据时不得静默生成完整结果，必须标记可信度（PRD-05 §6）
- 默认需量周期 15 分钟；固定/滑动窗口、步长和账单规则由版本化方案配置；正式费用分析使用合同/供电方确认方案（PRD-05 §6）

### 电价与费用
- 支持电价方案、尖峰平谷时段、节假日日历和方案有效期（PRD-05 §7）
- 计算各时段电量和电费（PRD-05 §7）
- 支持基本电费、需量费用和功率因数调整项的可配置模型（PRD-05 §7）
- 费用结果可按账期重算并保留使用的价格方案版本（PRD-05 §7）
- 系统费用用于分析，不默认替代供电企业正式账单（PRD-05 §7）

### 电能质量
- 支持电压、电流、频率、功率因数、三相不平衡和谐波/THD 指标（PRD-05 §8）
- 支持实时值、趋势、统计值和越限事件（PRD-05 §8）
- 指标计算口径、采样要求和有效数据率可配置并可追溯（PRD-05 §8）
- 不满足采样条件时显示"不具备计算条件"，不输出误导性结果（PRD-05 §8）
- 平台不得从普通低频遥测推导谐波/THD；首期只接收设备已计算且带算法/采样元数据的指标，或使用满足 Spec 最低采样条件的波形数据（PRD-05 §8）

### 非功能与部署档位
- standard 原始遥测由 PostgreSQL 分区表读取，full 由 TDengine 读取；业务冻结值和计算结果统一保存在关系库（PRD-05 §11）
- 聚合任务幂等，可按账期重算（PRD-05 §11）
- 算法、规则和价格方案均版本化（PRD-05 §11）
- 大范围报表使用异步任务生成，禁止阻塞 HTTP 请求（PRD-05 §11）
- standard：计量点、自动抄表、补抄、冻结值、基础台账、基础分类分项和用量统计（PRD-05 §12）
- full：standard 全部 + 最大需量、尖峰平谷、电费分析、电能质量、同比环比、目标偏差、强度指标、更大规模与集中治理（PRD-05 §12）
- mini 不部署 iot-energy 电力能力、聚合任务或相关菜单/API（PRD-05 §12）
- 两档的数据完整率、版本追溯、租户隔离和审计要求相同（PRD-05 §12）

### 非目标
- 首期不处理电力市场交易和售电结算（PRD-05 §13）
- 首期不承诺替代法定计量系统（PRD-05 §13）
- 首期不自动调整生产设备，仅提供分析和建议（PRD-05 §13）

## 领域六：报表与经营分析（PRD-06，目标 M5-M6）

### 报告类型
- 站点运行日报、周报和月报（PRD-06 §3）
- 告警与事故分析报告（含事件时间线、告警状态变化、通知/确认、处置动作、关联遥测完整率、媒体证据索引）（PRD-06 §3）
- 巡检、缺陷、工单和 SLA 报告（PRD-06 §3）
- 能耗、需量、电费和电能质量报告（PRD-06 §3）
- 多站点能效排行和运维质量对标（PRD-06 §3）
- 设备专项分析报告（含统计范围、运行/离线、关键测点趋势、告警、检修记录、健康结论、数据不足声明）（PRD-06 §3）

### 月度报告内容
- 概览：站点与容量、数据完整率、运行结论（PRD-06 §4）
- 设备运行：在线率、负荷与温度、健康评分（PRD-06 §4）
- 告警安全：等级分布、响应关闭、重大事故（PRD-06 §4）
- 运维：巡检完成率、缺陷闭环、工单 SLA（PRD-06 §4）
- 能源：分类分项、同比环比、最大需量、尖峰平谷费用、电能质量（PRD-06 §4）
- 建议：风险清单、下月计划（PRD-06 §4）

### 报告模板
- 支持系统模板和租户自定义模板（PRD-06 §5.1）
- 模板选择章节、指标、图表、排序和说明文本（PRD-06 §5.1）
- 指标引用统一口径，不允许模板自行编写不可审计 SQL（PRD-06 §5.1）
- 模板保存版本，历史报告使用原模板版本（PRD-06 §5.1）

### 报告生成
- 支持手动和按计划生成（PRD-06 §5.2）
- 大报告采用异步任务，显示进度和失败原因（PRD-06 §5.2）
- 生成时冻结统计范围、数据版本、计算口径和模板版本（PRD-06 §5.2）
- 数据完整率不足时显示警告，不静默输出确定性结论（PRD-06 §5.2）
- "冻结"采用不可变生成清单（查询范围、时区、源数据水位/冻结值版本、指标口径版本、模板版本、输入摘要）；同一幂等键只生成一个草稿；源数据修正后创建新修订版（PRD-06 §5.2）

### 审批、归档与发送
- 支持草稿、待审批、已批准、已发布、已作废状态（PRD-06 §5.3）
- 审批人可退回并填写意见（PRD-06 §5.3）
- 已发布报告不可直接覆盖，只能创建修订版（PRD-06 §5.3）
- 修订版通过 revisionOf 关联首次发布版本并使用连续修订号；记录修订原因、受影响章节/指标和前后差异摘要（PRD-06 §5.3）
- 报告及附件归档到 MinIO，并记录校验信息（PRD-06 §5.3）
- 支持按角色、客户和订阅策略发送通知或下载入口（PRD-06 §5.3）

### 钻取与追溯
- 报告指标可回到对应明细页面或数据查询条件（PRD-06 §5.4）
- 展示统计周期、时区、单位、数据完整率和口径版本（PRD-06 §5.4）
- 修正原始业务数据后可重算并生成新修订版（PRD-06 §5.4）
- 钻取使用稳定资源 deep link 和冻结查询上下文，目标页面重新执行权限校验；未启用/过保留期/无权限时钻取明确返回原因且不泄露数据（PRD-06 §5.4）

### 非功能与部署档位
- 报告任务支持失败重试，同一请求不产生重复发布版本（PRD-06 §8）
- 文件下载使用临时授权（PRD-06 §8）
- 报告生成资源限流，避免影响实时监控和告警（PRD-06 §8）
- PDF/Excel 版式经过自动结构检查和视觉抽检；自动门禁检查文件可打开、页数/工作表、必需章节、字体嵌入、表格截断、图表占位、页码、空白异常和数据摘要一致性（PRD-06 §8）
- 发布模板首次上线和重大版式变更必须 100% 视觉抽检，稳定模板按版本化抽检策略执行（PRD-06 §8）
- standard：预置运行/告警/用量报表、手工触发与导出、系统预置模板（PRD-06 §9）
- full：standard 全部 + 综合月报、SLA、电费、电能质量、多站点经营分析、定时生成、审批归档、订阅发送、租户自定义模板与品牌化报告（PRD-06 §9）
- mini 不部署电力报告模板、生成任务或入口（PRD-06 §9）
- 综合报告首期作为能源与运维域组合应用，不单独复制业务事实或建设通用 BI 服务（PRD-06 §9）

### 非目标
- 首期不建设通用 BI 自助建模平台（PRD-06 §10）
- 首期不允许用户执行任意数据库查询（PRD-06 §10）
- 报告建议不自动触发高风险设备控制（PRD-06 §10）

## 平台基础能力（跨领域）

### 部署档位与单一实现原则
- 电力运维云平台仅面向 standard/full，mini 不在建设、交付和验收范围（平台功能计划 §1.1）
- mini 安装、升级、运行时必须保持电力能力关闭，菜单/任务/服务不得以启动异常方式暴露不可用能力（平台功能计划 §1.1）
- mini 升级为 standard/full 后按正式迁移流程启用电力模块；降级到 mini 前必须导出或迁移电力业务数据（平台功能计划 §1.1）
- standard 与 full 是同一产品能力组合，禁止创建两套同语义 Controller/Service/页面/数据库表/消息 Topic/设备协议实现（平台功能计划 §1.4）
- 共有功能必须使用相同 API、DTO、权限点、状态机、事件契约、数据模型和测试基线（平台功能计划 §1.4）
- standard 升级 full 只允许启用高级模块、提高配额和执行向前兼容迁移；不得替换核心设备身份、API、Topic 或历史数据（平台功能计划 §1.4）
- 测试必须证明 Capabilities(standard) ⊂ Capabilities(full)，并运行同一套合同测试（平台功能计划 §1.4）

### Capability Manifest（能力清单）
- 档位差异由统一 capability manifest 表达，至少包含能力编码、是否启用、配额、依赖和不可用原因（平台功能计划 §1.4，遵循 ADR-011）
- 后端、前端、安装脚本和许可证读取同一来源，禁止各自维护冲突的档位判断（平台功能计划 §1.3）
- 功能规模上限、数据保留期和并发预算在 Technical Design 与容量测试后冻结（平台功能计划 §1.3）

### 租户与权限
- 复用用户、角色、菜单、数据权限、多租户基础（iot-system），增加电力运维岗位和操作权限点（平台功能计划 §4.1、§8.7）
- 新增权限域：energy:dashboard:view、energy:meter:manage、energy:reading:review、energy:tariff:manage、energy:report:export、maintenance:archive:manage、maintenance:inspection:execute、maintenance:defect:assign、maintenance:work-order:dispatch、maintenance:work-order:accept、device:control:switch、device:control:approve（平台功能计划 §8.7）
- 远程分合闸"申请/执行"和"审核"权限分离，保存完整审计记录（平台功能计划 §8.7）
- 跨领域只保存稳定业务标识，不建立跨服务数据库外键；引用有效性通过 API 和事件校验（平台功能计划 §8.2）

### 统一遥控入口
- iot-device 是遥控申请、审批状态机、联锁校验、命令执行、回执和审计的唯一责任模块，统一 API 为 /device/control/**（平台功能计划 §8.4）
- iot-energy、iot-maintenance、WEB、APP、SCADA 只能创建带业务关联 ID 的控制申请或查询结果，不得直接发布设备命令、写设备影子或调用 iot-sink 内部接口（平台功能计划 §8.4）
- 同一 controlRequestId 全链路幂等；任何模块超时都不得绕过原申请重新生成无关联命令（平台功能计划 §8.4）

### TelemetryStore 与时序存储适配
- TelemetryStore 统一接口：standard 固定使用 PostgreSQL 分区时序表，full 使用 TDengine；业务层不维护两套业务逻辑（平台功能计划 §1.2、§4.1、§8.6，遵循 ADR-006）
- standard 原始遥测进入 PostgreSQL 分区表并执行准入配额；full 高频遥测进入 TDengine（平台功能计划 §8.6）
- 分钟、小时、日、月聚合结果可进入 PostgreSQL 或独立 TDengine 聚合表（平台功能计划 §8.6）
- 表计冻结值、修正记录、电价、工单、缺陷和档案元数据进入 PostgreSQL（平台功能计划 §8.6）

### 事件总线与 Kafka 事件
- 新增 Kafka 事件：device.telemetry.reported.v1、device.alarm.created.v1、device.alarm.recovered.v1、meter.reading.frozen.v1、inspection.task.overdue.v1、defect.created.v1、work-order.status.changed.v1（平台功能计划 §8.5）
- 事件必须携带 eventId、eventVersion、tenantId、occurredAt、source 和业务关联 ID；消费者必须幂等（平台功能计划 §8.5）
- 事件 JSON Schema 存放于生产者 iot-*-api 资源目录，CI 执行向后兼容检查（平台功能计划 §8.5）
- 破坏性升级遵循"消费者先兼容→生产者双发→对账→消费者切换→停止 v1"，双发至少跨一个完整发布周期（平台功能计划 §8.5）

### 统一调度与任务能力
- 抄表计划复用平台调度、幂等、重试和可观测能力（PRD-05 §4，平台功能计划 §8.5）
- 报告生成支持手动和按计划生成，大报告异步任务（PRD-06 §5.2）
- 告警消费者幂等，支持积压和死信监控（PRD-02 §7）

### 文件存储
- 图纸、手册、报告、巡检照片和工单附件进入 MinIO（iot-file）（平台功能计划 §4.1、§8.6）
- APP 离线巡检数据进入本地临时存储，联网后按幂等键同步；服务端成功后清除（平台功能计划 §8.6）

### 时间与时区管理
- 时间事实统一保存 UTC 毫秒时间戳并同时记录来源时区（平台功能计划 §8.6）
- 业务统计使用站点 IANA 时区，周期统一采用左闭右开 [start, end)（平台功能计划 §8.6）
- 冻结任务精确到秒，禁止依赖服务器默认时区（平台功能计划 §8.6）

### 可观测性
- 采集成功率、数据延迟、告警延迟、通知送达率、工单 SLA、队列积压（平台功能计划 §8.9）
- 关键日志携带站点、网关、设备和测点标识（PRD-01 §8）

### 数据质量治理
- 无效值、跳变、断点、时间漂移、倍率变化和人工修正均需留痕（平台功能计划 §8.9）
- 告警创建 P95 不超过 5 秒；采集断点续传、消息幂等、有限重试、死信和任务补偿（PRD-02 §7，平台功能计划 §8.9）

### 隐私合规
- 人员定位必须授权、可关闭、限定用途并设置保留周期（平台功能计划 §8.9）
- 原始轨迹默认保留 90 天后删除或匿名化；导出、延长保留和管理查看必须单独授权并审计（平台功能计划 §8.6）

### APP 移动端框架
- APP 新增一级业务入口"运维"（capability 驱动，不替换首页；standard/full 启用，mini 和无权限用户不创建空白入口）（平台功能计划 §8.8）
- 运维首页含扫一扫、我的巡检、我的工单、缺陷上报、设备档案、告警处置、位置签到、消息中心（平台功能计划 §8.8）
- 关键移动能力：扫码进入设备详情、查看实时状态/历史告警/巡检/工单、离线巡检与断点续传、拍照录像语音签名证据、定位授权签到轨迹上传、工单接单转派暂停处理提交验收（平台功能计划 §8.8）

### 业务控制面模块划分
- iot-system（用户、角色、班组）、iot-device（设备、产品、物模型、控制）、iot-energy（新增：计量、需量、电费、电能质量）、iot-maintenance（新增：档案、巡检、缺陷、工单）、iot-visualize（大屏、组态、数据源）、iot-message（通知模板与渠道）、iot-file（图纸、报告、附件）（平台功能计划 §5）
- iot-energy 通过 OpenFeign 获取设备/产品/测点信息，通过 Kafka 消费遥测事件，通过 TelemetryStore 查询时序数据；不直接操作 iot-device 或时序后端数据库（平台功能计划 §8.1）
- iot-maintenance 通过设备 API 关联设备，系统 API 关联用户/班组，文件 API 保存附件，消息服务发送任务和工单通知（平台功能计划 §8.1）

## 部署档位能力矩阵

| 能力 | mini | standard | full |
|---|---|---|---|
| 边缘采集、缓存、补传 | 不支持 | 必须 | 必须 |
| 实时监控与告警 | 不支持 | 必须 | 必须 |
| 视频联动 | 不支持 | 基础 | 完整事故证据 |
| 站点看板与一次图 | 不支持 | WEB 基础查看 | 大屏编辑 + FUXA SCADA |
| 安全遥控 | 不支持 | 可选；启用即执行完整安全门禁 | 完整安全门禁 + 集中治理 |
| 运维闭环 | 不支持 | 基础巡检、缺陷、工单 | 完整 SLA、轨迹、评价和绩效 |
| 能源聚合与报告 | 不支持 | 抄表、冻结、基础统计和预置报表 | standard 全部 + 高级能源与经营报表 |
| 高级电费与电能质量 | 不支持 | 不提供 | 必须 |
| 多站点经营分析 | 不支持 | 不提供 | 必须 |

> 三个档位复用同一代码主线；mini 通过 capability manifest 关闭全部电力能力，full 仅启用 standard 之上的高级模块和配额，不重复开发共享功能。档位能力编码、依赖、配额和不可用原因遵循 ADR-011；服务端必须执行能力门禁，菜单隐藏只负责交互，不构成授权。

## MVP 范围

### MVP 必须包含
- 单站点配电房设备树
- 高压柜/变压器/低压柜/环境监测产品模板
- RS485/Modbus RTU 采集链路
- 实时状态/历史曲线/阈值告警
- 值班通知/告警确认关闭
- 一次系统图与站点看板
- 视频实时查看/告警抓拍回放
- 安全远程控制申请审核执行回执
- 设备档案与二维码
- 简化版巡检任务和缺陷上报

### MVP 暂不包含
- 复杂电价结算和力调电费
- 高级谐波诊断算法
- 完整备品备件库存
- 多级外包商结算
- AI 自动生成运维决策

> MVP 最低部署档位为 standard，不以 mini 作为开发/演示/验收环境。

## 非目标（首期不建设）

- 电力交易、售电结算或电网调度主站
- 替代继电保护装置的保护逻辑
- 完整 ERP、财务会计或仓储系统
- 无安全联锁的自动高压操作
- 基于未经验证 AI 结论的自动分合闸
- 通用 BI 自助建模平台
- 用户执行任意数据库查询
