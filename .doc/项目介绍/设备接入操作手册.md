## 1. 接入总览

### 1.1 接入链路

所有协议的遥测数据最终归一到统一 MQTT 可靠链路进入平台：

```
设备（任意协议）
   ├─ MQTT 直连 ────────────┐
   ├─ 网关代理（子设备）─────┤
   ├─ Modbus TCP ── iot-sink ┤→ EMQX (QoS1) → 中心 Inbox → TelemetryStore
   └─ Modbus RTU ── 站点 collector（串口轮询 + SQLite 断网缓存）┘
```

### 1.2 协议接入方式一览

| 协议 | 接入方式 | 设备侧要求 | 适用场景 |
|---|---|---|---|
| **MQTT** | 设备直连 EMQX 发布上行 Topic | 设备实现 MQTT 3.1.1/5 client | 智能硬件、网关、电表模块 |
| **网关+子设备** | 网关以自身身份连接，代理子设备上下行 | 网关设备支持 MQTT | Zigbee/LoRa/RS485 汇聚网关 |
| **Modbus TCP** | iot-sink 主动轮询设备（TCP 502） | 设备/串口服务器作为 Modbus TCP 从站 | 综保、仪表、PLC 联网设备 |
| **Modbus RTU** | 站点 collector 持串口轮询 RS485 总线 | RS485 从站设备（站号唯一） | 电表、传感器串口总线 |
| **OPC UA** | iot-sink 作为 OPC UA client 读取 | 设备提供 OPC UA Server | PLC、工业控制系统 |
| **TCP** | 设备连平台网关 8091 端口，首包 auth | 设备支持私有 TCP 长连接 | 定制协议设备 |
| **HTTP** | 设备 POST 上报，配合协议脚本 | 设备可发 HTTP 请求 | 低成本上报类设备 |

### 1.3 MQTT Topic 契约（所有 MQTT 类接入共用）

| 方向 | Topic | 用途 |
|---|---|---|
| 上行 | `/iot/{产品标识}/{设备标识}/property/upstream/report` | 属性上报（影子/运行状态/时序入库） |
| 下行 | `/iot/{产品标识}/{设备标识}/property/downstream/desired/set` | 云端设置属性期望值 |
| 上行 | `/iot/{产品标识}/{设备标识}/property/upstream/desired/set/ack` | 设备回复属性设置 ACK |
| 下行 | `/iot/{产品标识}/{设备标识}/service/downstream/invoke/{服务标识}` | 云端调用设备服务 |
| 上行 | `/iot/{产品标识}/{设备标识}/service/upstream/invoke/{服务标识}/response` | 设备应答服务调用 |
| 上行 | `/iot/{产品标识}/{设备标识}/event/upstream/report/{事件标识}` | 事件上报 |
| 上行 | `/iot/{产品标识}/{设备标识}/log/upstream/report` | 设备日志上报 |

> 依据 ADR-017：此 Topic 为唯一权威契约，QoS 1；设备 ACL 只允许发布/订阅自身精确 Topic，禁止 `#` 通配。网关子设备在 `/iot/{网关产品}/{网关设备}/sub/#` 下代理。

### 1.4 属性上报报文格式（JSON）

```json
{
  "tenantId": 1,
  "requestId": "a1b2c3d4e5f60718",
  "method": "thing.property.post",
  "params": {
    "temperature": 23.5,
    "humidity": 56.2
  }
}
```

- `tenantId`：租户 ID（默认 1）
- `requestId`：请求唯一标识（用于幂等）
- `method`：固定 `thing.property.post`
- `params`：键为物模型属性 `propertyCode`，值为上报值

## 2. 第一步：创建产品并配置协议与认证

产品是设备接入的模板：**协议类型、认证方式、物模型都在产品上配置，设备自动继承**。

### 2.1 操作路径

WEB 管理控制台 → 左侧菜单「**产品管理**」→「新增产品」（或编辑既有产品）

### 2.2 基础信息

| 字段 | 说明 | 示例 |
|---|---|---|
| 产品名称 | 显示名 | 我的电表模块 |
| 产品类型 | 直连设备 / 网关设备 / 网关子设备 / 视频设备 | 直连设备 |
| 厂家 / 型号 | 厂商信息 | — |

### 2.3 传输协议（关键配置）

在「传输协议」区块：

| 字段 | 可选值 | 说明 |
|---|---|---|
| **协议类型** | MQTT / HTTP / TCP / Modbus TCP / Modbus RTU / OPC UA / GB28181 | 决定设备接入方式，设备侧不可改 |
| **数据格式** | JSON / 二进制（BINARY） | JSON=标准物模型报文；BINARY=配合协议脚本自定义编解码 |
| 连接实例 | iot-sink 连接器标识 | 一般留空用默认 |
| **认证方式** | 用户名密码 / Access Token / 证书认证 | MQTT/EMQX 鉴权方式 |

### 2.4 认证信息

「认证信息」区块（认证方式选「用户名密码」时）：

| 字段 | 说明 |
|---|---|
| 用户名 | 设备接入 EMQX 的用户名 |
| 密码 | 设备接入 EMQX 的密码 |
| 签名密钥 | 可选，用于签名认证 |

> 同一产品下的所有设备共用这套认证。生产环境建议每个产品独立凭据，并定期轮换。

### 2.5 保存与发布

填写完成后保存。产品创建成功后进入产品详情可继续配置物模型（下一步）。

## 3. 第二步：配置物模型

物模型定义设备「有什么属性、什么服务、什么事件」，是 JSON 报文 `params` 键的依据。

### 3.1 操作路径

「产品管理」→ 产品行点击进入**产品详情** → 「物模型」Tab → 「新增属性 / 新增服务 / 新增事件」

### 3.2 属性定义

| 字段 | 说明 | 示例 |
|---|---|---|
| 属性名称 | 显示名 | 温度 |
| **属性标识（propertyCode）** | 报文 `params` 中的键，创建后不可改 | `temperature` |
| 数据类型 | int / float / double / string / bool / enum / date / struct | float |
| 单位 / 精度 | 计量单位与小数位 | ℃ / 1 |
| 读写类型 | 只读 / 可读可写 | 只读 |

### 3.3 服务与事件

- **服务**：云端可调用的设备功能（如 `reboot`），对应下行 Topic `/service/downstream/invoke/{identifier}`
- **事件**：设备主动上报的事件（如 `overTempAlarm`），对应上行 Topic `/event/upstream/report/{identifier}`

### 3.4 工业协议说明

Modbus TCP/RTU、OPC UA 等工业协议产品：物模型以**属性**为主，点位映射在设备侧配置（寄存器地址↔属性），**无需 JS 协议脚本**。BINARY/私有协议设备才需要在产品「协议脚本」中上传 JS 编解码脚本（见 6.4）。

## 4. 第三步：创建设备

### 4.1 操作路径

「设备管理」→「新增设备」

### 4.2 填写字段

| 字段 | 说明 | 示例 |
|---|---|---|
| 设备名称 | 显示名 | 1号配电房电表 |
| **设备标识（deviceIdentification）** | Topic 中的设备身份，唯一且创建后不可改 | `meter-001` |
| 所属产品 | 选择第二步创建的产品（决定协议） | 我的电表模块 |
| 客户端 ID（clientId） | MQTT clientId，留空系统自动生成 | — |
| 设备描述 / 备注 | 可选 | — |

### 4.3 接入配置区说明

选择产品后，抽屉自动显示接入协议提示：

- **MQTT**：「设备使用 MQTT 协议接入，凭据由平台根据产品认证配置自动生成」→ 设备侧**无需再配置**，凭据到第 5 步查看
- **Modbus TCP**：显示连接配置表单（主机地址/端口/站号/轮询周期），见第 8 章
- **Modbus RTU**：显示串口配置表单（串口名/波特率/数据位/停止位/校验位/站号），见第 8 章
- **未显示协议**：所选产品未配置协议类型，回到产品设置

### 4.4 工业设备点位配置

Modbus 类设备创建后，还需在设备详情配置**点位表**（寄存器地址、功能码、数据类型、字节序、倍率、偏移、轮询周期），将物模型属性映射到寄存器，见 8.3。

## 5. 第四步：获取接入凭据与联调命令

设备详情抽屉 →「**接入指引**」Tab（最重要的联调入口，所有参数按当前设备实时生成，可一键复制）。

### 5.1 各子 Tab 说明

| Tab | 内容 |
|---|---|
| **推荐命令** | 可直接复制执行的 mqtt-demo 联调命令（自动带好产品/设备/租户/密码参数） |
| **联调参数** | Broker 地址（默认 localhost:1883）、鉴权模式（设备身份/Broker 直通）、租户 ID——修改后命令自动更新 |
| **连接鉴权** | 该设备的完整连接参数：用户名、密码、clientId、Broker 地址，逐项可复制 |
| **Topic** | 该设备全部标准 MQTT Topic 清单，可复制 |
| **报文** | 属性上报/服务调用的样例 JSON，可复制 |
| **验收** | 检查清单（影子刷新、在线状态、时序入库等） |

### 5.2 鉴权模式选择

| 模式 | 用途 |
|---|---|
| **设备身份（device）** | 标准模式，用产品认证的用户名/密码 + 设备标识连接 |
| **Broker 直通（broker）** | 本地快速联调用（密码 123456），生产环境必须启用 EMQX HTTP 鉴权（→ iot-sink `/mqtt/auth`） |

### 5.3 生产环境要求

生产部署必须：EMQX 启用 HTTP 认证指向 iot-sink `/mqtt/auth`；设备 ACL 只允许发布自身精确上行 Topic、订阅自身精确 ACK Topic（ADR-017 约束）。

## 6. MQTT 直连设备接入

### 6.1 快速联调（mqtt-demo 脚本，推荐）

平台仓库内置联调脚本，位于 `.scripts/mqtt-demo/`：

```bash
# 1. 进入脚本目录（仓库根目录下）
cd .scripts/mqtt-demo

# 2. 安装依赖（仅首次）
pip install paho-mqtt

# 3. 属性上行——让设备立刻有数据、变在线（推荐先跑）
python3 01_uplink_property.py \
  --host localhost \
  --port 1883 \
  --product <产品标识> \
  --device <设备标识> \
  --tenant-id 1 \
  --password <产品认证密码>

# 4. 下行监听 + 自动回执（另开终端）
python3 02_downlink_listen.py \
  --host localhost --port 1883 \
  --product <产品标识> --device <设备标识> \
  --tenant-id 1 --password <密码>

# 5. 上下行同进程（可选，快速演示）
python3 03_full_loop.py \
  --host localhost --port 1883 \
  --product <产品标识> --device <设备标识> \
  --tenant-id 1 --password <密码>
```

**验收**：
- `01` 脚本 → 设备详情「影子/运行状态」有数据，设备列表显示**在线**
- `02` 脚本运行中 → 页面对设备「功能调用」下发服务 → 终端打印下行 Topic

> 以上命令在设备「接入指引 → 推荐命令」Tab 中已按当前设备自动拼好，直接复制即可，无需手填参数。

### 6.2 常驻运行（.env 方式）

```bash
# 保存凭据为 .env（接入指引 Tab 可直接生成下载）
cat > .scripts/mqtt-demo/.env <<'EOF'
MQTT_HOST=localhost
MQTT_PORT=1883
PRODUCT=<产品标识>
DEVICE=<设备标识>
TENANT_ID=1
PASSWORD=<密码>
AUTH_MODE=device
EOF

bash start_mqtt_demo.sh    # 启动
bash stop_mqtt_demo.sh     # 停止
```

### 6.3 真实设备固件接入要点

设备固件需实现：

1. MQTT 连接：Broker 地址/端口 + clientId（设备标识）+ 产品认证的用户名/密码
2. QoS 1 发布属性到 `/iot/{产品标识}/{设备标识}/property/upstream/report`，payload 见 1.4
3. 订阅 `/iot/{产品标识}/{设备标识}/service/downstream/invoke/+` 接收服务调用并回复 response
4. 心跳：周期上报（默认 30s 内有任意上报即保持在线）

### 6.4 私有协议（紧凑文本）接入

若设备不方便发 JSON（如嵌入式紧凑报文 `EA|UP|...`）：

1. 产品详情 →「协议脚本」→ 上传 JS 编解码脚本（模板见 `.scripts/mqtt-demo/product_script_compact_text.js`，可用 `upload_product_script.py` 辅助上传）
2. 数据格式选 BINARY 或启用对应脚本
3. 联调：

```bash
# 私有协议上行
python3 04_codec_uplink.py --host localhost --port 1883 \
  --product <产品标识> --device <设备标识> --tenant-id 1 --password <密码>
# 验收：影子出现属性；iot-sink 日志含 JS 上行解码

# 私有协议下行（EA|DN|... 非 JSON）
python3 05_codec_downlink.py --host localhost --port 1883 \
  --product <产品标识> --device <设备标识> --tenant-id 1 --password <密码>
```

## 7. 网关与子设备接入

适用于：Zigbee/LoRa/RS485 汇聚网关，下挂多个子设备。**子设备不直连 MQTT，由网关代理**。

### 7.1 前置配置

1. 创建**网关产品**（产品类型=网关设备，协议 MQTT）+ 物模型
2. 创建**子设备产品**（产品类型=网关子设备）+ 物模型
3. 创建网关设备（选网关产品）；创建子设备（选子设备产品，**父设备选网关**）

### 7.2 联调命令

```bash
# 01. 网关代报子设备（推荐先跑）：建连 → topo 添加子设备 → 周期代报
python3 06_gateway_uplink_subdevice.py \
  --host localhost --port 1883 \
  --product <网关产品标识> --device <网关设备标识> \
  --tenant-id 1 --password <密码> \
  --sub-product <子设备产品标识> \
  --sub-device demo-sub-001 \
  --sub-name 演示子设备

# 验收：网关「子设备」Tab 出现设备；子设备影子/运行状态刷新；网关在线

# 02. 网关代收下发并自动 ACK（另开终端保持运行）
python3 07_gateway_downlink_subdevice.py \
  --host localhost --port 1883 \
  --product <网关产品标识> --device <网关设备标识> \
  --tenant-id 1 --password <密码> \
  --sub-product <子设备产品标识> --sub-device demo-sub-001 --sub-name 演示子设备

# 验收：子设备详情「功能调用」下发 → 网关终端打印 /sub/... 下行
```

### 7.3 网关代理 Topic

子设备上下行走网关代理 Topic（payload 内携带子设备标识）：

```
/iot/{网关产品标识}/{网关设备标识}/sub/#     （网关订阅范围）
```

## 8. Modbus TCP / RTU 工业设备接入

### 8.1 产品配置

产品「协议类型」选 **Modbus TCP** 或 **Modbus RTU**：

- 工业协议产品**物模型以属性为主**，点位映射在设备侧配置，无需 JS 协议脚本
- 认证配置不适用（平台主动采集，不涉及设备侧凭据）

### 8.2 设备配置

设备新增/编辑抽屉中，选工业协议产品后出现「连接配置」：

**Modbus TCP：**

| 字段 | 说明 | 常用值 |
|---|---|---|
| 主机地址 | 设备/串口服务器 IP | 192.168.1.100 |
| 端口 | Modbus TCP 端口 | 502 |
| 站号 | Modbus unitId | 1 |
| 轮询周期 | 采集间隔（ms） | ≥1000 |

**Modbus RTU：**

| 字段 | 说明 | 注意 |
|---|---|---|
| 串口名称 | collector 所在主机可见端口 | Windows `COM3`；Linux `/dev/ttyUSB0` |
| 波特率/数据位/停止位/校验 | 必须与从站一致 | 常用 9600/8/1/N |
| 站号 | 同一 RS485 总线必须唯一 | 1~247 |

配置后可点「**测试连接**」：TCP 验证主机端口可达；RTU 验证串口能否打开（不校验寄存器内容）。

### 8.3 点位表配置（寄存器映射）

设备详情 → 点位/映射配置，将物模型属性映射到寄存器：

| 字段 | 说明 |
|---|---|
| 物模型属性 | 目标 propertyCode |
| 功能码 | 保持寄存器 / 输入寄存器 / 线圈 / 离散输入 |
| 寄存器地址 | 从站寄存器偏移 |
| 数据类型 | INT16/UINT16/INT32/UINT32/FLOAT32/INT64/FLOAT64 |
| 字节序 | AB/BA/ABCD/CBDA 等 |
| 倍率（scale）/ 偏移（offset） | 协议解码换算：`归一值 = 原始值 × scale + offset` |

> **换算边界（重要）**：寄存器 scale/offset 只做协议解码与单位归一；CT/PT 计量倍率由能源计量点按有效版本应用，两层禁止重复换算（PRD-01 §4.3）。

### 8.4 RTU 部署架构（M1 权威方式）

RS485 设备按 [SPEC-003](../规格/电力运维云平台/SPEC-003-RS485-Modbus-RTU采集产品化.md)/[TD-001](../技术设计/电力运维云平台/TD-001-collector与NODE部署契约.md) 由站点 collector 采集：

```
WEB 点表配置 → iot-device 发布单 → iot-node 编排 → NODE Agent 部署
→ iot-sink collector profile（持有串口轮询）
→ 断网时写本地 SQLite Outbox 缓存，恢复后按原始时间补传
→ MQTT QoS1 上行中心
```

- collector 必须部署在**能直接访问物理串口**的站点节点，由 NODE 管理生命周期
- 发布前平台自动校验：串口独占冲突、站号冲突、轮询时长、总线负载——不满足**拒绝发布**（不会静默降频）
- 同一物理串口请求串行化；单次合并读取默认最多 120 个 16 位寄存器

## 9. OPC UA / TCP / HTTP 设备接入

### 9.1 OPC UA

1. 产品协议类型选 **OPC UA**
2. 配置物模型属性
3. 创建设备，按界面提示填写 OPC UA 服务器连接信息（端点地址、安全策略、认证）
4. 平台（iot-sink）作为 OPC UA client 读取节点并按物模型归一上报

### 9.2 TCP 私有协议

1. 产品协议类型选 **TCP**
2. 设备固件连接平台网关 **8091 端口**，建立 TCP 长连接，**首包发送 auth 方法**完成认证
3. 之后按平台 TCP 协议规范收发；可配合产品协议脚本做编解码

### 9.3 HTTP

1. 产品协议类型选 **HTTP**，**数据格式选 JSON 并配置物模型**（或 BINARY+协议脚本）
2. 设备向平台 HTTP 接口 POST 上报（接口地址在设备「接入指引」查看）
3. HTTP 为短连接上报，设备在线状态依赖上报周期

## 10. 验收与故障排查

### 10.1 接入验收清单

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 设备在线状态 | 列表显示「在线」 |
| 2 | 影子/运行状态 | 设备详情数据随上报刷新，值与单位正确 |
| 3 | 时序入库 | 历史曲线/遥测查询出现数据点 |
| 4 | 下行链路 | 页面「功能调用」→ 设备/脚本终端收到下行并回执 |
| 5 | 历史曲线 | 多测点对比、粒度切换正常 |
| 6 | 断网恢复（工业链路） | 断网期间数据进本地缓存，恢复后补传无重复 |
| 7 | 权限隔离 | 换普通账号无法查看他人站点设备/点表 |

### 10.2 常见问题

| 现象 | 排查方向 |
|---|---|
| 设备一直离线 | ① Broker 地址/端口是否可达（容器内 localhost 指自身，应为 emqx-server）② 用户名/密码是否产品认证配置的原值 ③ clientId 是否与其它设备冲突 |
| 连上但影子无数据 | ① Topic 是否精确匹配（产品/设备标识顺序）② payload 的 `params` 键是否与物模型 propertyCode 一致 ③ `tenantId` 是否正确 |
| 连接被拒（认证失败） | 生产模式检查 EMQX HTTP 鉴权是否指向 iot-sink `/mqtt/auth`；本地联调可切 Broker 直通模式 |
| 功能调用无响应 | 设备是否订阅了 `/service/downstream/invoke/+`；02 号脚本是否在运行 |
| 私有协议解码失败 | 产品「协议脚本」是否已启用并发布；JS 脚本与报文格式是否匹配 |
| Modbus 读不到数 | 「测试连接」验证连通；核对接线、站号、波特率；点位表功能码/地址/字节序与设备手册核对 |
| RTU 发布被拒绝 | 平台串口独占/站号冲突/总线负载校验未过——检查同串口其他任务与轮询周期 |
| 属性值偏差一个倍率 | 检查是否在寄存器 scale 和计量点倍率两层重复换算 |

### 10.3 安全红线（宪法约束）

- 不得在任何文档、日志、交付说明中回显凭据明文
- 设备 ACL 禁止 `#` 通配订阅生产授权
- 不同租户设备/点表必须隔离，越权访问会被服务端拒绝并审计
- 凭据泄露后必须立即在产品配置中轮换
