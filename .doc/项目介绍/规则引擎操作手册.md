## 1. 规则引擎是什么

「规则引擎」菜单（`/rulechains`）是平台内嵌的 **Node-RED 流程编排器**：

- 拖拽节点 → 连线 → 部署，即可实现**消息路由、协议转换、告警分流、联动控制**等数据流逻辑
- 底层为独立容器 `nodered-server`（端口 1880），WEB 页面经 nginx 代理管理其 flows（`/dev-api/nodeRed/`）
- 编辑器与后端通过 WebSocket（`/dev-api/nodeRed/comms`）实时通信

**典型用途**：设备消息中转、第三方系统对接（HTTP/Modbus/MQTT 互转）、告警分级推送、AI 结果联动控制。

> ⚠️ 区分：本规则引擎是**通用数据流编排**；电力业务告警规则（阈值/复合条件/状态机）属于 M2 告警中心功能，不在本页面配置。

## 2. 页面总览与列表操作

进入路径：左侧菜单「**规则引擎**」→「规则列表」Tab。

### 2.1 工具栏

| 按钮 | 作用 |
|---|---|
| **新增规则** | 弹出抽屉：名称（必填）+ 状态勾选（勾=启用） |
| **导入规则** | 上传 JSON（⚠️ 当前为半成品：仅校验文件，未真正落库；导入请用 9.2 种子脚本或 Node-RED 原生导入） |
| **切换视图** | 表格视图 ↔ 卡片视图 |
| **批量删除** | 勾选多条后删除 |

### 2.2 行操作

| 操作 | 说明 |
|---|---|
| 👁 详情 | 抽屉查看调试/错误/统计/生命周期事件 |
| ✏️ 编辑 | 修改名称、启停状态 |
| 🔗 编辑规则链 | **进入 Node-RED 画布**（核心操作，见第 4 章） |
| 🗑 删除 | 删除规则链（演示链无此按钮） |

### 2.3 启停控制

列表「状态」Tag：**启用（蓝）/ 禁用（红）**。「编辑」里勾选/取消「状态」切换。禁用的链不执行但保留定义。

## 3. 新增规则链

1. 点「新增规则」→ 填写：
   - **名称**（必填，如 `车间温度监控`）
   - **状态**：勾选 = 启用
2. 保存 → 列表出现新链（此时是**空画布**）
3. 点该行 🔗「编辑规则链」→ 进入画布开始编排（第 4 章）
4. 编排完成后 **Deploy** 生效

> 命名建议：链路用途 + 来源，如 `1号配电房-告警分级`。避免与演示链同名（`设备遥测采集链路` 等 4 个名称有只读保护逻辑）。

## 4. 编辑器操作（节点画布）

点「编辑规则链」后进入内嵌 Node-RED 编辑器（iframe `/rulechains/index/{id}`）。

### 4.1 界面分区

```
┌─────────────────────────────────────────────┐
│ 左侧节点面板 │      中央画布        │ 右侧信息 │
│ (按类分组)   │  (拖入/连线/选中等)   │ (帮助/调试)│
├─────────────────────────────────────────────┤
│ 右上角：Deploy 部署按钮 │ 侧栏: 调试/信息/节点列表 │
└─────────────────────────────────────────────┘
```

### 4.2 基本操作

| 操作 | 方法 |
|---|---|
| 添加节点 | 左面板拖入画布（或点节点后点画布） |
| 配置节点 | 双击节点 → 属性面板 → Done |
| 连线 | 从节点右侧输出端口拖到下一节点左侧输入端口 |
| 删除连线 | 点线上的圆点 |
| 启用/禁用节点 | 选中节点 → 点右下角启停按钮 |
| **部署** | 右上角 **Deploy**（不部署不生效！） |
| 快捷键 | Ctrl+I 导入、Ctrl+E 导出、Ctrl+Z 撤销 |

### 4.3 消息（msg）模型

Node-RED 的数据单元是 `msg` 对象，链路上流动：

```javascript
msg = {
  payload: ...,   // 主数据（必懂）
  topic: "...",   // 主题/路由标识
  // 各节点可附加字段，如 msg.level、msg.quality
}
```

大多数节点只处理 `msg.payload`，用 function/change 节点变换它。

## 5. 常用节点配置示例

### 5.1 MQTT 输入（mqtt in）— 订阅设备消息

双击节点配置：
- **服务器**：新增 MQTT broker（演示链内置 `EasyAIoT Demo MQTT` = 127.0.0.1:1883；生产改实际 EMQX 地址）
- **订阅主题**：如 `/easyaiot/demo/+/telemetry`（`+` 匹配单层）
- 输出：`msg.payload` = 消息体，`msg.topic` = 实际主题

### 5.2 函数（function）— JS 变换数据

演示链「点位→物模型映射」的实际代码（可直接参考）：

```javascript
const regs = (msg.payload && msg.payload.registers) || {};
msg.payload = {
    productKey: 'easyaiot-demo-plc',
    deviceName: 'PLC-LINE-A',
    timestamp: Date.now(),
    properties: {
        speed_rpm: Number(regs['40001'] || 0),
        motor_run: Number(regs['40002'] || 0) === 1,
        pressure_kpa: Number(regs['40003'] || 0) / 10,
        quality: msg.payload.quality || 'unknown'
    }
};
msg.topic = 'easyaiot/demo/PLC-LINE-A/property/post';
return msg;
```

要点：`return msg;` 结尾；可 `return [msg1, msg2];` 多路输出。

### 5.3 开关（switch）— 条件分流

演示链「温度阈值」的规则（三条出口）：

| 出口 | 条件 | 去向 |
|---|---|---|
| 1 | `>= 45`（数值） | 标记：过热告警 |
| 2 | `>= 35`（数值） | 标记：温度预警 |
| 3 | else | 标记：正常 |

属性：属性栏选 `msg.payload.temperature`，规则依次从上到下匹配（顺序即优先级）。

### 5.4 修改（change）— 设置字段

给消息打标记/映射字段：
- **Set** `msg.level` = `紧急`
- **Change** 搜索替换 payload 内容
- **Move** `msg.payload.data` → `msg.payload`

### 5.5 模板（template）— 生成文本

通知内容模板（Mustache 语法）：

```
【{{payload.level}}告警】
设备：{{payload.deviceName}}
内容：{{payload.message}}
时间：{{payload.timestamp}}
```

### 5.6 MQTT 输出（mqtt out）— 发布消息

topic 填目标主题（如 `easyaiot/demo/PLC-LINE-A/property/post`），或留空用 `msg.topic` 动态决定（演示链即此用法）。

### 5.7 其他常用

| 节点 | 用途 |
|---|---|
| inject | 手动/定时注入测试消息（`模拟温度上报`就是它） |
| http in / http response | 暴露 HTTP 接口接收外部回调 |
| http request | 调用外部 HTTP API |
| debug | 调试输出（配合右侧调试栏） |
| delay / trigger | 限流、防抖、超时 |
| join / split | 聚合/拆分消息 |

## 6. 四条内置演示链详解

种子导入后的 4 条只读演示链（`easyaiot_demo_*`），是最好的学习样例：

### 6.1 设备遥测采集链路（10 节点）

```
mqtt in(遥测订阅) ──→ function(补全时间戳) → function(解析遥测JSON) → switch(温度阈值)
inject(模拟温度上报) ──────────────────────────↑                        ├ ≥45 → change(过热告警) ─┐
                                                              ├ ≥35 → change(温度预警) ─┼→ debug(遥测结果)
                                                              └ else → change(正常)    ─┘
```
**学**：MQTT 接入 → 解析 → 阈值分流的经典结构。

### 6.2 告警分级推送链路（8 节点）

```
inject(模拟告警事件) ──┐
inject(模拟紧急告警) ──┴→ function(规范化告警) → switch(按级别分流)
                                            ├ 紧急 → template(紧急通知模板) ─┐
                                            ├ 重要 → template(重要通知模板) ─┼→ debug(推送内容)
                                            └ 一般 → template(一般通知模板) ─┘
```
**学**：多来源归一 → 按字段三路分流 → 各自模板渲染。

### 6.3 工控协议桥接链路（5 节点）

```
inject(模拟工控点位) → function(点位→物模型映射) → switch(仅上行good) → mqtt out(MQTT物模型上报)
                                                       └→ debug(映射结果)
```
**学**：Modbus 寄存器值 → 物模型属性 → MQTT 上报的协议桥接（function 代码见 5.2）。

### 6.4 视觉质检联动链路（10 节点）

```
http in(POST /easyaiot/demo/vision/inspect) ─→ function(解析AI质检结果) → switch(OK/NG)
inject(模拟NG结果) ─────────────────────────────────↑                ├ OK → change(放行)
                                                                      └ NG → change(剔除联动) → function(组装指令) → mqtt out(下发剔除指令)
                                  function(HTTP响应) → http response ←┘
```
**学**：HTTP 回调触发 → AI 结果判定 → 控制指令下发的联动闭环。

### 6.5 演示链运行方式

演示链的 `inject` 节点（模拟温度上报/模拟告警事件等）：
- 打开画布 → 点 inject 节点左侧方块按钮 → 立即注入一条模拟消息 → 看 debug 栏输出
- MQTT 类节点需要 broker 可达（`EasyAIoT Demo MQTT` 指向 127.0.0.1:1883，即平台 EMQX）

## 7. 典型场景实操

### 场景 A：给设备遥测做温度告警（从零开始）

1. 「新增规则」：名称 `温度告警测试`
2. 进入画布，依次拖入并配置：
   - `mqtt in`：订阅 `/easyaiot/demo/+/telemetry`（或你的设备真实 Topic）
   - `function`：`return {payload: JSON.parse(msg.payload)};`（解析）
   - `switch`：属性 `msg.payload.temperature`，规则 `>= 45`
   - `change`：Set `msg.payload.alarm` = `过热`
   - `debug`：输出完整消息
3. 连线：mqtt in → function → switch(出口1) → change → debug
4. **Deploy**，往订阅 Topic 发测试消息（可用 `.scripts/mqtt-demo/01_uplink_property.py` 改造），右侧调试栏看到 `过热` 即通

### 场景 B：告警消息转发企业微信/短信网关

在 6.2 演示链基础上，把 `debug` 换成 `http request`：
- Method: POST，URL: 你的通知网关地址
- Headers: Content-Type: application/json
- Payload: 上游 template 生成的 JSON

### 场景 C：HTTP 回调 → 设备控制

参照 6.4 视觉链：`http in`（定义 URL）→ 业务 function → `mqtt out`（下发指令到设备下行 Topic）→ `http response` 返回处理结果。

## 9. 只读保护与运维

### 9.1 演示链四层防护（不要试图绕过）

| 层 | 行为 |
|---|---|
| WEB 前端 | 4 条演示链隐藏编辑/删除按钮 |
| Node-RED settings.js 中间件 | 拒绝 PUT/DELETE 演示页签；Deploy 后回填锁定副本 |
| 编辑器脚本 | 演示页签禁用 Deploy |
| nginx | `easyaiot_demo_*` 路径仅 GET（实测 PUT 返回 403） |

### 9.2 常用运维命令

```bash
# 恢复/重置演示链（幂等，自建链保留）
bash .scripts/node-red/seed_nodered_demo.sh
# 生产环境直连内网执行：
NODERED_URL=http://<内网IP>:1880 bash .scripts/node-red/seed_nodered_demo.sh

# 重启（settings.js 变更后生效）
docker restart nodered-server

# 健康检查
curl -sf http://127.0.0.1:1880/ >/dev/null && echo OK
```

### 9.3 修改演示链的正确姿势

1. 直连内网 `http://<内网IP>:1880`（绕过公网只读）
2. 修改 → 导出 JSON → 覆盖仓库 `.scripts/node-red/easyaiot_flows_demo.json` 固化
3. 被改坏时跑 9.2 种子脚本整包恢复

## 10. 常见问题

| 现象 | 原因与解决 |
|---|---|
| 「丢失与服务器的连接，重新连接...」 | `/dev-api/nodeRed/comms` WebSocket 被代理截断——确认 nginx nodeRed 块含 `proxy_set_header Upgrade $http_upgrade` 等三行（本环境已修复于 `WEB/conf/nginx.conf`） |
| 「导入规则」上传后什么都没发生 | 该功能当前为半成品（仅读文件未落库）——用 Node-RED 原生导入（Ctrl+I）或种子脚本 |
| 「导入规则」弹窗点保存报 `form instance has not been obtained` | 同上半成品问题；源码已加拦截提示，待前端重新构建生效 |
| Deploy 后链没跑 | ① 忘点 Deploy ② 链状态为「禁用」③ mqtt broker 不可达（节点下蓝点） |
| 演示链改不了/删不掉 | 正常，四层只读保护；需定制走 9.3 |
| 规则引擎菜单不显示 | 部署档位非 full（standard/mini 隐藏该菜单） |
| 新建链与演示链重名后异常 | 避免使用 4 个演示链名称；已中招则改名或删除自建链 |
| 节点连不上 EMQX | 检查 broker 配置地址：容器内应为 `emqx-server:1883` 或宿主可达 IP，不是 `localhost`（在容器内指向自身） |
