# ADR-009：物模型模板版本策略

> 状态：Accepted  
> 日期：2026-07-30  
> 决策范围：M1 电力物模型模板  
> 关联：POWER-SPEC-002  
> 产品基线：平台功能计划 1.5.0 / 项目开发宪法 1.6.0

## 决策

模板对外版本采用 SemVer `MAJOR.MINOR.PATCH`，模板 ID/数据库主键与版本号分离。已发布版本不可原地修改。

| 级别 | 触发条件 | 示例 | 默认升级行为 |
|---|---|---|---|
| MAJOR | 删除必选属性、改变 propertyCode/数据类型/单位语义、收紧范围导致现有值非法、改变服务风险语义 | `1.4.2 → 2.0.0` | 必须人工评审、影响预览和迁移计划 |
| MINOR | 向后兼容新增可选属性/事件/服务、放宽范围、增加标准映射 | `1.4.2 → 1.5.0` | 可选择升级，不自动改现有产品 |
| PATCH | 不改变机器契约的文案、示例、翻译或元数据修正 | `1.4.2 → 1.4.3` | 可提示安全升级，仍保留审计 |

- 新增 `required=true` 属性视为 MAJOR；产品实例化必须执行 TM-009。
- 发布记录保存规范化内容哈希、创建来源、基线版本和结构化差异。内容先转换为版本化 canonical JSON（字段排序、数值和空值规则固定），再使用 SHA-256；记录 `canonicalizationVersion` 与 `hashAlgorithm=SHA-256`。
- 厂家模板记录标准模板精确版本，不使用浮动范围；标准模板升级不自动改变厂家模板。
- 预发布标签 MAY 用于草稿/试点，但生产产品只允许绑定正式版本。预发布版本可归档；只有未被试点产品、配置快照或审计记录引用时才可物理清理，清理必须遵循可配置保留期并留审计。
- 同一模板版本内容哈希不同必须拒绝发布；系统模板使用全局模板 ID，不归属业务租户。租户派生时创建新的租户内唯一模板 ID 和独立版本线，并保存 `baseTemplateId + baseVersion`，不得与其他租户共享可写版本记录。

## 升级和兼容

- 升级预览必须列出受影响产品、设备、RTU 点位、告警规则、SCADA 绑定和 API 消费者。
- MAJOR 升级必须提供属性映射、数据迁移/双读期限和回滚版本。
- 旧版本进入 `DEPRECATED` 后仍可运行；只有无产品绑定且兼容期结束才能 `RETIRED`。
- propertyCode 仅显示名称变化时保持不变；语义变化创建新 propertyCode。

## 被否决方案

- **单纯递增整数**：无法表达兼容性和自动化门禁。
- **日期版本**：不能直接判断破坏性变化。
- **发布后原地修改**：无法复现设备配置和历史数据语义。

## 回滚

产品保存升级前精确模板版本和绑定快照。升级失败时恢复旧版本及绑定；已按新语义产生的数据不删除，必须按 configVersion 保持可解释。
