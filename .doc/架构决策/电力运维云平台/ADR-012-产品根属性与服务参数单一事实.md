# ADR-012：产品根属性与服务参数单一事实

> 状态：Accepted
> 决策日期：2026-08-05
> 决策范围：现有产品 TSL 运行表与 M1 电力物模型模板绑定
> 关联：SPEC-002、ADR-009、TD-005 1.0.7
> 证据：[TD-005 目标数据库与现有实现画像报告](../../技术设计/电力运维云平台/TD-005-目标数据库与现有实现画像报告.md)、[TD-005 运行模型兼容与删除链技术设计](../../技术设计/电力运维云平台/TD-005-运行模型兼容与删除链技术设计.md)、[ADR 评审报告 §11](../../开发规范/ADR评审报告.md)

## 1. 背景

目标数据库 `postgres-server / iot-device20` 与仓库实现共同证明：

- `product_properties` 表示产品或模板根级属性，不存在 `service_id`；
- `product_services`、`product_commands`、`product_commands_requests`、`product_commands_response` 已形成服务、命令、输入参数和输出参数链；
- `ProductPropertiesMapper` 的基础列、upsert 和批量查询仍引用不存在的 `service_id`；
- `findAllByServiceId` statement 已被注释但 Java 接口和调用者仍可调用；
- `ProductPropertyParamVO/ProductPropertyResultVO` 仍把 `serviceId` 当作必填或返回字段；
- `ProductServiceImpl`、`ProductTemplateServiceImpl`、`RemoteProductPropertiesService` 和 `ProductModelCacheService` 仍依赖旧“服务属性”模型；
- 新增的 `ProductServiceThingModelHelper` 已从 command request/response 读取服务入参与出参，证明替代路径可行，但尚未覆盖旧聚合、缓存、Feign 和删除链。

直接为 `product_properties` 增加可空 `service_id` 会形成“根属性与服务参数共表/分表并存”的双事实，并掩盖现有 Mapper/API 漂移。该问题必须先由 ADR 决定事实归属，再进入代码修复。

## 2. 决策

### 2.1 运行事实

| 业务成员 | 唯一运行事实 | 关联事实 | 禁止 |
|---|---|---|---|
| 产品/模板根级遥测或配置属性 | `product_properties` | `tenant_id + product_identification/template_identification + property_code` | 使用 `service_id` 表示服务参数 |
| 服务定义 | `product_services` | 产品或模板作用域 | 在属性表复制服务身份 |
| 服务命令 | `product_commands` | `service_id → product_services.id` | 用根属性记录代替命令 |
| 服务输入参数 | `product_commands_requests` | `commands_id → product_commands.id` | 同时写入 `product_properties` |
| 服务输出参数 | `product_commands_response` | `commands_id → product_commands.id` | 同时写入 `product_properties` |
| 事件输出参数 | `product_event_response` | `event_id → product_event.id` | 在产品删除链中遗漏 |

`product_commands_requests/response.service_id` 是当前兼容影子列，不是独立关联事实。M1 新代码必须通过 `commands_id` 解析所属服务；兼容期写入值必须由命令的 `service_id` 派生并校验一致，不得接受客户端自行指定。该影子列按“扩展—迁移—收缩”在后续主版本移除。

### 2.2 Java 与 API 边界

1. 不向 `product_properties` 新增 `service_id`。
2. 数据库 DO、API Request/Response VO 分离；不得继续把 `ProductProperties` 这类公共 VO 直接作为 Mapper 实体。
3. 根属性 DTO 不暴露 `serviceId`；服务参数使用独立 `ServiceInputParam/ServiceOutputParam` 语义。
4. `ProductPropertyParamVO/ProductPropertyResultVO` 只作为旧接口兼容类型，标记废弃期限，不得进入新 `/api/v1/power` 契约。
5. `findAllByServiceId/selectPropertiesByServiceIdList` 从生产调用链移除；服务参数统一从 command request/response 查询。
6. 旧 Feign/聚合接口在兼容期可由 adapter 将 command 参数投影为旧形状，但不得回写 `product_properties`。
7. 模板成员和运行表成员通过 `model_binding_id/model_member_fingerprint` 或独立映射表关联，不复用 `service_id` 推断模板来源。
8. standard/full 复用同一 Controller、Service、Mapper、DTO、表和测试；mini 不启用电力模板能力。

### 2.3 删除与租户边界

- 单条删除必须委托同一个批量删除编排器；批量删除是全有或全无事务。
- 删除前按 tenant 锁定产品；存在设备、历史服务调用、未完成 OTA、ACTIVE 模板绑定或其他受保护下游引用时拒绝删除。
- 允许删除时按“参数 → 命令 → 服务、事件参数 → 事件、根属性、产品脚本 → 产品”顺序显式执行；不级联删除设备或历史事实。
- 所有运行表 CRUD 必须由 `TenantLineInnerInterceptor` 和数据库复合约束双层保护；禁止依赖客户端提交 `tenantId`，禁止对这些表使用 `@TenantIgnore`。
- 跨租户按 ID 访问统一表现为资源不存在，写入不得产生部分数据。

## 3. 被否决方案

### A. 为 `product_properties` 补回 `service_id`

否决。它会与 command request/response 形成双写、双读和差异/快照歧义，且不能解释为什么现有表已按命令参数分离。

### B. M1 立即新建统一 TSL member 表替换全部运行表

否决。一次替换属性、事件、服务、命令和设备运行链的回归面过大，会把模板版本控制与运行时重构耦合。后续如需统一表，必须独立 ADR。

### C. 保留不同 API 各自选择来源

否决。它无法定义发布 hash、绑定快照、差异和回滚的唯一事实，并继续保留确定性的 BindingException/缺列 SQL。

### D. 删除旧接口但不提供兼容窗口

否决。旧聚合和缓存仍有仓库内调用者，直接删除违反宪法“消费者兼容 → 双版本运行 → 迁移监控 → 下线旧版”。

## 4. 兼容迁移

采用扩展—迁移—收缩：

1. 建立含根属性、服务、命令、输入和输出参数的非空 fixture，以及旧格式 round-trip golden。
2. 新增分离的 DO/VO/Mapper 和 tenant-safe repository，不改变旧端点。
3. 将详情、缓存、导入导出和模板快照改为根属性与 command 参数分别读取。
4. 旧服务属性端点改由兼容 adapter 投影，记录调用量和调用方，不再查询 `product_properties.service_id`。
5. 完成租户、唯一约束、删除中途失败和 standard/full 同结果合同测试后启用新路径。
6. 兼容窗口至少持续到 M1 GA 后 6 个月；调用量连续一个发布周期为零、迁移通知完成且回滚演练通过后，方可删除旧 DTO、Feign 方法和影子列。

回滚只切回兼容 adapter 和旧响应形状，不恢复 `product_properties.service_id`，也不把服务参数复制回根属性表。

## 5. 决策接受依据

本 ADR 的 `Accepted` 表示事实归属已冻结，依据为：

- 本地目标集成实例画像确认 `product_properties.service_id` 不存在，孤儿数据已清零；
- 仓库调用点、Mapper、VO、缓存和删除链清单已形成；
- 候选方案对单一事实、兼容性、租户与 standard/full 单一实现的影响已比较；
- ADR 评审未发现必须改变事实归属的阻断项。

`Accepted` 不表示代码已经修复或 TD-005 已冻结。以下事项继续作为 TD-005 实现/发布门禁：

- Mapper/DO/VO 漂移归零并通过编译、Mapper statement 启动检查；
- 非空产品旧格式导入 → 运行表 → 导出 round-trip golden；
- 根属性、服务、命令、输入/输出参数 CRUD 与失败回滚合同；
- tenant `1/2` 交叉访问、写入和批量 ID 混入测试；
- 唯一、XOR scope、同租户引用与删除保护约束落库并完成迁移/回滚演练；
- 单条/批量产品删除的全链路和逐步骤故障注入；
- standard/full 相同结果、mini 无入口；
- 生产环境按画像 Schema 重跑并附原始输出。

## 6. 结果与影响

正向影响：消除根属性/服务参数双事实，模板 canonical/hash、绑定快照、差异、缓存和服务调用可使用同一来源；standard/full 无需重复实现。

代价：需要迁移旧聚合 DTO、Feign 和缓存调用，增加兼容 adapter 与一轮数据库约束迁移；`service_id` 影子列在兼容窗口内仍需一致性校验。

风险：旧调用者清单不完整、租户拦截器在自定义 XML 上行为不一致、删除链遗漏历史/设备引用。上述风险由 TD-005 合同测试、数据库 RESTRICT 约束和生产重跑门禁控制。
