# ADR-010：统一告警模型与存量迁移

> 状态：Accepted  
> 日期：2026-07-30  
> 决策范围：M2 告警中心  
> 影响章节：《平台功能计划》8.3、8.5、11  
> 产品基线：平台功能计划 1.4.0 / 项目开发宪法 1.4.0

## 背景

现有代码至少存在两类告警事实：`iot-device` 的阈值告警使用 `OPEN/CLEARED`，`iot-sink` 的 `AlertDO` 对应 VIDEO 告警记录且没有统一处置状态。若新增一套电力状态机，将形成多个入口、ID 和统计口径。

## 决策

在 `iot-device` 建立唯一告警主记录 `alarm_record`，作为状态、确认、处置、关闭和审计的唯一事实源；各来源记录保留为证据/来源明细，不复制处置状态。

- 主记录使用全局 `alarmId`，字段至少包含租户、站点、来源类型/来源 ID、设备/测点、规则版本、等级、当前状态、首次/最近发生、恢复时间、关闭时间和版本号。
- 阈值、VIDEO、AI、设备主动事件通过版本化 `AlarmRaised`/`AlarmRecovered` 事件进入统一告警服务。
- `iot-sink AlertDO`、VIDEO 告警和原阈值表继续保存原始证据，通过 `sourceType + sourceId` 唯一映射到 `alarmId`。
- WEB/APP 的“当前告警、未恢复告警、历史告警”统一查询告警主记录；原接口保留兼容期并内部转调新服务。
- standard/full 共用告警主记录、状态机、事件和 API；full 只启用复合规则、跨站治理和事故证据扩展。mini 不启用电力告警 capability。

状态机：

```text
ACTIVE → ACKNOWLEDGED → PROCESSING → RECOVERED → CLOSED
   ├→ ESCALATED ────────────────────────────────┤
   ├→ IGNORED(until, reason) → ACTIVE/ACKNOWLEDGED
   └→ FALSE_ALARM(reason, reviewer) [terminal]
```

- `IGNORED` 是有截止时间的临时通知抑制，不删除事件；进入时必须原子保存 `ignoredFromStatus`、`ignoredUntil`、原因和操作者，到期仅在记录仍处于同一次忽略且版本匹配时恢复 `ignoredFromStatus`，防止覆盖期间发生的恢复/关闭。M2 紧急等级禁止忽略，不提供配置放开；如需改变必须另行安全 ADR。
- `FALSE_ALARM` 是不可逆业务判定，必须有原因、判定人、复核人和时间；如需恢复只能创建纠正记录，不改写历史。
- 设备恢复只转换为 `RECOVERED`，不自动 `CLOSED`。

## 迁移

1. 扩展新表和事件，不改旧读路径。
2. 为存量 OPEN/CLEARED 和 VIDEO Alert 生成稳定 source 映射及 alarmId；迁移任务可重跑。
3. 双写新旧模型并对账当前未恢复数量、等级和来源证据。
4. 切换 WEB/APP 查询到统一告警 API，保留旧 API 至少一个发布周期。
5. 停止旧状态写入；来源证据表继续保留，旧处置字段进入只读。

### 存量映射与对账

- 迁移映射表对 `(tenantId, sourceType, sourceId, cycleKey)` 建唯一约束并持久保存 `alarmId`，重跑先查映射，不重新生成 ID。
- 历史阈值 `OPEN` 映射为 `ACTIVE`；`CLEARED` 映射为 `RECOVERED`，不推断为 `CLOSED`。若旧记录存在可靠的确认/处置证据，按证据映射并保存转换依据。
- M2 首次迁移中每条不可变 VIDEO/AI `AlertDO` 记录一对一生成告警周期；只有来源明确提供稳定的相关键和版本化窗口规则时才允许聚合，禁止用迁移脚本临时按时间猜测合并。
- 对账按租户、来源类型、等级、状态、source 映射、发生/恢复时间和证据数量执行；缺失映射和重复映射必须为零，语义转换差异必须进入批准清单。切换前至少完成一次全量对账和一个双写观察窗口，窗口时长在迁移 TD 冻结。

### 告警周期唯一性

活动周期幂等键至少包含 `(tenantId, sourceType, sourceObjectId/deviceId, propertyCode, ruleId, ruleVersion, cycleKey)`；不适用字段使用明确空值规范。恢复后再次发生默认创建新 `cycleKey` 和新告警周期；若规则允许在 `reopenWindow` 内重开，窗口和行为必须随规则版本保存，不能改变历史周期。

## 验收与回滚

- 同一来源重复事件只生成一个逻辑告警周期；恢复后再次发生创建新周期或按规则重开，策略必须版本化。
- 切换前后“未恢复告警”数量必须逐租户对账，差异为零或有批准的差异清单。
- 回滚只切换读路径和停止新消费者，不删除新主记录或迁移映射。
