# PRD-01：站点设备与数据采集

> PRD ID：POWER-PRD-001  
> 版本：1.2.0  
> 状态：Approved / Baselined（M1）  
> 基线日期：2026-07-31  
> 优先级：P0  
> 目标里程碑：M1  
> 基线：[《平台功能计划》1.5.0](../../架构设计/平台功能计划.md)、[《EasyAIoT 项目开发宪法》1.6.0](../../开发规范/EasyAIoT项目开发宪法.md)

## 1. 目标

建立电力站点、配电房、回路、设备、测点和计量点的统一模型，使高低压设备、变压器、直流屏、电容柜、环境传感器及表计的数据可靠进入平台。

## 2. 现状与建设方式

| 分类 | 内容 |
|---|---|
| 直接复用 | 产品、设备、子设备、物模型、MQTT、设备状态；full 复用 TDengine |
| 修改增强 | 电力设备模板、测点编码、数据质量、多曲线查询 |
| 新增 | RS485 串口配置、Modbus RTU 点表、边缘缓存补传、能源计量点、`TelemetryStore` 档位存储适配 |

## 3. 角色与用户故事

- 作为实施工程师，我希望导入厂家点表并绑定设备，以减少逐点配置。
- 作为电气主管，我希望按站点和一次回路查看设备树，以理解设备关系。
- 作为值班人员，我希望看到实时值、质量状态和最后更新时间，以判断数据是否可信。
- 作为运维人员，我希望设备离线和数据中断能够区分，以便采取正确措施。
- 作为平台管理员，我希望模板可版本化并复用于多个租户站点。

## 4. 功能需求

### 4.1 站点与电力对象

- 支持企业、园区、站点、配电房、线路、回路和设备层级。
- 设备可关联上级回路、产品模板、协议网关、地理位置和摄像机。
- 支持高压柜、综保、变压器、直流屏、低压柜、电容柜、电表、水表、气表及环境传感器类型。
- 对象编码创建后不可直接修改；变更须保留映射关系。

### 4.2 电力物模型模板

- 模板包含属性、事件、服务、单位、精度、枚举、读写类型和采样建议。
- 支持厂家模板继承标准模板，并保留差异项。
- 模板发布后生成版本；已绑定设备不会被未确认升级自动改变。
- 支持点表导入、校验、预览和错误下载。
- 模板升级与回滚遵循 ADR-009：厂家模板记录所继承的标准模板版本，升级时生成差异并由用户选择合并；租户私有模板不得被其他租户读取或引用，系统标准模板只读共享。

### 4.3 协议与边缘采集

- 支持 RS485-Modbus RTU 的串口、波特率、数据位、停止位、校验位和站号配置。
- 支持寄存器地址、功能码、数据类型、字节序、倍率、偏移和轮询周期。
- 支持现有 Modbus TCP、OPC UA、MQTT 接入。
- 配置发布到站点采集运行端后必须返回版本和应用状态；M1 运行端为 `iot-sink collector profile`，EDGE 延至 M2 评估。
- 站点 collector 断网时缓存数据，恢复后按原始时间补传。
- 同一物理串口请求必须串行化；发布前校验串口独占冲突、站号冲突、预计轮询时长和总线负载。预计轮询周期无法满足时拒绝发布并给出冲突点位，不得静默降低采样频率。
- 寄存器 `scale/offset` 只负责协议解码与单位归一；CT/PT 等计量倍率由计量点按有效版本应用，禁止在两层重复换算。

### 4.4 数据质量

- 每条数据至少包含设备、测点、采集时间、接收时间、值和质量码。
- 质量码区分正常、超时、无效、越界、人工修正和补传。
- 支持数据中断、时间漂移、固定值和异常跳变检测。
- 质量异常不得被普通业务告警误认为设备真实越限。

### 4.5 实时与历史

- 实时页面显示值、单位、质量、更新时间和告警状态。
- 支持多设备、多测点曲线对比。
- 支持原始、分钟、小时、日粒度。
- 支持最大、最小、平均、累计值和导出。
- 查询 API 统一依赖 `TelemetryStore`：standard 使用 PostgreSQL 分区时序表，full 使用 TDengine；页面和业务模块不得感知或复制后端差异。
- 历史查询必须分页或异步导出并受 capability 配额约束。standard 原始查询默认最多 10 个测点、31 天和 100,000 条；超过限制应提高聚合粒度、缩小范围或提交导出任务，禁止无界查询。

## 5. 异常与边界

- 同一串口不得存在冲突的独占采集任务。
- 重复补传数据必须按设备、测点和时间幂等处理。
- 设备时间超出允许偏差时标记质量问题，不直接覆盖服务器时间。
- 模板升级失败不得使现有采集任务停止。
- 边缘存储达到阈值时应按策略处理并告警，不得无限增长。

## 6. 权限

- 查看、配置、发布采集任务和修改物模型分别授权。
- 实施人员只能访问被授权站点。
- 点表导入和配置发布必须记录操作者、差异和结果。

## 7. 验收标准

- 可通过 UI 完成一个 RS485 电表从点表导入到实时显示。
- 断网 30 分钟后恢复，数据可补传且无重复。
- 错误 CRC、超时和非法数值显示为不同质量状态。
- 同一设备至少 10 个测点可在一张历史图中对比。
- 不同租户无法查看或配置对方设备及点表。
- 连续运行 7 天后输出采集成功率、延迟和中断统计。

## 8. 非功能要求

- 站点 collector 的采集任务数量、轮询周期和缓存大小可配置。
- 点位数、最小轮询周期、串口数、缓存字节数和历史查询上限由 capability manifest 声明；配置发布前必须做容量准入，不以“可配置”绕过硬上限。
- 电力站点设备与数据采集仅支持 standard/full；mini 不部署电力采集任务、缓存、时序或相关菜单/API。
- standard/full 使用同一设备身份、点表、collector、MQTT 消息和查询契约；full 仅提高规模与保留能力。
- 配置发布支持回滚到上一版本。
- 关键日志携带站点、网关、设备和测点标识。
