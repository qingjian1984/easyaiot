## 1. 责任划分

`iot-device` 保存值班/升级策略、接收人快照、通知意图和升级事实；`iot-message` 保存渠道适配配置、每次发送尝试与渠道回执。渠道结果不能修改告警主状态，用户点击通知也不能自动替代告警确认 API。

## 2. 数据模型

告警域：`duty_roster`、`duty_shift`、`duty_substitution`、`alarm_escalation_policy`、`alarm_notification_request`、`alarm_notification_outbox`。消息域：`alarm_notification_inbox`、`alarm_delivery_attempt`、`alarm_delivery_callback_inbox`。

关键约束：

- 值班/策略发布版本不可覆盖，时间统一存 UTC 并保留 IANA 时区。
- 通知幂等键为 `alarmId+policyVersion+level+recipientId+channel+purpose`。
- `alarm_notification_request` 将 `submit_status` 与 `delivery_status` 分列保存：前者为 `PENDING/SUBMITTING/SUBMITTED/RETRY_WAIT/FAILED_FINAL/EXPIRED/CANCELLED/NO_RECIPIENT/SUPPRESSED`，后者为 `NOT_APPLICABLE/UNKNOWN/DELIVERED/UNDELIVERED`；无可信回执保持 `SUBMITTED + UNKNOWN`，不得合并为复合状态。
- 回调 Inbox 以供应商事件 ID + 租户/渠道唯一，并保存验签结果与 hash。
- 联系方式只保存受控引用或加密值；Outbox 与日志不携带渠道密钥。

## 3. 端到端流程

1. TD-006 在告警事务 Outbox 发布 `device.alarm.created.v1`、`device.alarm.occurrence-recorded.v1`、`device.alarm.recovered.v1`、`device.alarm.status-changed.v1`、`device.alarm.escalated.v1` 和 `device.alarm.suppression-decided.v1`；通知域只执行最后一个事件携带的抑制决策。
2. `iot-device` 解析已发布策略和值班快照，原子创建通知请求与通知 Outbox。
3. `iot-message` Inbox 幂等消费，按 channel adapter 创建一次 attempt。
4. adapter 在超时边界内提交供应商；`submitStatus=SUBMITTED` 与 `deliveryStatus=DELIVERED/UNDELIVERED/UNKNOWN` 分开上报。
5. 渠道结果事件回到 `iot-device`，只更新通知投影与升级调度，不直接改变告警状态。

## 4. 调度与状态

- 重试任务只领取 `RETRY_WAIT` 且 `nextAttemptAt<=now<validUntil` 的记录，使用带租约的 CAS。
- 默认退避 `5s/30s/2m/5m`，最大 8 次；认证/模板/权限等最终错误不重试。
- 升级任务以 `alarmId+policyVersion+targetLevel` CAS；重复扫描只产生一个升级事件。
- 告警关闭、误报或策略停止时，只取消未提交请求；已提交仅记 `cancelRequested`。
- 维护结束重评估不得复活 EXPIRED/SUPPRESSED 请求，只能按当前窗口创建新的幂等意图。

## 5. 渠道适配 SPI

```text
NotificationChannelAdapter
├─ validateConfiguration()
├─ submit(request, timeout)
├─ parseAndVerifyCallback(headers, body)
└─ queryDelivery(externalId) [optional]
```

首期可实现站内信/APP 的真实适配；短信、电话、企业微信在供应商、凭据、回调验签和回执语义确认前只保留禁用适配器，不返回伪成功。

## 6. 安全与权限

- 值班表、替班、策略发布和跨站模板分别授权；替班发起/批准留痕。
- 回调端点必须限定渠道、验签、防重放、请求大小和时间偏差；失败进入安全指标，不回显解析详情。
- 手机号、邮箱、用户 OpenID、模板变量按字段脱敏；密钥由环境/Secret 管理，不入数据库明文。
- 租户与站点从告警事实和策略版本解析，禁止信任外部回调传入的租户。

## 7. 现有链迁移

告警域和消息域的 Inbox、表、序列、迁移资产与 runner 完全分离：`iot-device` 的 `alarm_source_inbox` 只接收告警来源事件，由告警域迁移脚本和 runner 管理；`iot-message` 的 `alarm_notification_inbox` 与 `alarm_delivery_callback_inbox` 只接收通知请求/渠道回调，由消息域独立迁移脚本和 runner 管理。两域不得共用表、序列或迁移执行清单，跨域只经版本化事件协作。

对 `iot-sink`/`iot-message` 的 `AlertNotificationConsumer`、`SnapshotAlertNotificationConsumer` 和现有 `AlertDO` 做调用/Topic/幂等画像。迁移期旧消费者只接收旧 Topic，新通知只接收版本化 Topic；禁止同一事件同时被两套消费者发送。完成按告警、接收人、渠道、模板和时间窗口的双发对账后停旧链。

## 8. 监控与容量

指标分三层：意图创建、平台提交、渠道送达。SLO 的“平台提交成功率”分母排除无接收人、被抑制和过期请求；渠道送达率独立展示，不混为平台成功率。

队列深度、最老年龄、每渠道限流、重试量、最终失败、回调验签失败、无接收人和升级延迟必须可观测。过载时优先紧急级别，但不得饿死普通告警或无界堆积。

## 9. 验证矩阵

- 班次：重叠、空档、替班、离职、时区和 DST。
- 幂等：Outbox 重投、Inbox 重复/冲突、回调重放、调度并发。
- 状态：`submitStatus` 与 `deliveryStatus` 分离；无可信回执保持 `SUBMITTED + UNKNOWN`，过期不补发，确认/关闭取消边界明确。
- 渠道：超时、429、认证失败、非法模板、签名错误和未知回执。
- 安全：跨租户、联系方式脱敏、密钥扫描、回调大小/重放。
- 档位：mini 无消费者；standard 禁止跨站；full 依赖不足关闭。
- 迁移：旧链双发为零、回滚不丢新通知历史。
