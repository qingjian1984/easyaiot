## 3. 逐项签署

### 3.1 severityMapping（按推荐，无修改）

| legacy 值 | 批准的统一 severity | 理由（引用推荐） |
|---|---|---|
| `INFO` | `INFO` | 信息提示语义保持不变 |
| `WARNING` | `NORMAL` | 对应一般告警，避免无依据提升处置强度 |
| `CRITICAL` | `IMPORTANT` | 对应重要告警；legacy 严重不自动获得"永不可忽略"的紧急安全语义 |

**特别批准项**：legacy 没有任何值自动映射 `EMERGENCY`。紧急等级必须由产品对具体规则单独批准，并具备不可忽略、升级和值班处置能力；不得通过批量迁移隐式获得。

### 3.2 retainedScope（按推荐）

全部有效 `enabled=1` 且通过预览校验（tenant、site、条件与 severity 均合法）的规则进入 `READY_NEW_REVISION`。无产品/设备/规则排除项。

### 3.3 disabledPolicy（按推荐，`DRAFT_ONLY`）

`enabled=0` 的规则保留为 legacy 只读证据，可生成统一 DRAFT，但不发布、不激活。

### 3.4 隔离条款（按推荐）

tenant/site 冲突、非法 JSON、min/max 与 rules 语义冲突的条目隔离，不静默修复。

### 3.5 activationAt（时序受控，本签署不含）

按 G2 输入单 §3.2 约束：`activationAt` 只能在**迁移预览清单冻结后**由发布清单签署时填写（RFC 3339 + 显式 offset）。本签署时预览清单尚未冻结，故该字段为空并保持 `PENDING-PREVIEW` 状态。

activationAt 前的遥测和 legacy OPEN/CLEARED 不 backfill；新 revision 从 activationAt 后第一条有序 GOOD 遥测起算——此语义随本签署一并批准。

## 4. 生效与限制

1. 本签署关闭 G2-01 门禁中除 `activationAt` 外的全部 owner 输入；门禁状态转 `SIGNED-PENDING-ACTIVATION`。
2. `activationAt` 补填后 G2-01 才完全关闭（`CLOSED-OWNER`）。
3. 本签署不解锁 C1A/C1-C4、不批准任何 adapter/DDL/transport 实现、不改变 ADR-019 `Proposed` 状态。
4. severity 映射进入迁移实现后不得静默调整；如需调整须新版本签署记录并更新 decisionRef。
