## 1. 核对结论

本轮关闭了 C1 的“仓库事实不明”问题，并修正 C0 验收记录中的一项过时判断：M1 canonical telemetry 的 identity/route 已存在已提交且已冻结的合同基础，不应继续表述为“没有最终冻结且已提交证据”。

但是该合同尚未完整进入旧 `THRESHOLD` 和 `DEVICE_EVENT` 链：现有 M1 权威接口只解析 `productIdentification + deviceIdentification → tenantId`，不返回 `siteId`；旧阈值请求没有 message/tenant/site/time/quality/rule version；旧设备事件也没有站点、周期和告警映射。因此 C1 仍为 `CLOSED`，不得实现 adapter、生产 Bean、双写或 transport。

本轮唯一批准的下一步是按后继任务单形成来源身份、周期、映射和事务补偿的架构决策。该任务完成前不得把 M1 的局部合同关闭误解为 C1 已解锁。

## 4. M1 可复用与不可复用边界

### 4.1 可以复用

1. `TelemetryEnvelope.messageId` 是遥测幂等身份，`tenantId/siteCode/deviceIdentification/collectedAt/quality/configVersion` 是 canonical telemetry 已冻结事实；
2. `CollectorConfigSnapshot 1.1` 是 collector 侧 `productIdentification/tenantId/siteId/siteCode/configVersion` 的已应用配置事实；
3. canonical Topic 固定 `/iot/{product}/{device}/property/upstream/report`；不得继续从 `siteCode/propertyCode` 构造路由；
4. `TelemetryDeviceAuthorityService` 对产品+设备执行全租户、精确、最多两行的唯一性判定，`NOT_FOUND/AMBIGUOUS` 必须 fail-closed。

### 4.2 不可以直接复用或推断

1. `IotDeviceMessage.id` 注释明确为后端生成，不等同于跨设备/collector 重试稳定的来源身份；在证明其与 M1 canonical messageId 同源前不得作为告警 eventId；
2. 一个遥测 message 可能同时命中多条阈值规则，不能直接把单一 telemetry messageId 当作多条告警来源事件的唯一 eventId；
3. M1 Envelope 只有 `siteCode`，告警命令要求正 `siteId`；不得查询当前设备站点后回填历史事件，也不得把 siteCode 强转为 siteId；
4. `TelemetryDeviceAuthorityService` 只返回 tenant，不证明站点归属，也不提供阈值 rule/version；
5. `AlarmSourceTransactionService.process()` 使用 `REQUIRES_NEW`。未经新决策不得把它嵌入旧写方法并声称与旧事实同一事务。

## 5. 两类来源的阻断事实

### 5.1 THRESHOLD

- `PropertyThresholdEvaluateParam` 只有设备、设备名和 properties；缺 messageId、product、tenant、site、configVersion、event time、quality。
- `evaluateAndAlarm` 未声明事务；`alarmMapper.insert` 后直接 `kafkaTemplate.send`，Kafka 成功再更新 `kafka_sent`，不存在数据库提交与 broker 确认的原子保证。
- 新告警使用 `tenantId=0`、`LocalDateTime.now()`；恢复按 `selectLatestOpen(device, property)` 选择旧行。
- 现有阈值记录能提供规则主键候选，但缺不可变规则版本和显式周期状态。静默用当前阈值内容处理重放会改写历史语义。

### 5.2 DEVICE_EVENT

- `DeviceEventHandler` 从 Topic 解析 product/device，但落库只保存 device/event code/type/message/status/tenant/time，没有 site、来源 messageId、映射版本或 cycle。
- tenant/time 缺失时仍回退 `0/now`；自由 `eventType` 只做字符串归一，不能直接映射统一等级。
- handler 虽处于事务中并会重新抛异常，但 `DeviceEventSubscriber` 捕获后只记录日志，transport 无法据此执行重试或终态隔离。
- 事件模型未区分告警触发、恢复、普通业务事件和一次性事件；在映射表冻结前禁止全量生成统一告警。

## 6. 后继任务边界

后继 C1P 只允许输出架构决策、字段来源矩阵、确定性 identity 算法、阈值周期状态机、设备事件映射合同、旧写/新入口事务或补偿决策以及纯合同验收矩阵。明确禁止：

- 修改 `PropertyUpstreamReportListener`、`SubPropertyUpstreamReportListener`、`DeviceThresholdAlarmServiceImpl`、`DeviceEventSubscriber` 或 `DeviceEventHandler`；
- 修改生产 Spring 装配、Feign、Kafka/MQTT、数据库 Schema/runner、capability、WEB/APP；
- 创建 adapter、listener、producer、relay、scheduler、Controller 或执行 SQL；
- 以当前工作区未提交 M1 文档、当前站点查询、`tenant=0`、`now`、随机 UUID 或“最新 OPEN”补齐身份。

## 7. 解锁判据

C1 只有在下列全部成立并由 Sol 再次复审后，才可拆分本地 adapter/fake 实现：

1. M1→告警的 message/product/tenant/site/device/time/quality 字段来源和冲突优先级冻结；
2. 多规则命中时确定性 eventId/sourceId 规则冻结，重放字节一致且无随机数/当前时间；
3. THRESHOLD 的 rule version、RAISED/RECOVERED、cycleKey 生命周期和并发语义冻结；
4. DEVICE_EVENT allowlist、映射版本、等级、恢复/一次性语义和 cycle 相关字段冻结；
5. 明确旧写与统一写是同一事务、来源 Outbox 补偿还是观察期只读投影，并给出失败/重放/对账/通知单 owner 矩阵；
6. C0 guard 保持通过，且后续实现拥有独立白名单和验收授权。
