# TD-005 standard 最低规格压测方案（迁移执行器专项）

> 版本：0.1.0（候选，待 DBA/owner 复核）　日期：2026-08-07　关联：ADR-013 1.4.2、TD-005 migration 0.2.0
>
> 门禁关系：ADR-013 §资源影响评估与预算明确"以上均为候选预算，只有附带标准最低规格原始压测证据后才能冻结"，
> 本方案是该证据的生产规程。压测通过前，所有阈值/预算值一律保持**候选**标记（宪法 §15：未实测不冻结）。
>
> 安全约束：压测在**专用 standard 最低规格环境**执行，禁止在任何共享/生产库执行；
> 压测库由种子脚本造数，压测后销毁。

---

## 1. 压测对象与目标

| # | 对象 | 目标问题 |
|---|---|---|
| P-1 | runner 五步骤全链（M05→M15→M16→V001→V002） | 代表性数据量下全链耗时与资源曲线 |
| P-2 | M15 `CREATE UNIQUE INDEX CONCURRENTLY` | 大表 `product` 上并发建索引的时长、CPU/IO/WAL/磁盘增量、`pg_stat_progress_create_index` 可观测性 |
| P-3 | 强制备份（pg_dump） | 备份时长与磁盘占用 ≈ 库体积的假设验证 |
| P-4 | schema-sync 漂移核对 | 临时参考库的磁盘与耗时预算验证 |
| P-5 | 有界重试与锁等待 | 并发会话持锁时 `lock-wait`/`retry`（3/1s/4s）行为与有界失败 |
| P-6 | 失败恢复 | 非事务步骤失败后 INVALID index 检测/清理/重跑的在负载下的正确性 |

## 2. 环境规格（候选，执行前须运维确认）

> 现状：仓库文档未定义 "standard 最低规格" 的硬件基线，本方案给出候选值，**执行前必须由运维/DBA 书面确认或修正**。

| 项 | 候选值 | 说明 |
|---|---|---|
| CPU | 4 vCPU | standard 单站点/园区档最低假设 |
| 内存 | 8 GiB | 含 PostgreSQL `shared_buffers=2GiB` 候选 |
| 磁盘 | SSD ≥ 100 GiB 可用 | 须容纳 库体积×3（数据+备份+参考库） |
| PostgreSQL | 18.4（与目标平台一致） | 容器或裸装均可，记录确切小版本 |
| 部署档位 | standard manifest（含 `iot-device`） | mini fail-closed 不在本压测范围 |
| 并发背景负载 | 候选：50 连接 OLTP 背景流量 | 模拟迁移窗口内业务低峰 |

## 3. 数据规模模型（候选）

以 12 表画像的冻结基线为形状，按规模因子造数：

| 表 | 基线（iot-device20 画像） | 压测规模因子（候选） | 压测行数（候选） |
|---|---:|---:|---:|
| product | 4 | ×2500 | 10,000 |
| product_properties | 17 | ×2500 | 42,500 |
| device | 3 | ×10000 | 30,000 |
| 其余九表 | 0～少量 | 按 product 1:5 派生 | 见造数脚本 |

- 造数脚本须保持画像列签名不变（仅增行，不改结构），并包含**边缘形状**：长 `product_identification`、多租户分布（≥3 tenant）、1% 近重复（不违反唯一）。
- 规模因子为候选值；若运维提供生产估算（站点数×设备数），以生产估算替换并重记本节。

## 4. 测量项与通过阈值（全部候选，实测后回填冻结）

| 指标 | 采集方式 | 候选阈值 |
|---|---|---|
| 五步骤全链 wall time | runner 结构化日志 `duration_ms` 之和 | ≤ 30 min |
| M15 单独耗时 | history `duration_ms` + `pg_stat_progress_create_index` 采样（5s 间隔） | ≤ 20 min |
| M15 期间磁盘增量 | 执行前后 `pg_database_size` + 文件系统余量 | ≤ 表体积 1.5× |
| M15 期间 WAL 增量 | `pg_stat_wal` / LSN 差值 | 记录实测值（不设阈） |
| 备份耗时/体积 | runner 备份步骤日志 + 文件大小 | 体积 ≤ 库体积 1.2× |
| 漂移核对耗时/临时库体积 | schema-sync 日志 | 体积 ≤ 基线体积 1.2× |
| 锁等待有界失败 | 持锁会话 + 并发 apply | 在 lock-wait+retry 窗口内（≤ 15s+3 重试）以明确错误码退出 |
| 背景负载影响 | 迁移期间 OLTP p95 延迟对比基线 | 劣化 ≤ 20%（CONCURRENTLY 不锁写） |

> 任何一项超阈：不判失败下线，而是回填实测值并触发预算复审（DBA + 架构），决定调阈值或改设计。

## 5. 执行步骤

1. **环境确认**：运维签字确认 §2 规格；记录主机/容器指纹（CPU/内存/磁盘/PG 版本）。
2. **造数**：运行造数脚本（待编写，见 §7 OPEN），校验 12 表列签名与画像基线一致。
3. **基线测量**：空载 OLTP p95、`pg_database_size`、磁盘余量。
4. **背景负载启动** → **dry-run**（核对 manifest 哈希与签字包 §1.2 一致）→ **apply 全链**，全程采样 `pg_stat_progress_create_index` / `pg_stat_wal` / 磁盘。
5. **备份与漂移核对**：按 runner 流程执行，记录 §4 对应指标。
6. **故障注入**：P-5 锁竞争、P-6 中断 M15（kill 会话）→ INVALID index 清理 → 重跑恢复。
7. **复跑幂等**：全链二次 apply，预期五步全 STEP_SKIPPED。
8. **销毁环境**，归档证据包（§6）。

## 6. 证据包格式

```
perf-evidence-YYYYMMDD/
├── env-fingerprint.txt        # 环境指纹 + 运维确认记录
├── seed-report.txt            # 造数行数与列签名校验
├── runner-logs/               # 结构化日志（含 duration_ms / error_code）
├── samples/                   # pg_stat_progress / pg_stat_wal / 磁盘采样
├── baseline-vs-load.txt       # 背景负载 p95 对比
├── fault-injection.md         # P-5/P-6 过程与恢复记录
└── verdict.md                 # 逐项阈值判定 + 超阈值项的处置建议
```

证据包回填 ADR-013 证据表与评审报告 §8 新小节，候选预算按实测值修订后申请冻结。
