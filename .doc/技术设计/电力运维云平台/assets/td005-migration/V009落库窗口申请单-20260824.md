# V009 落库窗口申请单（LC02-07 产品路由身份补列）

> 申请日期：2026-08-24
> 依据：ADR-013 1.5.7（Accepted）/ LC02-07 §20 / 宪法 1.6.0 §6.2
> 目标：待另行指定的 PostgreSQL 目标实例
> 当前状态：**OPEN / NOT APPROVED**

## 1. 申请范围

本单只申请未来在独立批准窗口通过 TD-005 runner 执行 `V009`。本次 LC02-07 实现授权不包含本窗口批准，也不包含 `iot-device20`、共享库或生产库写入。

| 步骤 | 内容 | 类型 | SHA-256 |
|---|---|---|---|
| V009 | `iot_sink.telemetry_inbox.product_identification VARCHAR(128)` nullable 扩展及中文 COMMENT | 单事务 additive | `48416787b7fc886cc3274be53f3a38c60f9a9dd93ca205e3f0311d54a8eafbde` |

V009 不包含默认值、非空约束、索引、CHECK/FK、trigger、数据回填或业务 DML。执行前必须由 runner 精确验证 `V008`、`V010` 已以当前 hash 成功完成。

## 2. 执行前置

1. 决策所有者和 DBA 另行填写正式审批单号、执行人、目标实例和维护窗口。
2. 目标实例完成 ADR-013 precheck，确认 `V008`/`V010` history 为 `SUCCEEDED` 且 hash 与 runner 当前资产一致。
3. 选择仓库外备份目录；runner apply 必须先成功生成 `pg_dump` 备份。
4. 完成变更通知、连接/锁/语句超时确认和执行后只读对账准备。

## 3. 执行命令（批准后由授权执行人填写目标参数）

```bash
BACKUP_DIR=<repository-external-backup-dir> \
PG_PASSWORD="$PG_PASSWORD" \
.scripts/postgresql/td005-migration/td005_migration.sh apply \
  --db <approved-target-db> \
  --step V009 \
  --approval <approved-window-id> \
  --yes
```

执行输出必须包含 `STEP_DONE V009`、实际 hash 和备份路径；任何 `DEPENDENCY_NOT_SATISFIED V009`、`HASH_MISMATCH V009` 或锁/超时错误均停止并保留原结构。

## 4. 执行后验收

- `schema_migration_history` 中 V009 为 `SUCCEEDED`，hash 精确匹配本单；evidence 含审批单、目标库和备份摘要。
- `iot_sink.telemetry_inbox.product_identification` 为可空 `VARCHAR(128)`，无默认值，中文 COMMENT 精确存在。
- 既有 Inbox 行的旧列、行数、约束和索引不变，新列值为 `NULL`。
- V008/V010 history、hash 和既有表结构不变。
- 运行 `check-comments` 返回零行；归档 runner 输出、备份路径和只读验证结果。

## 5. 回滚边界

正常应用回滚是关闭 LC02-08 新写链并保留 nullable 列，不执行 U009。只有未来另行批准、确认列全 NULL、无依赖且备份有效时，才可在隔离窗口演练 U009；生产/共享环境不得由本单直接执行 U009。
