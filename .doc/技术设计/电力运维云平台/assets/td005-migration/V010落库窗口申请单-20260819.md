# V010 落库窗口申请单（TD-003 §14 telemetry_sample 质量码/接收时间补列）

> 申请日期：2026-08-19
> 依据：ADR-013 1.5.4（Accepted）/ TD-003 1.0.1 §14 / PRD-01 §4.4 / 宪法 1.6.0 §6.2（中文注释 MUST）
> 目标：`postgres-server / iot-device20` 本地目标集成实例
> 当前状态：**待批准**（未批准前仅在临时库验证；生产/共享库需独立审批）

## 1. 申请范围

通过 ADR-013 runner 执行 `--step V010`，为 `iot_sink.telemetry_sample`（V008 建表）additive 补两列 + 1 个防御 CHECK：

| 步骤 | 内容 | 类型 |
|---|---|---|
| V010 | `quality VARCHAR(32) NOT NULL DEFAULT 'GOOD'` + `received_at_ms BIGINT NOT NULL`（旧行以迁移时刻回填）+ `ck_sample_quality` CHECK + 中文 COMMENT | 单事务 additive（含 UPDATE 回填） |
| U006（配套回滚候选） | DROP 两列 + CHECK | 评审附件，随 V010 一并冻结 |

**注意**：V010 含一条 UPDATE 回填（`WHERE received_at_ms = 0 OR received_at_ms < collected_at_ms`）。本地 `iot-device20` 该表现有 0 行（合同测试事务回滚），UPDATE 实际空扫；生产库若已有存量行，回填行数须在窗口申请时评估并纳入备份核对。

## 2. 风险与锁影响

- `ALTER TABLE ADD COLUMN ... DEFAULT`：PG 11+ 为元数据级，不重写表，锁 `AccessExclusive` 瞬时完成。
- UPDATE 回填走 `collected_at_ms` 相关索引；存量行多时窗口应评估时长。
- 窗口 `lock_timeout=15s / statement_timeout=60s`（回填预留），锁忙即失败关闭。
- 单事务执行（BEGIN → DDL/COMMENT/UPDATE → COMMIT），任一失败全部回滚。

## 3. 前置证据

1. V010 SQL 含中文 `COMMENT ON COLUMN`（宪法 §6.2 MUST）。
2. 预检 SQL：两列在目标库不存在（`information_schema.columns` 期望 0 行）。
3. 写入侧代码（`JdbcTelemetryStore`/`TDengineTelemetryStore`）在 V010 落库前以列探测降级运行（quality 兜底 GOOD），落库后自动切换——迁移与部署无先后硬依赖。
4. 批准后执行前必须再次核对最终 hash。

## 4. 执行步骤

1. 记录批准单号，选择仓库外备份目录；
2. 只读 precheck：目标库名、V001～V008 history/hash、两列不存在、表行数（评估回填量）；
3. runner 自动 `pg_dump`，备份失败即停止；
4. 执行 `td005_migration.sh apply --step V010 --approval <批准单号> --yes`；
5. 执行后只读验证：两列存在、旧行 `received_at_ms >= collected_at_ms`、`quality='GOOD'`；
6. 归档 runner 输出、备份路径、history 与计数证据。

## 5. 执行后验收

- V010 history SUCCEEDED 且 hash 匹配；
- `quality` / `received_at_ms` 两列存在，COMMENT 齐全；
- 存量行全部 `quality='GOOD'` 且 `received_at_ms >= collected_at_ms`；
- V001～V008 history/hash 不变；
- 查询适配器（`JdbcTelemetryQueryAdapter`）探测列后返回真实 quality（合同测试 `qualityColumnsPresent` 路径）。

## 6. 回滚

U006（`U006__telemetry_quality.sql`）DROP 两列 + CHECK；执行前置：查询链路已切回兜底、无视图/索引依赖、接受历史质量信息丢失。备份恢复路径见 ADR-013 §回滚演练记录。

## 7. TDengine full 档说明

full 档 `telemetry_sample` 超级表补列走 TDengine `ALTER STABLE ... ADD COLUMN`（3.x 支持），SQL 与执行方式随 full 档部署评审另行冻结（TD-003 §14 已要求 Spike 证据，见 TQ-03 风险项）；本申请单仅覆盖 PG standard 档。
