# TD-006 附件：现有告警实现画像

> 版本：0.1.0  
> 日期：2026-08-24  
> 状态：Verified from Repository / Production Profile OPEN  
> 范围：`DEVICE/iot-device` 阈值告警及其 `iot-sink` 调用入口  
> 双基线：平台功能计划 1.5.0、EasyAIoT 项目开发宪法 1.6.0

## 1. 结论

现有实现可作为阈值配置、旧 API 和来源事件的迁移输入，但不能原地扩展为统一告警主记录。主要原因是：活动周期不唯一、租户边界不完整、时间/质量事实缺失、告警与 Kafka 发送不原子、公共 VO 与数据库实体混用。

本画像只证明仓库静态事实，不代表生产数据库数量、Topic 积压或调用量；生产画像仍为 OPEN。

## 3. 已核实的数据与并发问题

### 3.1 活动周期会分裂

`evaluateAndAlarm` 使用 `countOpenSince(device, property, since)` 做静默。该查询不限制 `alarm_status`：

- 静默窗口内即使旧记录已经 `CLEARED`，新的真实故障也会被抑制；
- 静默窗口结束后，即使旧故障仍为 `OPEN`，也会插入另一条 `OPEN`；
- 恢复逻辑只选择最新 `OPEN` 并清理一条，较早的重复 `OPEN` 可能永久残留。

因此旧行不能直接等价为“一个故障周期”；迁移必须先统计同租户/设备/属性的并行 OPEN 和时间重叠。

### 3.2 租户边界不完整

- 新阈值告警显式写 `tenantId(0L)`，没有从设备权威事实或 TenantContext 解析。
- 阈值/策略唯一约束只包含设备标识或设备+属性，不含 `tenant_id`。
- Mapper 查询未显式包含 tenant 条件。
- 阈值评估请求只有设备标识、名称和属性 Map，没有 tenant/site/product/messageId。

迁移时 tenant=0 不能静默当成系统租户；必须通过设备权威表解析，无法唯一解析的行进入隔离清单。

### 3.3 消息一致性和幂等不足

- 告警插入与 Kafka send 不在本地事务 + Outbox 中。
- `KafkaTemplate.send()` 返回后未等待 broker 确认即把 `kafka_sent` 更新为 1。
- `alertId` 被转为 `int` 写入 JSON，BIGINT ID 存在截断风险。
- 来源 messageId 未进入阈值评估，重复上报无法按消息幂等。
- Feign 调用失败只记录 warn；没有 Inbox、重放和死信恢复。
- 配置中的 `device.alarm=true` 在 `iot-device` 未发现代码读取点，不能作为 capability 或可靠启用事实。

### 3.4 时间与质量事实不足

- 请求不包含事件时间、接收时间、时区、offset、水位或质量码。
- 使用服务器 `LocalDateTime.now()` 判断静默、创建和恢复。
- 任意可解析数值都进入规则评估，无法区分 GOOD/BACKFILLED/TIMEOUT/COMM_ERROR。

旧数据只能保留原始发生/清理时间作为来源证据，不能推导未记录的事件时间、质量或站点时区。

## 4. 可复用与禁止复用

### 4.1 可复用

- 阈值/策略旧 API 可在兼容期转调或只读展示。
- `DevicePropertyThreshold` 的设备/属性、上下限、等级可作为规则草稿导入来源。
- `PropertyUpstreamReportListener` 和子设备 Listener 是来源接入点，但必须改为传递完整版本化 envelope。
- `PowerModelOutboxRepository/Relay` 的端口、租约、有限重试和测试方法可以复用模式，不复用表和幂等域。
- 共享 `CapabilityService` 和两档 manifest 是唯一 capability 事实源。

### 4.2 禁止复用为新事实

- 不把 `device_threshold_alarm` 改名或扩列后直接宣称统一模型完成。
- 不把 `kafka_sent` 作为可靠发送事实。
- 不用静默秒数代替活动周期唯一约束、迟滞或持续时间。
- 不把 tenant=0 当作有效归属兜底。
- 不从相近时间或相同属性猜测合并 VIDEO/AI/阈值告警。
- 不将 power-model Inbox 表直接作为告警 Inbox。
- 不保留 `/device/alarm` 的“只打印并成功”语义；兼容期必须转为版本化来源事件或稳定拒绝。

## 5. 迁移画像查询清单

生产/共享库窗口批准后，画像至少统计：

1. 总行数、tenant=0/NULL、设备不存在或多租户冲突数量。
2. 按设备/属性的 OPEN 数量，尤其 `OPEN > 1` 和时间重叠。
3. `kafka_sent=0/1` 与消息中心是否存在对应记录的差异。
4. alarm level 枚举、非法状态、时间倒置、空 device/property。
5. 阈值/策略唯一键与设备租户的一致性。
6. WEB/APP/内部 Feign 对旧告警 API 的调用方和版本。

画像脚本必须先以只读、带 `statement_timeout` 的方式评审；未经窗口授权不得连接生产库。

## 6. 迁移映射候选

| 旧事实 | 新事实 | 规则 |
|---|---|---|
| `OPEN` | `ACTIVE` | 仅在 tenant/device 唯一解析且无并行活动歧义时自动映射 |
| `CLEARED` | `RECOVERED` | 不自动 CLOSED；保留 clear_time |
| `INFO` | `INFO` | 直接映射 |
| `WARNING` | `NORMAL` | 兼容映射并记录来源枚举 |
| `CRITICAL` | `IMPORTANT` | 不猜测为 EMERGENCY |
| tenant=0 | 权威设备 tenant | 只能由设备事实唯一解析；否则隔离 |
| 多条并行 OPEN | 人工/规则化清单 | 不自动合并或删除，切读前必须归零/批准差异 |
| `kafka_sent` | 来源参考 | 不迁入新 Outbox 发送状态 |
