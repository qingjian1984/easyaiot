P02-M2-02B 已完成本地无 transport 实现和静态/单元验收：7 份正式 Schema、严格 codec/validator、规范消息摘要、Inbox 仲裁、V011-only JDBC 持久化端口、独立 Spring 事务代理用例、告警 Outbox JDBC claim/lease 与 Relay fake 已落地。

本记录不代表生产可用或数据库集成通过。未连接 PostgreSQL，未执行 V011/U011，未读取 `.env`，未调用 Docker，未创建物理 Topic、consumer、producer、listener、scheduler、Controller 或 capability Bean。

## 2. 已验收事实

- 生产 classpath 只包含来源 1 个、领域 6 个独立 Schema；未复制评审 union Schema。
- 当前主版本严格校验；未知可选字段允许；未知主版本稳定拒绝。
- `envelopeHash` 对排序后的完整 Envelope 规范 UTF-8 字节本地计算，格式为 `sha256:<64 lowercase hex>`；不信任 `payload.payloadHash` 代替。
- Inbox 同 hash 的 `RECEIVED` 可恢复处理、`PROCESSED` 判重复、`QUARANTINED` 维持最终拒绝；异 hash 隔离并保留首个 hash。
- 来源处理入口使用独立 `REQUIRES_NEW` Spring 事务方法并在无活动事务时 fail-closed；未声明 stereotype，当前不会自动启用。
- Inbox、source mapping、alarm record expectedVersion CAS、action log、Outbox 和 Inbox PROCESSED 在同一事务端口内完成；fake 注入任一步失败时全部回滚。
- 主记录更新 SQL 同时带 `tenant_id + site_id + id + row_version`；周期唯一争抢使用 `ON CONFLICT DO NOTHING` 后重读完整 `cycle_identity`，hash 碰撞隔离。
- Relay claim 使用 `FOR UPDATE SKIP LOCKED`、租约 owner 和过期恢复；只有明确 broker ACK 才标记 PUBLISHED；retryable 使用注入时间/抖动的有界退避，final/超限进入 DEAD_LETTER。
- 错误持久化仅保存稳定码和脱敏摘要；测试覆盖 payload、凭据、手机号和 URL 不泄漏。
