## 1. 任务目标

本任务关闭 C1 剩余四项设计门禁：tenant/site/device 权威、THRESHOLD 周期、DEVICE_EVENT 告警映射、旧写与统一入口的原子/补偿方案。交付物是可评审、可测试、不可歧义的架构合同，不是 adapter 实现。

优先形成独立 ADR 候选 `ADR-019-告警来源身份周期与补偿接入.md`，状态先为 `Proposed`。只有完成本任务验收并经决策所有者接受后，才能更新 ADR 索引和把 ADR 转为 `Accepted`；编号冲突时立即停止，不得自行改号或覆盖其他 ADR。

## 2. 冻结范围

### C1P-01：M1→告警身份桥

必须形成逐字段权威矩阵，至少覆盖：

| 告警字段 | THRESHOLD 候选事实 | DEVICE_EVENT 候选事实 | 必须裁决的问题 |
|---|---|---|---|
| event/message identity | M1 telemetry messageId + rule instance/action 的确定性派生 | 设备原始 request/message identity + event identifier/action 的确定性派生 | 32/36 位兼容、UUID 规范、同消息多事件、碰撞与重放 |
| tenant | canonical Envelope + 产品/设备权威核验 | Topic 产品/设备权威核验；不得信任 0 | Envelope 与权威库冲突时 fail-closed 规则 |
| siteId/siteCode | ConfigSnapshot/历史 route 事实 | 事件发生时的版本化 route 事实 | M1 Envelope 缺 siteId 时扩合同还是查历史 route；禁止查询当前站点猜历史 |
| device/product | canonical Topic + Envelope | canonical event Topic + 权威设备事实 | 子设备 Topic、歧义与缺失分类 |
| occurredAt/quality | collectedAt + quality | 设备时间及可信度策略 | 缺失/未来/过旧/时区异常的隔离规则 |

确定性 eventId 必须满足：同一来源事实、同一映射版本、同一 action 重放得到同一小写 canonical UUID；不同规则、不同事件或不同 action 不碰撞。不得使用随机 UUID、数据库序列、接收时间或当前时间。若采用 UUIDv5，必须冻结 namespace、UTF-8 canonical name 各字段顺序/分隔/空值编码和 golden fixture。

### C1P-02：THRESHOLD 周期

必须冻结：

1. `sourceId` 是 tenant/site/device/property/rule/rule-version 的稳定规则实例身份；展示名、阈值文本和当前值不得进入稳定身份；
2. rule version 必须不可变并可回溯。现有可变阈值行若没有版本事实，先形成版本化规则迁移设计，禁止读取“当前规则”解释历史重放；
3. `cycleKey` 在规则状态从未触发/已恢复转为 breached 时创建，并由后续重复发生和恢复复用；恢复完成后再次 breached 创建新周期；
4. 同一 rule instance 的并发 RAISED 只能赢得一个活动周期；RECOVERED 必须按显式 cycleKey 定位，禁止 `selectLatestOpen`；
5. silence/reopen 只影响通知或版本化重开策略，不得用 silence 窗口代替周期身份；
6. quality 非 GOOD 时是继续评估、形成 UNKNOWN/降级、还是隔离，必须按规则版本冻结，不能静默当正常值。

### C1P-03：DEVICE_EVENT 映射

必须形成版本化 allowlist，而不是把所有 `thing.event.post` 转成告警。每项至少包含：product/model scope、eventIdentifier、mappingVersion、sourceAction、severity、sourceId 模板、cycleKey 字段/相关键、可否恢复、一次性事件策略和非法输入处置。

映射裁决必须满足：

- 自由 `eventType/level/severity` 不能直接成为统一等级；只接受映射表固定值；
- RAISED/RECOVERED 必须是不同 event identifier 或载荷字段的显式合同；无法关联恢复周期的事件不得伪造 RECOVERED；
- 一次性事件若批准为告警，必须明确其闭合策略，不能创建永久 ACTIVE 后依靠运维猜测；
- mappingVersion 进入 identity/hash，映射升级不得改变已处理历史事件的含义；
- 未映射、歧义、字段缺失、非法等级和未知主版本必须 fail-closed 并具有稳定错误码。

### C1P-04：旧写、新写与通知补偿

必须在 ADR 中对以下三种方案作明确取舍，禁止混用：

1. **同事务**：旧来源事实和统一告警入口在同一 PostgreSQL 事务提交；需处理当前告警入口 `REQUIRES_NEW` 与调用代理边界，不得只在外层增加 `@Transactional` 后声称原子；
2. **源侧 Outbox**：旧来源事实与稳定 source event/outbox 同事务，relay 重放到统一 Inbox；适用于不能共享事务的边界；
3. **只读投影/对账**：观察期不在旧写路径同步生成统一事实，由可重放扫描器按不可变旧事实投影；只适合身份完整、延迟可接受且有游标/对账的来源。

无论选择哪种方案，都必须冻结失败矩阵：旧写失败、新写失败、提交后崩溃、重复、乱序恢复、hash 冲突、终态隔离、relay 耗尽、对账差异和回滚。通知必须只有一个 owner：观察期可保留旧通知 owner 并关闭新通知 relay，切换后才反转；禁止同周期双发，也禁止用 `kafka_sent` 表示统一 Outbox 状态。

## 5. 停工条件

出现任一情况立即停止并交回 Sol：

- 无法证明 source message identity 在上游重试中稳定；
- siteId 只能通过当前设备状态猜测，缺少事件时 route 事实；
- 现有阈值没有可版本化的 rule identity，且需要先迁移数据模型；
- DEVICE_EVENT 产品负责人尚未提供允许转告警的事件清单；
- 需要改变 `AlarmSourceTransactionService.REQUIRES_NEW` 或 V011 表结构；
- ADR-019 编号已被其他已提交/进行中任务占用；
- 需要读取生产数据、凭据、broker、数据库或执行 Docker/SQL。

停工不等于放宽合同。此时应把缺口保留为 OPEN，并拆出新的前置任务。

## 6. 验收标准

- 双基线版本、ADR-010/014/017 和 P02-M2-02B/R1 边界无冲突；
- 每个必填告警字段都有唯一权威来源、冲突规则和缺失处置；
- eventId/sourceId/cycleKey 对重放确定、对多规则/多事件隔离，并有 golden fixture；
- THRESHOLD 不再依赖 `latest OPEN`，DEVICE_EVENT 不再依赖自由严重度或全量映射；
- 原子/补偿方案只选一个主路径并覆盖失败矩阵；
- 通知 owner 在观察期和切换后各唯一；
- mini 明确无 adapter/consumer/relay/任务/迁移执行路径；
- C0 guard 继续通过，Markdown 链接和 `git diff --check` 通过；
- 结论只能是 `ADR Proposed` 或 `ADR Accepted / C1 Contract Gate Closed`，不得宣称 adapter 已实现、生产可用或迁移完成。
