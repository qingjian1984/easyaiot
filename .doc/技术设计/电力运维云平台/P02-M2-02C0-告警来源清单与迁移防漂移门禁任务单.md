# P02-M2-02C0：告警来源清单与迁移防漂移门禁任务单

> 版本：1.0.2
> 日期：2026-08-25
> 状态：Implemented / Verified-Local / Inventory Guard Only
> 执行模型：GPT-5.6 Luna / max
> 评审模型：GPT-5.6 Sol
> 冻结依据：[P02-M2-02C 来源接入与迁移切换专项冻结评审记录](./P02-M2-02C-来源接入与迁移切换专项冻结评审记录.md)
> 评审处置：采纳新功能方案评审 N-04；N-05 部分采纳，保留 `WEB/scripts/` 位置并补归属说明与双入口验证

## 1. 目标

把 THRESHOLD、DEVICE_EVENT、VIDEO、AI、RUNTIME 的仓库来源、旧写、旧读、通知旁路、身份缺口和阶段门禁固化为机器可读清单，并用无依赖静态校验阻止这些入口在 C1/C2 未批准前静默漂移。

本任务不实现 adapter，不创建 Topic，不接数据库，不改变任何现有运行行为。

## 2. 允许边界

```text
.doc/技术设计/电力运维云平台/assets/td006-migration/alarm-source-inventory.json
WEB/scripts/verify-alarm-source-migration-boundaries.mjs
WEB/package.json
```

不得修改 `pnpm-lock.yaml`，不得增加依赖。除上述三个文件外，业务代码、测试代码、SQL、配置、Compose、capability manifest、WEB/APP 页面和其他文档均不在任务范围。

## 3. 清单合同

清单必须：

1. 固定 `inventoryVersion`、双基线版本、仓库取证日期和 `scope=repository-static`；
2. 来源集合严格等于 `THRESHOLD / DEVICE_EVENT / VIDEO / AI / RUNTIME`；
3. 每类来源记录 producer/consumer/legacy store/legacy read/notification side effect、source owner、adapter owner、message/source/cycle identity、tenant/site/device/time/quality authority、readiness 和 blocker；
4. 对每个代码事实记录仓库相对路径和稳定 anchor，不使用绝对路径或行号作为唯一定位；
5. 对未发现的 AI producer 使用显式 `NOT_FOUND_IN_REPOSITORY`，不得伪造入口；
6. 将 `/device/alarm` 日志成功旁路、VIDEO 旧 Kafka/direct-persist 兼容链和 WEB/APP 旧查询列为独立 legacy entry；
7. 明确所有生产数量、调用量、Topic 运行参数和责任人均为 `OPEN_EXTERNAL`；
8. 不包含凭据、真实生产地址、个人信息、消息 payload 或媒体 URL。

## 4. 静态校验合同

校验脚本必须使用 Node.js 标准库，至少验证：

1. JSON 可解析、版本和枚举合法、五类来源不缺不重；
2. 所有清单路径存在且保持在仓库内，拒绝绝对路径、`..` 穿越和反斜杠；
3. 每个 anchor 在目标文件中存在且唯一或由显式计数约束；
4. THRESHOLD 的 Feign 入口、旧表、`tenantId(0L)`、当前时间、旧查询和直发通知均被覆盖；
5. DEVICE_EVENT 的消息总线入口、tenant/time fallback、旧落库和异常吞没风险均被覆盖；
6. VIDEO/RUNTIME 的两个 MQTT Topic、随机 `msgId`、tenant default、iot-sink 写 VIDEO `alert` 和通知转发均被覆盖；
7. WEB/APP 的 `/video/alert` 读取和 WEB 的阈值旧读均被覆盖；
8. `/device/alarm` 日志成功旁路被覆盖；
9. `AI/` 出现新的直接告警 publisher 特征时 fail-closed，要求先更新 02C 评审；
10. 清单中任何 `READY/APPROVED` 来源、production 数量或已关闭外部门禁都稳定拒绝；
11. 校验命令可以在仓库根和 `WEB/` 目录运行，退出码稳定，错误只输出路径、anchor 和规则码；
12. 不读取 `.env`、不访问网络、数据库、broker 或 Docker。

`WEB/package.json` 只允许增加 `verify:alarm-source-migration-boundaries` 命令，不得修改现有命令语义。

脚本文件头必须声明：该脚本属于 PRD-02 告警迁移门禁，放在 `WEB/scripts/` 仅为复用仓库 Node.js 执行环境，与 WEB 运行时或构建产物无关；移动或删除前必须重新评审。路径解析必须以脚本自身位置推导仓库根，不能依赖调用方当前目录。

## 5. 必测反例

- 删除一个来源、重复一个来源、拼错枚举或把 `scope` 改成 production；
- 路径不存在、越界、绝对路径、anchor 缺失或意外多次出现；
- 清单漏掉任一旧写、旧读、通知旁路或 `/device/alarm`；
- 将 AI 标为已存在 producer，或仓库新增 AI 告警发布特征但清单仍为未发现；
- 将 `tenant=0/default`、随机消息 ID、时间 fallback 或跨库写标为可接受；
- 把 C1/C2/C3/C4 或 production transport/capability 标为已批准；
- 在输出中放入疑似凭据、生产 URL、手机号或媒体签名参数。

反例可由测试脚本在临时目录构造，不得修改或清理工作区文件。

## 6. 完成定义

- 清单与 02C 评审表述一致，五类来源及全部 legacy entry 可追溯；
- 正例、逐项反例和仓库实时 anchor 检查全部通过，记录命令、退出码和检查数量；
- `git diff --check` 通过，diff 只在允许边界；
- Sol 独立复核没有 adapter、listener、producer、scheduler、Controller、SQL、配置或 capability 变更；
- 验收记录必须附 C1 门禁现状表，逐项列出 C0 验收、M1 identity/route、tenant/site/device 权威、阈值 cycle 规则、设备事件映射和旧写/新入口原子或补偿决策的 `OPEN/CLOSED` 证据；
- 交付状态最多为 `Verified-Local / Inventory Guard Only`，不自动解锁 C1。

- 生成来源 Schema、物理 Topic、消费组、DLQ 或配置；
- backfill、数据库画像、对账 SQL、迁移 Runbook 执行和 API 切读；
- 生产容量、性能、可用性或迁移完成声明。
