## 1. 验收结论

P02-M2-02A 的 **review-only runner 静态接线与反例** 已完成本地验收。V011/U011 未进入默认 dry-run、`APPLY_STEPS` 或默认 uninstall；本轮没有连接 PostgreSQL、没有调用 Docker、没有执行 DDL、没有创建临时数据库，也没有触碰目标/共享/生产实例。

本结论只关闭 02A 的静态实现门禁，不关闭临时 PostgreSQL 合同、生产迁移、capability、Topic、来源切换或容量门禁。交付上限保持 **Static-Verified / Production Apply Prohibited**。

## 2. 已实现合同

- V011 只接受 `apply --step V011`，U011 只接受 `uninstall --step U011`；二者均位于默认计划之外。
- 执行前同时要求 `TD006_REVIEW_ONLY=1`、合法审批标识、备份目录、`td006_review_*` 临时库名和预期 PostgreSQL `system_identifier`。
- 内置拒绝 `iot-device20`、`postgres`、`template0`、`template1`，并支持额外本地拒绝清单。
- 在备份和业务 DDL 前，以只读会话核对 `current_database()` 与 `(pg_control_system()).system_identifier`；任一不一致立即停止。
- V011 在任何业务 DDL 前检查 migration hash 和受管对象预存在；首次成功把表列、约束、索引、trigger、函数的 SHA-256 catalog 签名写入 history。
- 同 ID/hash 重放仅在实时 catalog 签名与 history 证据一致时返回 `STEP_SKIPPED`；漂移返回 `SCHEMA_SIGNATURE_MISMATCH`。
- V011 资产 DDL 与 SUCCEEDED history 位于 runner 独占的同一事务；失败后由 ADR-013 既有路径尝试记录 FAILED。
- U011 要求 V011 SUCCEEDED history 与实时签名一致；资产自身逐表拒绝任何非空业务、Inbox、Outbox 或审计事实，history 表保留。
- MIG-009 中文注释清单已纳入 V011 九表。
