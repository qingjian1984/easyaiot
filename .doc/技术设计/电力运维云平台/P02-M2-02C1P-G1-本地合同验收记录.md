## 1. 验收结论

G1 的三个仓库内设计包达到 `DESIGN-CLOSED`：

1. THRESHOLD 复用 V011 `alarm_rule/alarm_rule_version`，不建立平行版本事实；活动周期与逐规则 evaluation Inbox 使用 V011 之后的独立候选资产；legacy 历史不 backfill，从新 revision activationAt 起算。
2. THRESHOLD route 收紧为受信 `(tenantId, workloadId, configVersion)` release，DEVICE_EVENT 固定使用原始 request identity/time 和事件时历史 assignment；SUB_EVENT 在缺子设备 subject 合同前 fail-closed。
3. 两类来源共用 iot-device source-event outbox/local relay，但使用独立 ingress Inbox；TD-003 projection outbox、source outbox、V011 alarm outbox 三层事实严格隔离。

G1-EVENT 只完成机器 Schema 和空白模板，真实 mappings 仍为 0，状态 `WAITING-EXTERNAL`。ADR-019 保持 Proposed，ADR README 未更新，C1 adapter/C1A/C1B/C1C 全部继续关闭。

## 3. 关键裁决

### 3.1 THRESHOLD

- `alarm_rule_version` 是唯一版本事实；legacy current row 仅作迁移输入；
- 首版迁移 version=`1`，但 severity 未获产品映射时不得 PUBLISHED；
- 旧 OPEN/CLEARED 不导入统一周期，不用 latest OPEN 猜 cycle；
- 新 revision 发布不伪造旧周期恢复，旧 ACTIVE revision 只继续 recovery-only；
- 非 GOOD 零周期变化；顺序沿用 TD-003 `(epochMillis,sequence,messageId)`。

### 3.2 Route/identity

- projection event 必须扩出受信 workloadId/product/quality/originalOffset；当前 orchestrator 尚未形成该 outbox；
- historical release 必须曾 APPLIED，collectedAt 位于其应用窗口；ROLLED_BACK 仅在原窗口可验证 backlog；
- DEVICE_EVENT 的后端 `id/reportTime` 不合格；协议 requestId/time 未证明前不转告警；
- `power_device_assignment` 历史多匹配必须报 ambiguous，不能 LIMIT 1；
- 当前 SUB_EVENT 只含网关 Topic 身份，不得映射成子设备告警。

### 3.3 Outbox

- source relay 使用本地至少一次调用，不新增 Kafka Topic；
- `REQUIRES_NEW` 保持不变，崩溃窗口由告警 source Inbox 幂等吸收；
- source outbox 不复用 `kafka_sent`、`alarm_outbox` 或 TD-003 projection outbox；
- transport ACK/offset 只允许在来源业务事务提交后；当前 DEVICE_EVENT 吞异常行为不合格；
- 观察期旧通知 owner=1、新通知 owner=0；切换必须 XOR。
