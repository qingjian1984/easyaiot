# TD-006 附件：告警状态转换与并发矩阵

> 版本：0.1.2
> 日期：2026-08-25
> 状态：Freeze Candidate
> 上游：SPEC-005 0.1.2、ADR-010 1.1.0、TD-006 0.1.2
> 双基线：平台功能计划 1.5.0、EasyAIoT 项目开发宪法 1.6.0

## 1. 状态事实

主状态只有：`ACTIVE`、`ACKNOWLEDGED`、`PROCESSING`、`RECOVERED`、`CLOSED`、`IGNORED`、`FALSE_ALARM`。升级、维护、通知和证据均为正交事实，不得增加主状态组合。

每次状态写入必须同时满足：当前 tenant/数据权限、`expectedVersion`、动作幂等键和状态前置条件。API 重复同一幂等键返回第一次结果；不同请求命中旧版本返回 `ALARM_VERSION_CONFLICT`。

`ignoreGeneration` 是告警记录上的严格单次忽略代次。每次 `IGNORE` 进入 `IGNORED` 时单调递增；离开 `IGNORED` 后允许保留最后代次。到期任务必须携带领取时的 `expectedIgnoreGeneration`，并将 `status`、`expectedVersion`、`ignoredUntil<=now` 和代次一起放入 CAS 条件。

## 2. 状态转换矩阵

| 当前状态 | 动作/事件 | 目标状态 | 规则 |
|---|---|---|---|
| 不存在 | `SOURCE_RAISED` | ACTIVE | 来源 Inbox 成功且周期唯一；创建 occurrence=1 |
| ACTIVE | `SOURCE_RAISED` | ACTIVE | 同周期只增加 occurrence/lastOccurred，状态不变 |
| ACKNOWLEDGED | `SOURCE_RAISED` | ACKNOWLEDGED | 不撤销人员确认，只增加发生次数 |
| PROCESSING | `SOURCE_RAISED` | PROCESSING | 不打断处理，只增加发生次数 |
| IGNORED | `SOURCE_RAISED` | IGNORED | 保留事实并增加次数，不自动取消忽略 |
| ACTIVE | `ACK` | ACKNOWLEDGED | 保存确认人、时间、原因/备注 |
| ACKNOWLEDGED | 同幂等 `ACK` | ACKNOWLEDGED | 返回第一次结果，不追加重复动作 |
| IGNORED | `ACK` | ACKNOWLEDGED | 允许人员主动确认并解除忽略；清除当前忽略窗口、保留最后 `ignoreGeneration` 并追加结束原因 |
| ACKNOWLEDGED | `START_PROCESSING` | PROCESSING | 保存处理人和开始时间 |
| ACTIVE/PROCESSING/IGNORED | `SOURCE_RECOVERED` | RECOVERED | 来源恢复优先；忽略字段清空但历史保留在 action log |
| RECOVERED | 同周期重复 `SOURCE_RECOVERED` | RECOVERED | Inbox 幂等或业务 no-op，不追加重复领域事件 |
| RECOVERED | `CLOSE` | CLOSED | 需告警关闭权限和 expectedVersion |
| ACTIVE/ACKNOWLEDGED | `IGNORE` | IGNORED | 非 EMERGENCY；必须 reason、ignoredUntil 和原状态 |
| IGNORED | `IGNORE_EXPIRED/UNIGNORE` | ignoredFromStatus | 只允许恢复 ACTIVE/ACKNOWLEDGED；CAS 必须同时校验 `status + expectedVersion + ignoredUntil<=now + ignoreGeneration=expectedIgnoreGeneration` |
| ACTIVE/ACKNOWLEDGED/PROCESSING/IGNORED/RECOVERED | `PROPOSE_FALSE_ALARM` | 原状态 | 创建一条 PENDING 复核，提议人不能复核 |
| 上述状态且有 PENDING | `APPROVE_FALSE_ALARM` | FALSE_ALARM | 独立复核人批准；终态，不删除原始事实 |
| 上述状态且有 PENDING | `REJECT_FALSE_ALARM` | 原状态 | 复核记录 REJECTED，主状态不变 |
| ACTIVE/ACKNOWLEDGED/PROCESSING | `ESCALATE` | 原状态 | escalationLevel CAS 递增并发布独立事件 |

## 3. 明确拒绝的转换

| 请求 | 错误 |
|---|---|
| EMERGENCY 告警 `IGNORE` | `ALARM_EMERGENCY_IGNORE_FORBIDDEN` |
| ACTIVE 直接 `START_PROCESSING` | `ALARM_INVALID_TRANSITION`，必须先确认 |
| ACTIVE/ACKNOWLEDGED/PROCESSING 直接 `CLOSE` | `ALARM_INVALID_TRANSITION`，恢复不等于关闭 |
| PROCESSING `IGNORE` | `ALARM_INVALID_TRANSITION`，处理中不得隐藏 |
| IGNORED `ESCALATE` | `ALARM_INVALID_TRANSITION`；解除忽略后按当前策略重评估 |
| CLOSED/FALSE_ALARM 任意状态写 | `ALARM_INVALID_TRANSITION`；纠正只能追加审计/修订 |
| RECOVERED 收到同 cycleKey 的 `SOURCE_RAISED` | `ALARM_SOURCE_CYCLE_CONFLICT`；不得重开旧周期 |
| 提议人与复核人相同 | `ALARM_REVIEWER_CONFLICT` |
| 已有 PENDING 再建不同误报提议 | `ALARM_FALSE_ALARM_REVIEW_PENDING` |

## 4. 同周期与新周期

- `cycleKey` 由来源适配器生成并持久化，不能由查询时推导。维护模式开始和结束不切割告警周期。
- 同 cycleKey 在 ACTIVE/ACKNOWLEDGED/PROCESSING/IGNORED 中重复发生只更新 occurrence。
- 维护期间及维护结束同一评估周期再次满足条件时，只更新 occurrence/lastOccurred，并追加 `device.alarm.suppression-decided.v1`（决策为 `REEVALUATED`）；不得创建新的 alarmId 或 `created` 事件。
- 进入 RECOVERED 后，同 cycleKey 只能接收重复恢复或迟到证据；再次发生必须使用新 cycleKey 创建新 alarmId。
- 来源系统无法提供 cycleKey 时，适配器按已发布规则版本、对象和明确恢复边界生成；算法版本和生成规则写入来源映射。
- 旧数据没有可靠周期边界时不猜测合并，进入迁移差异清单。

## 5. 并发优先级

所有竞争最终由数据库 CAS 裁决，优先级只用于失败后重读与返回语义：

1. 来源恢复/误报复核终态。
2. 已提交的人工状态动作。
3. 忽略到期、升级和其他调度动作。

示例：忽略到期与来源恢复、主动解除忽略或再次忽略并发时，仅一个满足 `status + version + ignoredUntil + ignoreGeneration` 的 CAS 更新成功。失败方重读最终状态后结束为 no-op，不能把状态恢复成旧的 `ignoredFromStatus`。

## 6. capability 关闭语义

`power.alarm.core` 不能在存在活动规则、ACTIVE/IGNORED 告警、待投递 Outbox 或未处理 Inbox 时直接关闭。关闭流程为停止新规则发布 → 停止新来源接入 → 排空/隔离队列 → 处置活动告警 → 只读保留；到期恢复、恢复事件和审计在关闭完成前仍运行。

mini 从未启用该 capability，不创建规则、告警、Inbox/Outbox 或调度残留；这与运行中关闭是两个不同场景。

## 7. 必测并发场景

- 两个相同来源消息同时首次发生：一个创建，一个 DUPLICATE。
- 相同 messageId 不同 hash：原记录不变，冲突隔离。
- ACK 与 SOURCE_RECOVERED 并发：只允许一个 version 成功，重试后不得从 RECOVERED 回到 ACKNOWLEDGED。
- IGNORE_EXPIRED 与 SOURCE_RECOVERED 并发：最终 RECOVERED。
- 两个 ESCALATE 调度同时触发：只增加一级。
- CLOSE 与误报复核并发：只允许一个终态结果，另一个稳定冲突。
- 同一 Idempotency-Key 相同/不同请求摘要：相同重放、不同隔离并告警。
