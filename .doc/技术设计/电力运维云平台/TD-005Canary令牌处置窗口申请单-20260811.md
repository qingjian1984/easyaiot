## 0. 背景

Chrome CDP 认证窗口（BLOCKED_AUTH_ONLY_FLOW）期间，因认证成功后前端固定跳转 Dashboard 与认证-only allowlist 冲突，认证链虽 HTTP 200 但 UI 显示 `Network Error`，期间重复触发的登录在 tenant 123 / user 132 下产生 **3 组未撤销令牌**：

- access IDs：6102、6104、6106（创建时间 17:30:59 / 17:33:10 / 17:33:30）
- refresh IDs：6101、6103、6105（refresh token 到期时间 2026-08-12 对应时刻）

认证窗口在改造为 harness-only 流程前不得继续重试；本窗口先把这些令牌处置干净，恢复零令牌基线，再独立批准 harness 部署与重新认证。

## 1. 唯一允许动作

- 清空独立 Chrome（CDP）的 `localhost:8888` localStorage 与 sessionStorage（**不读取存储值，不导出 token**）；
- 在 `postgres-server / ruoyi-vue-pro20` 库 `public` schema，**软撤销** tenant 123 / user 132 的：
  - `system_oauth2_access_token`：id = 6102、6104、6106（共 3 行）
  - `system_oauth2_refresh_token`：id = 6101、6103、6105（共 3 行）
- 执行前在**仓库外**生成 `ruoyi-vue-pro20` 的 custom-format 全库备份；
- 备份成功后才执行软撤销；撤销与验收全部在受控 SQL 事务内进行，影响行数不符立即 `ROLLBACK`。

## 2. 明确禁止

- **不读取** `access_token` / `refresh_token` 字段的值（只按 `id` 定位，结果集不返回 token 字段）；
- **不用物理 `DELETE`**（与先例"软撤销"一致，保留审计行；MyBatis-Plus 逻辑删除要求 `deleted=1`）；
- **不修改 `expires_time`**（软删除后令牌自然不再被查询命中；改过期时间是错误手段）；
- **不撤销**其他用户、其他租户、其他时间窗的令牌；上一批 6093–6098 已闭合，**严禁触及**；
- 不刷新、不导出、不复制令牌到终端、仓库、文档或聊天；
- 不重建任何容器，不改 API 开关、HMAC Secret、角色、菜单、Topic、Nacos、capability；
- 不调用电力/产品/设备/绑定等业务 API，不写 Canary；
- 不在 `iot-device20` 库执行任何 SQL；本窗口仅作用于 `ruoyi-vue-pro20`；
- 本窗口成功**不构成** harness 部署、认证窗口或 Canary 写入批准。

## 3. 冻结撤销 SQL（精确到 id，三重 WHERE 保护）

```sql
-- access token 软撤销（期望影响 3 行）
UPDATE public.system_oauth2_access_token
SET deleted = 1, update_time = CURRENT_TIMESTAMP
WHERE id IN (6102, 6104, 6106)
  AND user_id = 132
  AND tenant_id = 123
  AND deleted = 0;

-- refresh token 软撤销（期望影响 3 行）
UPDATE public.system_oauth2_refresh_token
SET deleted = 1, update_time = CURRENT_TIMESTAMP
WHERE id IN (6101, 6103, 6105)
  AND user_id = 132
  AND tenant_id = 123
  AND deleted = 0;
```

约束说明：`id + user_id + tenant_id + deleted=0` 四重条件确保只命中目标行；任一 UPDATE 影响行数 ≠ 3 立即 `ROLLBACK`；不返回 `access_token` / `refresh_token` 字段值。

## 6. 失效条件

- 任一 UPDATE 影响行数 ≠ 3；
- 验收 §5.1 任一目标行 `deleted` 不为 1 或 `expires_time` 被改动；
- 验收 §5.2 仍存在 user 132 未过期 access token；
- 反向核验发现其他用户/租户 token `deleted` 状态变化；
- 备份 hash 校验失败或 `pg_restore -l` 失败；
- 上述任一触发即 `ROLLBACK`（若事务未提交）或从仓库外备份恢复，并停止后续动作。
