# TD-008：安全遥控与操作票

> 版本：0.2.0  
> 状态：In Review / Safety Hold  
> 日期：2026-08-24  
> 上游：[SPEC-007 0.2.0](../../规格/电力运维云平台/SPEC-007-安全遥控与操作票.md)  
> 双基线：[平台功能计划 1.5.0](../../架构设计/平台功能计划.md)、[项目开发宪法 1.6.0](../../开发规范/EasyAIoT项目开发宪法.md)  
> 关联决策：ADR-011、ADR-012、ADR-013、ADR-014、ADR-018

## 1. 安全结论

安全遥控唯一入口归属 `iot-device`。在现场设备/动作/联锁/回执目录未签字前，`power.control.safe` 保持关闭；本 TD 允许评审数据和接口骨架，不授权连接真实受控设备或放开既有直写入口。

## 2. 风险目录与默认值

`control_risk_catalog_version` 保存产品版本、服务/属性身份、动作、风险级别、操作票模板、审批策略、联锁策略、命令超时和回执能力。发布后不可覆盖。

分类顺序：现场硬禁用 > `HIGH` > 经批准的 `LOW_CONTROLLED` > 明确 `NOT_CONTROLLED`。未命中、版本过期或字段缺失一律按 `HIGH` 拒绝简化流程；低风险白名单不能豁免权限、预检、幂等、超时、回执与审计。

## 3. 数据模型

| 表 | 作用 | 核心约束 |
|---|---|---|
| `control_request` | 申请与唯一执行状态 | `request_id` PK；`idempotency_key` 租户内唯一；version CAS |
| `control_risk_catalog_version` | 发布后的产品/动作风险目录版本 | `catalog_version` PK；发布后内容不可覆盖；申请必须引用确定版本 |
| `operation_ticket` | 票据实例与模板快照 | 票据内容/版本不可覆盖；关联目标和有效期 |
| `control_approval` | 审批/拒绝/失效 | 申请人与审批人分离；追加记录 |
| `control_interlock_snapshot` | 预检/执行前联锁输入 | 保存来源、质量、时间、水位、结果 hash |
| `control_command` | 唯一命令与回执摘要 | `request_id` UNIQUE；`command_id` UNIQUE |
| `control_action_log` | 全过程审计 | sequence 唯一；普通用户不可删 |
| `control_outbox` | 命令与领域事件 | event ID 唯一；过期与重试有界 |
| `control_receipt_inbox` | 回执幂等/冲突 | command ID + receipt ID 唯一、hash 冲突隔离 |

DDL 必须有中文注释、租户/站点/状态索引、保留策略和不可删除约束决策。

## 4. 状态与事务

```text
REQUESTED
  ├→ PRECHECK_FAILED [terminal]
  ├→ CANCELLED [terminal]
  └→ PENDING_APPROVAL
       ├→ REJECTED [terminal]
       ├→ CANCELLED [terminal]
       ├→ EXPIRED [申请审批截止过期，CONTROL_REQUEST_EXPIRED]
       └→ APPROVED
            ├→ INVALIDATED [terminal]
            ├→ EXPIRED [批准执行窗口过期，CONTROL_APPROVAL_EXPIRED]
            └→ EXECUTING
                 ├→ SUCCEEDED [terminal]
                 ├→ FAILED [terminal]
                 └→ UNKNOWN [terminal，需人工复核]
```

- 创建：在同一请求事务内同步校验 capability、权限、目标和风险目录；失败 CAS 到 `PRECHECK_FAILED`，通过则追加 `PRECHECK_PASSED` 动作记录/联锁快照并 CAS 到 `PENDING_APPROVAL`，不产生独立的持久化预检主状态。保存不可变申请快照和确定的 `catalog_version` 引用。
- 审批：独立人员和票据满足后 CAS 到 `APPROVED`。`PENDING_APPROVAL` 超过申请审批截止时间进入 `EXPIRED` 并返回 `CONTROL_REQUEST_EXPIRED`；批准执行窗口默认 5 分钟、硬上限 15 分钟，窗口过期进入 `EXPIRED` 并返回 `CONTROL_APPROVAL_EXPIRED`。
- 执行：再次校验权限、硬禁用、目标版本、权威状态、质量和联锁；任一变化使批准失效。
- 同一申请事务内只插入一个 `control_command` 与 Outbox；重复执行返回原结果。
- 回执成功仍需按策略写后读；回执冲突或无法确认进入 `UNKNOWN`，禁止自动重发。

过期原因必须进入 API 响应和追加式动作审计，禁止用同一个通用过期码合并：

| 主状态 | 过期事实 | 稳定码 |
|---|---|---|
| `PENDING_APPROVAL → EXPIRED` | 申请审批截止未完成审批 | `CONTROL_REQUEST_EXPIRED` |
| `APPROVED → EXPIRED` | 批准执行窗口已过 | `CONTROL_APPROVAL_EXPIRED` |

## 5. 联锁执行器

联锁只接受版本化白名单 DSL：等值/范围、布尔、设备在线、质量、数据新鲜度、有限 AND/OR。禁止脚本、SpEL、SQL 和外部 URL。每个输入必须指向权威数据源并设置最大年龄；`TIMEOUT/COMM_ERROR/UNKNOWN` 均失败关闭。

执行前快照包含测点值、单位、质量、事件时间、接收时间、来源和策略版本。申请时通过不代表执行时通过。

## 6. 命令合同与设备边界

`ControlCommand.v1` 包含 `controlRequestId/commandId/tenantId/siteId/deviceId/targetIdentity/action/parametersRef/issuedAt/expiresAt/riskCatalogVersion/contractVersion/traceId`，敏感参数不写日志。

命令由 `iot-device` Outbox 发送，`iot-sink` Inbox 幂等接收并通过既有物模型下行。仅在设备明确支持相同 `commandId` 幂等时允许传输级重试；否则一次发送后超时进入不确定状态。

## 7. 旧入口阻断

必须盘点 `DeviceController.invokeService/setProperties`、`DeviceCommandController.issueCommands` 及内部 Feign/MQTT 调用。目标属于风险目录时：

1. 已迁移调用方转为创建控制申请；
2. 未迁移调用方返回稳定 `CONTROL_ROUTE_REQUIRED`；
3. 任何“内部调用”“管理员”或前端隐藏都不能绕过；
4. 旁路观测只记录调用事实，不发送高风险命令。

旧入口回滚不得恢复受控目标的直写能力。

## 8. 权限与审计

权限族至少分申请、审批、执行、复核、风险目录发布、票据模板、硬禁用查看。申请人不能审批自己的高风险请求；执行人与审批人是否可同人由现场批准策略决定，但默认分离。

审计保存操作者/主体、角色、租户/站点、动作前后状态、策略/票据/联锁版本、请求来源、trace、回执和失败原因。日志和导出不得包含可重放命令正文或凭据。

## 9. 故障与人工处置

- 发送前失败：保持未执行，可在批准窗口内重新请求执行。
- 发送后网络超时：`UNKNOWN`，不自动重发，启动状态复核和人工 Runbook。
- 回执失败：FAILED，但保存设备错误和写后读事实。
- 回执冲突：进入 `UNKNOWN`，隔离、告警、冻结该目标后续控制，待复核。
- 数据源/联锁不可用：执行前拒绝，不采用缓存旧值放行。

## 10. 验证矩阵

- 状态全矩阵、申请审批截止过期/批准执行窗口过期（分别验证 `CONTROL_REQUEST_EXPIRED` 和 `CONTROL_APPROVAL_EXPIRED`）、审批失效、并发 execute、重复 Idempotency-Key。
- 同人审批、跨租户、数据范围、管理员旁路、现场硬禁用。
- 联锁缺失/陈旧/坏质量/变化、恶意 DSL、时钟偏差。
- 设备幂等/非幂等、发送前后故障、重复/冲突回执、写后读不一致。
- 旧三个入口及内部调用旁路阻断。
- mini/依赖不足无控制 Bean/路由/消费者；standard/full 同安全语义。
- DDL forward/rollback、审计保留和故障注入。
