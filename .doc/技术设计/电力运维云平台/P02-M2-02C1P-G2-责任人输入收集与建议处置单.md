## 1. 目的与授权边界

本文件把 C1P-G1 遗留的四类外部输入转换为可逐项签署的决策包。仓库执行者负责提供事实、风险与推荐值，产品、M1/TD-003、设备协议等责任人负责确认其业务和协议事实。

本文件不是责任人签署，不把推荐值自动变成批准值，也不授权 C1A、来源 adapter、DDL、数据库执行、Kafka/MQTT transport、双写、backfill、对账或切读。四项输入未全部关闭、ADR-019 未 Accepted 且 ADR 索引未同提交更新前，C1-C4 继续关闭。

## 3. G2-01：legacy severity、保留范围与 activation

### 3.1 推荐选择

| legacy 值 | 推荐统一 severity | 理由 |
|---|---|---|
| `INFO` | `INFO` | 信息提示语义保持不变 |
| `WARNING` | `NORMAL` | 对应一般告警，避免无依据提升处置强度 |
| `CRITICAL` | `IMPORTANT` | 对应重要告警；legacy 严重不自动获得“永不可忽略”的紧急安全语义 |

推荐明确规定：legacy 没有任何值自动映射 `EMERGENCY`。紧急等级必须由产品对具体规则单独批准，并具备不可忽略、升级和值班处置能力；不能通过批量迁移隐式获得。

保留与激活推荐如下：

1. `enabled=1` 且 tenant、site、条件与 severity 均通过预览校验的规则，进入 `READY_NEW_REVISION`；
2. `enabled=0` 的规则保留为 legacy 只读证据，可生成统一 DRAFT，但不发布、不激活；
3. tenant/site 冲突、非法 JSON、min/max 与 rules 语义冲突的条目隔离，不静默修复；
4. `activationAt` 使用未来受控发布窗口的 RFC 3339 时间并带显式 offset，由发布清单签署时填写；不得使用文档日期、迁移执行时 `now` 或服务器默认时区；
5. activationAt 前的遥测和 legacy OPEN/CLEARED 不 backfill；新 revision 从 activationAt 后第一条有序 GOOD 遥测起算。

### 3.2 产品规则 owner 必填

| 字段 | 待填内容 |
|---|---|
| decision | `APPROVE_RECOMMENDATION` / `APPROVE_WITH_CHANGES` / `REJECT` |
| severityMapping | 若修改，逐项填写 `INFO/WARNING/CRITICAL` 的目标等级及理由 |
| retainedScope | 全部有效 enabled 规则，或明确的产品/设备/规则排除清单 |
| disabledPolicy | 推荐 `DRAFT_ONLY`；若不同需说明历史与回滚影响 |
| activationAt | RFC 3339 + 显式 offset；只能在迁移预览清单冻结后填写 |
| approvedBy / approvedAt | 责任人及带 offset 的签署时间 |
| decisionRef | 可审计的产品决策文档或评审记录 |

未填写完整前，THRESHOLD revision 不得 PUBLISHED。

## 4. G2-02：TELEMETRY_PROJECTED_V1 owner 确认

### 4.1 推荐合同

由于当前 projection outbox 尚未实现或发布，推荐在首次实现前把以下字段冻结为 v1 必填；若 M1 owner 证明已有任何环境发布 v1，则不得原地收紧，必须创建 v2 并执行消费者先行迁移。

| 字段 | 必须来源/约束 |
|---|---|
| `messageId/contentSha256` | telemetry Inbox 已校验的 canonical identity/hash |
| `tenantId` | Topic、principal、release 与 Envelope 一致性校验后的租户 |
| `workloadId` | MQTT principal/ingress route 持久化事实，禁止从 Envelope 或当前设备表猜测 |
| `productIdentification` | canonical Topic 与 Inbox 持久化 route 元数据 |
| `siteCode/deviceIdentification/propertyCode` | canonical Envelope 且已和 release/注册事实交叉校验 |
| `collectedAt/originalOffset/sequence/quality/configVersion` | Envelope 原始事实，不以接收时间重建 |
| `storeResult` | 只允许 `STORED/DUPLICATE` |

完成状态和 projection outbox 必须在同一 PostgreSQL 事务提交；事件至少一次发布，消费者按 `(tenantId,messageId,eventType)` 幂等。C1 只消费正式版本化事件，不能从当前表、缓存或旧业务事件补字段。

### 4.2 M1/TD-003 owner 必填

| 字段 | 待填内容 |
|---|---|
| publicationHistory | `NEVER_PUBLISHED`，或列出已发布环境、版本和时间 |
| eventVersionDecision | `EXTEND_V1_BEFORE_FIRST_PUBLISH` / `CREATE_V2` |
| ownerDocument | 更新后的 TD-003、事件 Schema/API 资源路径 |
| testPlan | 必须覆盖缺/错 workload、product、quality、offset、同 ID 异 hash、COMPLETED/outbox 原子回滚、relay 重投 |
| approvedBy / approvedAt / decisionRef | M1/TD-003 owner 签署与可审计引用 |

Schema、测试计划和 owner 签署未同时到位前，THRESHOLD adapter 继续关闭。

## 5. G2-03：DEVICE_EVENT 协议原始身份与时间

### 5.1 当前协议矩阵

| 路径/codec | requestId 事实 | occurredAt 事实 | 当前资格 |
|---|---|---|---|
| MQTT + Alink | `AlinkMessage.id` 被传入 requestId，但只有注释声称设备内唯一；无重试和异正文碰撞 fixture | 协议结构无原始时间字段 | `DISABLED` |
| TCP JSON | `TcpJsonMessage.id` 被传入 requestId；无稳定性 fixture | 输入有 `timestamp`，但 decode 丢弃，后续只生成 backend reportTime | `DISABLED` |
| TCP Binary | 帧内 messageId 被传入 requestId；编码缺失时会生成后端 ID，必须区分上下行 | 帧合同无原始时间字段 | `DISABLED` |
| HTTP/MQTT transport | transport 本身不是身份 owner，资格取决于所用版本化 codec | 无独立 occurredAt 合同 | `DISABLED` |
| Modbus/OPC UA/polling | 当前属于属性遥测采集，不作为 direct DEVICE_EVENT 来源 | 不适用 | `OUT_OF_SCOPE` |
| SUB_EVENT Topic | Topic 只有网关 product/device，没有冻结子设备 subject、子 requestId 和子时间 | 不合格 | `UNSUPPORTED` |

`IotDeviceMessage.id/reportTime` 明确由后端生成；`DeviceEventHandler` 还允许 tenant=0 和 `LocalDateTime.now()` fallback；`DeviceEventSubscriber` 捕获异常后不向 transport 暴露失败。这些现状只能作为旧链事实，不是 C1 可接受身份、时间或 ACK 证据。

### 5.2 每个拟启用协议必须提交

1. 版本化协议/codec 名称及 direct event Topic；
2. requestId 的原文字段、字符/长度限制、设备内唯一窗口和重试不变规则；
3. occurredAt 的原文字段、单位/格式、显式 offset、精度、时钟来源和未来/历史容差；
4. 同一原文重试至少两次仍产生相同 requestId/time/hash 的 fixture；
5. 同 requestId 异正文必须进入 collision/quarantine 的负例；
6. 缺失、无 offset、超精度、接收时间 fallback 和后端生成 ID 全部 fail-closed；
7. 协议 owner 的 approvedBy/approvedAt/decisionRef。

协议可以逐个批准；未批准协议保持关闭，不得以“通用 IotDeviceMessage 有 requestId 字段”替代来源证明。

## 6. G2-04：DEVICE_EVENT 产品 allowlist

产品输入必须从 [DRAFT 模板](./assets/c1p-g1/device-event-alarm-allowlist-template.json) 复制，并通过 [v1 Schema](./assets/c1p-g1/device-event-alarm-allowlist-v1.schema.json) 与 [G1-EVENT 语义校验](./assets/c1p-g1/G1-EVENT-产品Allowlist输入说明.md)。不得直接覆盖空白模板。

每个候选 mapping 至少填写并评审：

| 分类 | 必填决策 |
|---|---|
| scope | productIdentification；需要时再限定 modelIdentifier |
| lifecycle | 唯一 raisedMatcher、唯一 recoveredMatcher；当前只允许 `PAIRED` |
| identity | correlationJsonPointer、occurredAtJsonPointer，且已被 G2-03 批准的协议提供 |
| alarm | alarmTypeKey、固定 severity；payload 不得自由覆盖 severity |
| upgrade | `PIN_ORIGINAL_VERSION_UNTIL_RECOVERED` |
| evidence | raised、recovered、未命中、correlation 不一致及字段缺失 fixture |
| approval | approvedBy、approvedAt、decisionRef、按 G1-EVENT 规则计算的 contentSha256 |

G2-03 没有任何协议通过前，不接受 APPROVED allowlist；产品事件名称或界面截图不能替代原始身份、恢复关联和时间证据。当前运行结论固定为 `DENY_ALL`。

## 7. 签署与关闭顺序

1. 产品规则 owner 签署 G2-01；
2. M1/TD-003 owner 提交版本化事件合同与测试计划并签署 G2-02；
3. 设备协议 owner 按协议逐项提交证据并签署 G2-03；
4. 产品负责人只针对已通过 G2-03 的协议形成 APPROVED allowlist 并签署 G2-04；
5. Sol 校验完整性、Schema/hash、重叠、负例和仓库路径，形成 `C1P-G2 输入处置记录 1.0.0`；
6. ADR-019 独立评审。只有决策所有者 Accepted 且同提交更新 ADR README 后，才可另行冻结 C1A 范围。

签署不得用聊天中的“可以”“按建议执行”替代 decisionRef；可以引用受控评审记录，但必须明确责任人、时间、版本、具体选择及适用范围。
