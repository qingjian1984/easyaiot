## 1. 设计边界

`iot-device` 保存事故时间线、证据索引、冻结清单和报告任务；VIDEO/RUNTIME 产生媒体，`iot-sink` 接入媒体并管理受控 NFS 暂存到 MinIO 的归档。TelemetryStore 仍是遥测事实源。

PRD-03 未基线化期间，只冻结后端证据合同和失败隔离；预置位交互、SCADA 展示和完整视频联动体验保持 OPEN。

## 2. 数据模型

| 表 | 作用 | 关键约束 |
|---|---|---|
| `incident_timeline_event` | 统一时间线追加投影 | `(tenant_id,source_type,source_event_id)` 唯一；`source_event_id` 是上游版本化事件的全局稳定 ID |
| `evidence_index` | 媒体/遥测/日志/报告索引 | `evidence_id` PK；来源唯一；hash 冲突隔离 |
| `evidence_action` | 抓拍、录像、归档动作 | alarm+camera+action+policyVersion 唯一 |
| `telemetry_freeze_manifest` | 查询窗口、水位、摘要与修订 | 已发布版本不可覆盖；revision 链连续 |
| `incident_report_task` | 异步报告任务 | 幂等 purpose；有界重试和状态 CAS |
| `evidence_outbox` | 证据请求/结果事件 | event ID 唯一、禁止媒体大正文 |
| `evidence_inbox` | 跨服务结果幂等 | message ID+hash；冲突隔离 |

对象本体不进 PostgreSQL/Kafka；只保存受控对象 key、版本、大小、媒体类型、SHA-256、归档状态、保留策略和缺口码。

## 3. 时间线投影

TD-006/007/008 的版本化领域事件进入事故 Inbox，投影为追加时间线。每项必须携带 `sourceEventId`（持久化字段 `source_event_id`），它是上游版本化事件的全局稳定 ID；同一租户、来源类型和 `sourceEventId` 不得重复投影。`sourceSequence` 只用于同一来源的排序和 tie-breaker，不参与幂等判定；同一 `alarmId` 的两次升级必须生成不同的 `sourceEventId`。排序键为 `occurredAt + sourceSequence + timelineEventId`，展示按 UTC 排序并保留原时区。重建新投影时使用版本号切换，禁止覆盖已发布事故报告引用的旧清单。

事件缺失、迟到或版本未知产生 `INCOMPLETE/UNSUPPORTED_VERSION` 标记，不静默丢弃。

## 4. 遥测冻结

在线请求先经权限和上限校验，再调用 `TelemetryStore`：standard PostgreSQL、full TDengine，共用查询合同。冻结清单保存测点、`[start,end)`、后端抽象版本、水位、质量策略、行数、摘要和结果对象 hash。

超过 10 点/1 小时/100,000 条时，若异步能力和任务配额可用，返回 accepted/202、`EVIDENCE_TELEMETRY_ASYNC_REQUIRED` 和任务 ID，由有界任务生成冻结清单；该结果表示已受理，不是失败。若异步能力未启用或任务配额不可用，按原因返回 `EVIDENCE_LIMIT_EXCEEDED` 或 `EVIDENCE_CAPABILITY_UNAVAILABLE` 并 fail-closed，不得执行无界同步查询，也不得把通用 TelemetryStore 配额错误直接暴露为事故合同。TD 不允许业务端绕过上限。告警未恢复使用临时结束和 `OPEN_WINDOW`，恢复后生成新修订而非覆盖。

## 5. 媒体动作与归档状态

```text
REQUESTED → CAPTURED → STAGED → ARCHIVING → ARCHIVED
          └→ RETRY_WAIT/FAILED_FINAL/EXPIRED
```

1. 告警事务后异步发布 evidence request。
2. VIDEO/RUNTIME 执行抓拍/录像并返回媒体元数据；单摄像机失败不影响其他动作。
3. `iot-sink` 将对象写入受控 NFS 暂存，记录路径白名单、大小和 SHA-256。
4. worker 流式上传 MinIO，校验大小/hash 后发布 archived 事件。
5. `iot-device` 更新索引；成功归档且不再是唯一副本后才按策略清理暂存。

MinIO 不可用时有界重试；NFS 达高水位按等级/保留策略执行背压并产生缺口，禁止改写到非受管本地目录。

## 6. 对象键与访问

对象键建议为 `tenant/{tenantId}/site/{siteId}/alarm/{alarmId}/{evidenceType}/{evidenceId}/{revision}`，服务端必须从授权事实构造，不能直接信任客户端 key。

下载/播放通过短时、限对象、限方法的签名 URL；签发前重新验证告警、站点、设备/摄像机和对象权限。URL 不写日志、审计正文或永久分享记录。

## 7. 保留与不可变性

完整事故冻结启用前必须选择批准的 `retentionPolicyId/version`。清理任务同时检查普通期限、紧急期限、延长审批和 legal hold；删除使用可重试 tombstone 并保留审计。

应用层不可覆盖和 SHA-256 不等于法定 WORM。只有部署确认 MinIO object lock/版本化、时间源和治理流程后，manifest 才能声明对应不可变能力。

## 8. 报告任务

报告 worker 只读取冻结清单和索引，不进行无界实时查询。输入包含模板版本、来源水位和脱敏策略；输出写 MinIO 并计算 hash。迟到证据生成 `revisionOf` 新版本，原发布版保持可下载。

PDF/Excel 版式质量由 PRD-06 后续规格复用；当前只验证内容完整性、分页/大小上限、敏感字段和对象授权。

## 9. 兼容迁移

旧 VIDEO/iot-sink `alertId` 先经 TD-006 `alarm_source_mapping` 映射；没有唯一映射的媒体进入待认领清单，不得把旧 ID 当全局 `alarmId`。旧路径迁移任务只处理配置的受管根目录，校验解析后的绝对路径仍在根目录内，支持 dry-run、批次、hash 对账和可重跑。

回滚只停止新动作/归档和切回旧详情读，不删除已归档对象、证据索引、清单或报告。

## 10. 验证矩阵

- 时间线：重复/乱序/迟到/缺事件、同一 `sourceEventId` 重复投影、同一告警两次升级使用不同 `sourceEventId`、投影重建、状态来源一致；`sourceSequence` 只验证排序，不作为幂等键。
- 遥测：跨后端合同、坏质量/缺失、边界窗口、超限异步、开放窗口修订。
- 媒体：三摄像机部分失败、NFS/MinIO 中断、容量满、hash/大小冲突、死信恢复。
- 安全：跨租户、对象 key 注入、路径穿越、签名 URL 泄露/过期、媒体权限独立。
- 保留：legal hold、延长、清理重试、唯一副本保护、对象锁能力声明。
- 档位：mini 无任务/消费者；standard 拒绝完整冻结；full 未配留存仍关闭。
- 迁移：旧 ID 对账、dry-run、重复运行和回滚不删证据。
