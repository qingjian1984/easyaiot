### 2.1 版本不一致处置

签署记录引用了正确的仓库路径、§3 G2-01、推荐内容和逐项值，因此已批准的具体业务选择不存在语义歧义，可以部分接受。已签署文件不得由执行者静默改写；责任人需用以下任一方式关闭审计项：

1. 提交 G2-01 v1.0.1 勘误版，明确签署对象为 `C1P-G2 输入收集与建议处置单 0.1.0 §3`，其余决策不变；或
2. 提交独立勘误附录，引用原签署提交 `d7d77d5c6`，声明 `1.0.0` 是笔误、正确版本为 `0.1.0`。

聊天说明或执行者自行改字不构成勘误。该审计项与 activationAt 均关闭后，G2-01 才能进入 `CLOSED-OWNER`。

## 3. G2-02 仓库事实复核

| 事实 | 当前证据 | 结论 |
|---|---|---|
| TD-003 | 1.0.3 / In Review；§12 设计 projection outbox 和 `TELEMETRY_PROJECTED_V1` | 只有设计基线 |
| API Schema | `iot-sink-api` 当前没有 telemetry projected 版本化事件 Schema | OPEN |
| projector | 当前只完成 Store→Inbox COMPLETED/重试/死信；没有 outbox 同事务写入 | OPEN |
| SELECT/row | 未携带 workloadId、productIdentification、quality、originalOffset、dataPriority | OPEN |
| value | canonical Envelope 中存在 `value/valueEncoding`，但 TD-003 §12 event payload 未显式列入 | OPEN-CONTRACT |
| tests | 现有 batch 测试不覆盖 event Schema、COMPLETED/outbox 原子性、relay 重投和 C1 所需字段 | OPEN |
| 发布历史 | 仓库无 publisher/outbox 实现只能证明“当前提交未实现”，不能证明外部环境从未发布 | OWNER CONFIRMATION REQUIRED |

THRESHOLD evaluator 必须从版本化投影事件直接得到规范 `value/valueEncoding` 和 quality；不允许为补字段查询当前设备表、跨档位时序后端或完整 Inbox 原文。G2-02 因此需要在原四字段之外补充 value/dataPriority 合同。
