> 文档版本：0.2.0  
> 日期：2026-08-05  
> 状态：Executed / Verified

> 上游依据：[TD-005 目标数据库画像报告](./TD-005-目标数据库与现有实现画像报告.md)、[ADR-012（Proposed）](../../架构决策/电力运维云平台/ADR-012-产品根属性与服务参数单一事实.md)

## 1. 处置结论

4 条记录判定为 **过期演示种子残留（obsolete demo seed residue）**，建议处置码为 `DELETE_OBSOLETE_DEMO_SEED`：

1. 从初始化基线 `.scripts/postgresql/iot-device10.sql` 删除这 4 条旧种子；
2. 对已初始化环境使用受保护、可审计、可回滚的精确删除脚本；
3. 删除后重跑 TD-005 目标库画像，要求 `orphanProperties=0`；
4. 不补建标识为 `8700054938017792`、`9030000000000001` 的产品，也不把旧记录迁移到现行演示产品。

本方案已于 2026-08-05 按授权完成执行：初始化基线已移除精确 4 行，目标数据库已用 `COMMIT_REMEDIATION=true` 提交删除，修复后画像确认孤儿属性为 0。脚本仍保持默认 `ROLLBACK`，避免被无意重复执行。

2026-08-04 已在本地目标实例完成一次修复脚本默认回滚演练：精确命中并临时删除 4 行，删除后断言通过，随后 `ROLLBACK`；演练后只读复核仍为 4 行。为避免 Windows PowerShell 管道改变中文常量编码，修复断言和回滚值使用 UTF-8 十六进制字节表达式。

## 3. 判定证据

### 3.1 来源证据

- Git 提交 `d29e0dbdcbd20b18feb84bfdb3e46031eed2c81e`（`udp(DEVICE)：增加Modbus-TCP/Modbus-RTU/OPCUA功能`）同时引入旧的 4 条属性和现行演示产品、设备及属性；
- `git show --stat d29e0dbd -- .scripts/postgresql/iot-device10.sql` 显示该提交对初始化文件增加 25 行、删除 6 行；裁剪 diff 同时包含四个旧主键、三个 `IND_*` 产品、三台演示设备和九条现行属性；
- 旧标识仅存在于 `.scripts/postgresql/iot-device10.sql` 的 4 条 `product_properties` 种子中；
- 同一初始化基线没有两个旧标识对应的 `product` 记录。

### 3.2 下游引用证据

2026-08-04 在 `BEGIN TRANSACTION READ ONLY` 中逐表核对全部 `product_identification` / `template_identification` 列：

| 对象 | 两个旧标识的引用数 |
|---|---:|
| `product_properties.product_identification` | 4 |
| `device` | 0 |
| `device_service_invoke_response` | 0 |
| `ota_packages` | 0 |
| `product`（产品标识与模板标识） | 0 |
| `product_event`（产品标识与模板标识） | 0 |
| `product_script` | 0 |
| `product_services`（产品标识与模板标识） | 0 |
| `product_template` | 0 |

`product_template` 的模型只以 `template_identification` 标识，不存在 `product_identification` 列。命令、请求和响应表也不直接保存产品标识，专项检查通过 `service_id + tenant_id` 关联 `product_services`，三条命令链结果均为 0。脚本还会从 `information_schema` 动态发现并检查所有直接承载 `product_identification` / `template_identification` 的基础表列；当前除目标列外扫描 12 列，结果为 0。

因此，这些记录没有可保留的父对象，也没有会因删除而断开的业务引用。

### 3.3 现行替代关系

现有演示链已经使用明确、可读且协议分离的标识：

| 产品 | 现行标识 | 设备 | 属性 |
|---|---|---:|---:|
| Modbus TCP 演示产品 | `IND_MODBUS_TCP_DEMO` | 1 | 3 |
| Modbus RTU 演示产品 | `IND_MODBUS_RTU_DEMO` | 1 | 3 |
| OPC UA 演示产品 | `IND_OPCUA_DEMO` | 1 | 3 |

每个现行产品都有 `temperature`、`setpoint`、`running`，设备协议配置也引用这些现行产品标识。旧 Modbus 标识没有信息可判断应归属 TCP 还是 RTU，强制迁移会引入歧义和重复成员。

## 4. 方案比较

| 方案 | 结论 | 原因 |
|---|---|---|
| 补建两个旧父产品 | 拒绝 | 会制造与现行三套演示产品并存的幽灵产品，且旧 Modbus 标识无法区分 TCP/RTU。 |
| 映射到现行产品 | 拒绝 | `temperature`、`setpoint` 已存在；映射会造成重复，且 Modbus 目标不确定。 |
| 增加隔离状态长期保留 | 拒绝 | `product_properties` 没有隔离/软删除语义；为无引用演示残留扩表没有业务价值。 |
| 精确删除并修正种子 | 采纳 | 对象无父记录、无下游引用且已有完整替代链；影响范围最小并可完整回滚。 |

### 5.1 初始化基线修改

`.scripts/postgresql/iot-device10.sql` 使用 PostgreSQL `COPY public.product_properties ... FROM stdin` 数据段，不是普通 `INSERT`。获批后只删除以下四个以主键开头的 COPY 数据行，不改变表定义、COPY 头尾或现行 `911xxx` 属性：

```text
900101 ... 8700054938017792 ...
900102 ... 8700054938017792 ...
900111 ... 9030000000000001 ...
900112 ... 9030000000000001 ...
```

定位与复核命令：

```powershell
rg -n '^(900101|900102|900111|900112)\s' .scripts/postgresql/iot-device10.sql
rg -n '^(911001|911002|911003|911011|911012|911013|911021|911022|911023)\s' .scripts/postgresql/iot-device10.sql
git diff -- .scripts/postgresql/iot-device10.sql
```

第一条命令在修改前必须精确命中 4 行、修改后必须为 0；第二条必须始终精确命中 9 行。不得使用不受主键和旧产品标识双重约束的批量替换。

推荐执行顺序：

```powershell
# 1. 只读预检
docker exec postgres-server psql -U postgres -d iot-device20 -v ON_ERROR_STOP=1 -f /path/orphan-properties-precheck.sql

# 2. 先做默认回滚演练；确认输出精确为 4 行
docker exec postgres-server psql -U postgres -d iot-device20 -v ON_ERROR_STOP=1 -f /path/orphan-properties-remediation.sql

# 3. 评审授权后，在维护窗口显式提交
docker exec postgres-server psql -U postgres -d iot-device20 -v ON_ERROR_STOP=1 -v COMMIT_REMEDIATION=true -f /path/orphan-properties-remediation.sql
```

容器命令中的 `/path/...` 必须替换为容器内实际挂载路径；生产环境不得直接复用本地容器路径或数据库名。

## 6. 提交前置条件

同时满足以下条件才允许设置 `COMMIT_REMEDIATION=true`：

1. 目标环境重新运行预检并全部为 `PASS`；
2. 两个旧标识在硬编码命令链和动态发现的所有产品/模板标识列中仍只有这 4 条目标属性；
3. 四行 `row_to_json` 完整快照 MD5 与本方案固化值一致；MD5 只用于等值漂移检测，不作为安全签名；
4. 已保存预检原始输出和数据库备份/恢复点；
5. 初始化基线同步移除 4 条旧种子，避免新环境再次引入；
6. 变更单明确执行人、环境、时间、Git 提交和回滚责任人；
7. TD-005/ADR 评审人批准该数据修复，不把本脚本视为 ADR-012 自动 Accepted。

任一环境出现额外行、父产品或下游引用时，脚本必须失败关闭；不得扩大 `DELETE` 条件或手工跳过断言。

## 7. 验收与回滚

### 7.1 验收

- 精确删除计数为 4；
- 两个旧标识在 `product_properties` 中计数为 0；
- 重跑 `target-schema-profile.sql` 后孤儿属性计数为 0，其他重复/标识作用域指标不得回退；
- 三个现行演示产品、3 台演示设备和 9 条现行演示属性保持不变；
- 在初始化基线已同步移除 4 条旧 COPY 数据行并附 Git diff 的前提下，空库重建后不再出现四个旧主键或两个旧标识。

### 7.2 回滚触发

只有在删除被证明影响未纳入数据库画像的外部消费者时才执行回滚。回滚脚本恢复的是已知不一致状态，因此执行后必须：

1. 记录触发原因与外部消费者证据；
2. 暂停 TD-005 门禁关闭；
3. 补充外部依赖画像并重新决策，而不是把回滚后的孤儿状态当成正常基线。

## 9. 评审意见（2026-08-04）

### 9.1 总体评价

**处置方案质量：高。** 三件套（precheck / remediation / rollback）设计严谨：默认回滚、精确 4 行断言、`LOCK ... IN SHARE ROW EXCLUSIVE MODE`、`SET LOCAL lock_timeout/statement_timeout`、UTF-8 十六进制避免 PowerShell 编码问题、`COMMIT_REMEDIATION` / `COMMIT_ROLLBACK` 显式提交开关、失败关闭。与 ADR-012 方向完全一致（"不补建旧父产品、不映射到现行产品、精确删除"），与画像报告 §3/§4 的孤儿事实吻合。

### 9.2 脚本核对

| 脚本 | 核对 |
|---|---|
| `orphan-properties-precheck.sql` | ✅ `BEGIN TRANSACTION READ ONLY`；4 项检查（TARGET_ROWS / TARGET_SCOPE_ROWS / PARENT_PRODUCTS / DOWNSTREAM_REFERENCES）；最终 `ROLLBACK` |
| `orphan-properties-remediation.sql` | ✅ `BEGIN` + `LOCK` + `DO` 块精确断言 4 行（含 UTF-8 十六进制）；`WITH deleted AS (DELETE ... RETURNING *)` 输出证据；删除后再断言 0 行；`COMMIT_REMEDIATION` 分支默认回滚 |
| `orphan-properties-rollback.sql` | ✅ 前置冲突检查（4 个主键不得已存在）；完整 `INSERT` 4 行（含 `convert_from(decode(...,'hex'),'UTF8')` 处理中文 property_name/description/unit）；后置 `v_restored=4` 断言；`COMMIT_ROLLBACK` 分支默认回滚 |

### 9.3 可改进之处

| # | 严重度 | 观察 | 建议修订 |
|---|---|---|---|
| O1 | MEDIUM | `precheck.sql` 和 `remediation.sql` 的下游引用检查覆盖 8 张表，**缺 `product_commands` 防御性检查** | 属性删除不会直接影响 `product_commands`，但应加 `SELECT count(*) FROM product_commands WHERE ...`（期望 0）作为防御性断言，防止未来 schema 引入新引用路径 |
| O2 | MEDIUM | `rollback.sql` 只锁 `product_properties`，未锁 `product` 表 | 若回滚期间并发创建了旧 `product_identification` 的父产品，回滚后会再次产生孤儿。建议前置检查 `product WHERE product_identification IN (...)` 仍为 0，或同时 `LOCK TABLE product IN SHARE ROW EXCLUSIVE MODE` |
| O3 | MEDIUM | §1/§5 仅称"从初始化基线 `.scripts/postgresql/iot-device10.sql` 删除这 4 条旧种子"，**未给出具体 diff 位置和修改方式** | 补一小节"基线文件修改"：列出 4 条 INSERT 在 `iot-device10.sql` 中的行号或匹配模式（例如 `WHERE id IN (900101, 900102, 900111, 900112)`），以及提交前的 diff 样例 |
| O4 | LOW | §7.1 验收条件第 5 项"初始化空库重建后不再出现四个旧主键或两个旧标识"**未明确以"基线文件已修改"为前置条件** | 改为"在基线文件已同步移除 4 条种子（提交证据附后）的前提下，空库重建不再出现..." |
| O5 | LOW | 删除条件硬编码 `tenant_id = 1` | 当前环境仅租户 1 有孤儿，但若未来多租户部署出现其他租户孤儿，需参数化 `:TARGET_TENANT_ID`。可在脚本顶部 `\set` 默认 `1`，便于复用 |
| O6 | LOW | §3.1 称"Git 提交 `d29e0dbd...` 同时引入旧的 4 条属性和现行演示产品" | 建议补 `git show d29e0dbd --stat` 的裁剪输出作为证据，证明确实是同一 commit 引入 |
| O7 | LOW | §3.2 下游引用检查 `product_template` 只用 `template_identification` | 与其他表同时检查两种标识的写法不一致。由于 `product_template` 语义上只承载模板标识，可保留现状但加一行说明："product_template 只以 template_identification 标识" |

### 9.4 与上游文档的协同

- **与画像报告 §4/§7 协同**：本方案精准处置"删除链 FAIL"的 4 条孤儿属性；执行后重跑画像，该子门禁可由 FAIL 升为 PASS（其他子门禁仍独立评估）；
- **与 ADR-012 协同**：§1 明确"尚未授权执行数据库删除，也尚未修改初始化 SQL"、§6.7 明确"不把本脚本视为 ADR-012 自动 Accepted"，与 ADR-012 §6 "Proposed 阶段不授权修改生产表"完全一致；
- **与 TD-005 §23 门禁 1 协同**：方案是门禁 1 通过所需的前置清理，但不替代 Mapper/实体/VO 漂移修复、租户感知唯一约束和删除事务边界（画像报告 §6 P0 后 4 项）。

### 9.5 结论

**处置方案可采纳。** 三件套 SQL 设计严谨，默认回滚 + 精确断言 + 失败关闭 + UTF-8 十六进制，与 ADR-012 方向一致，与画像报告事实吻合。

执行建议：

1. 先补 O1（`product_commands` 防御性检查）和 O2（rollback 锁 `product` 或前置检查）；
2. 按 O3 补"基线文件修改"小节，明确 4 条 INSERT 在 `iot-device10.sql` 的位置和 diff；
3. 维护窗口内按 §5 顺序执行：precheck → remediation 默认回滚演练 → 评审授权 → `COMMIT_REMEDIATION=true`；
4. 执行后立即重跑 `target-schema-profile.sql`，确认 `orphanProperties=0`；
5. 基线文件修改与执行证据一并提交，作为 TD-005 门禁 1 "删除链"子门禁的 PASS 证据。

本方案获批并执行后，只关闭"4 条孤儿属性处置"这一项。TD-005 其他门禁（ADR-012 Accepted、Mapper 漂移修复、租户感知唯一约束、删除事务边界、JCS/hash、恶意导入、行业模板、发布回滚）仍按原计划推进。

## 10. 评审意见最终处置（2026-08-04）

### 10.1 评估结论

§9 的总体方向合理，但 O1、O2、O3、O5 的部分技术描述需要纠正。最终为：**采纳 4 项、采纳并修正 2 项、驳回 1 项，并补充 1 项快照保护**。

| 编号 | 处置 | 最终依据与落点 |
|---|---|---|
| O1 | 采纳并修正 | `product_commands*` 没有产品/模板标识列，不能执行原建议的直接 WHERE；预检和修复脚本改为经 `product_services` 检查三条命令链，并动态扫描全部直接标识列。 |
| O2 | 采纳并纠正理由 | rollback 同时锁定并检查 `product`；目的不是避免“再次产生孤儿”，而是保证恢复时父对象状态与原始快照一致。 |
| O3 | 采纳并修正 | §5.1 给出稳定主键匹配和 diff 命令；初始化文件是 COPY 数据段，不称为 INSERT，也不固化易漂移行号。 |
| O4 | 采纳 | §7.1 明确空库重建验收以前置基线修正和 Git diff 为条件。 |
| O5 | 驳回 | 固定 `tenant_id=1` 是本次已画像数据的安全边界；参数化会把未经溯源的其他租户数据纳入删除能力。其他租户必须单独画像和形成新处置清单。 |
| O6 | 采纳 | §3.1 增加可复现 `git show` 统计和裁剪 diff 事实。 |
| O7 | 采纳 | §3.2 解释 `product_template` 只承载模板标识。 |
| S1 | 补充采纳 | 删除前和回滚后校验四行完整 `row_to_json` 快照 MD5；任何字段或表列变化都会失败关闭，避免用旧快照覆盖已变化数据。 |
