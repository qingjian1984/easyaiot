## 1. 目标

实现告警正式 Schema 资源、来源 Inbox 仲裁、告警主记录/来源映射/动作历史/Outbox 的持久化端口、同事务编排和 Outbox Relay 纯合同。任务不装配 Kafka/MQTT listener/producer，不接旧来源，不开放 HTTP API，不启用 capability。

## 3. 实现切片

### B0：Schema 与纯裁决

- 来源事件 1 个 Schema、领域事件 6 个独立 Schema；生产资源只保留每事件正式文件，不复制评审聚合 Schema。
- validator/codec 严格校验当前主版本；未知可选字段允许，未知主版本稳定拒绝并进入隔离决策。
- 本地计算 `envelopeHash=sha256:<64 lowercase hex>`；消息自报 `payload.payloadHash` 只作为来源证据摘要。
- Inbox 仲裁：`PROCESS/DUPLICATE/QUARANTINE_HASH_CONFLICT/REJECT_UNKNOWN_MAJOR/REJECT_FINAL`。
- Outbox Relay 策略：claim、租约过期恢复、有界退避、PUBLISHED、DEAD_LETTER；所有时间与随机抖动从端口注入。

### B1：持久化与同事务编排

- JDBC 只访问 V011 九表；不在应用启动时建表。
- 来源处理方法必须由 Spring 事务代理进入；Inbox、mapping、record CAS、action log、Outbox、Inbox PROCESSED 同一事务。
- 无活动事务时 fail-closed；禁止 self-invocation 绕过事务。
- 事务提交前不向调用方返回可 ACK 结果。重复/隔离结果也必须先完成持久化裁决。
- Relay 只依赖 transport 端口和 fake；本任务不提供 Kafka/MQTT Bean、调度器或配置。

## 4. 必测场景

1. 7 个正式 Schema 的正例、逐字段缺失反例、UUID 小写、tenant/ID 字符串、offset 时间。
2. 当前主版本、未知主版本、未知可选字段和未来 additive 字段。
3. 同 messageId 同 envelopeHash 重放；异 hash critical 隔离且既有告警零变化。
4. 首次 SOURCE_RAISED 原子产生 Inbox、mapping、record、action、Outbox；任一步失败全部回滚。
5. 同周期并发首次发生只创建一个 alarmId；hash 碰撞时比较完整 cycle identity 并隔离。
6. SOURCE_RECOVERED、重复恢复、RECOVERED 后同 cycle raise 冲突。
7. expectedVersion CAS 冲突、跨租户/跨站点拒绝、同租户 FK。
8. EMERGENCY 忽略在应用与数据库两层拒绝；误报提议人与复核人分离。
9. Outbox 双 claim 互斥、租约未过期不可抢、过期恢复、broker 成功后 PUBLISHED。
10. retryable 有界退避、final/超限 DEAD_LETTER；transport/DLQ 失败不返回 ACK。
11. 日志、错误摘要和指标不包含 payload、凭据、手机号或媒体 URL。
12. 受影响模块编译及 P02-M2-01 状态机/Envelope 回归继续通过。

## 5. 完成定义

- 代码 diff 只在允许目录，未出现生产 transport、listener、scheduler、Controller、配置或旧链改动。
- Schema/fixture 合同与 Java 事件枚举一致；当前主版本 CI 样例通过，上一主版本在 v2 出现前记录为 `N/A - no previous major`，不得伪造。
- fake 仓储/transport 单元测试通过；JDBC 集成测试只有在 P02-M2-02A 临时库门禁另行解锁后执行。
- Maven 定向测试实际执行、0 跳过；受影响 Reactor 编译通过。
- Sol 独立复核事务代理入口、SQL 租户条件、CAS、hash 和 ACK 返回语义。
- 交付状态最多为 `Verified-Local / No Production Transport`。
