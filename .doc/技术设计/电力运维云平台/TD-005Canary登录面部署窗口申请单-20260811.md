# TD-005 Canary 登录面首次部署窗口申请单（2026-08-11）

> 双基线：平台功能计划 1.4.0 / EasyAIoT 项目开发宪法 1.5.0
> 依据：TD-005 1.0.39
> 状态：OPEN / 待 owner 独立批准
> 目标：仅以 full 档位构建并首次创建 `web-service`

## 1. 当前基线

- `iot-gateway`、`iot-system` 均 healthy，公共 `/api/v1/power/**` 路由已部署；
- 当前不存在 `web-service` 容器和 `web-service:latest` 镜像，8888 端口没有登录面；
- WEB Dockerfile 的 `VITE_GLOB_DEPLOY_PROFILE` 构建参数默认值为 `full`，并在构建时追加覆盖生产环境通用
  默认值；本窗口仍必须显式传入 `--build-arg VITE_GLOB_DEPLOY_PROFILE=full`；
- tenant 122、user 113、role 111 均满足只读基线，未过期 access token 数量为 0。

## 2. 唯一允许变更

仅允许从当前提交构建 `web-service:latest`，构建参数显式固定为 `full`；随后仅执行
`docker compose up -d --no-deps web-service` 首次创建 WEB 容器并等待 healthy。执行前冻结 gateway、system、
device、PostgreSQL、Kafka 的容器 ID和启动时间；执行后必须逐一证明未重建。

本窗口不允许用户登录，不允许输入、读取或保存密码，不允许创建、读取或刷新 token；不调用登录、权限、
电力或其他业务 API，不写 Canary 数据。

## 3. 明确禁止

- 不重建 `iot-gateway`、`iot-system`、`iot-device` 或其他容器；
- 不修改 template/binding API、Secret、角色、数据库、Topic、Nacos 或 capability；
- 不修改 WEB 源码或环境文件，不使用 mini/standard 构建结果；
- 不获取 token，不调用 `/api/v1/power/**`，不执行 Canary；
- 构建或健康验收失败时仅删除新建 `web-service` 容器和本窗口新建镜像，恢复“无 WEB”初始状态。

## 4. 验收

- 新容器 healthy，8888 端口仅提供静态登录面和既有 Nginx 代理；
- 镜像构建日志证明 `VITE_GLOB_DEPLOY_PROFILE=full`；
- gateway/system/device/PostgreSQL/Kafka 的容器 ID和启动时间保持不变；
- 未过期 token 仍为 0，role 111 权限与 tenant 122 空数据事实保持原值；
- 不通过 HTTP 探测登录或业务 API；容器健康仅使用 Compose/Docker healthcheck。

## 5. 后续独立认证窗口

WEB 部署成功不授权登录。后续必须由用户本人在浏览器输入 tenant=`测试租户`、username=`aoteman` 和现有
密码，设置 `rememberMe=false`；若启用验证码由用户本人完成。只允许一次正常登录及前端自动权限信息请求，
access token 有效期应为 1800 秒。密码和 token 不得写入仓库、文档、终端或普通日志；登录失败立即停止，
不得重试、重置密码或直读数据库密码摘要。
