# TD-006 附件：事件与 capability 合同

> 版本：0.1.1  
> 日期：2026-08-24  
> 状态：Freeze Candidate / Capacity Values OPEN  
> 双基线：平台功能计划 1.5.0、EasyAIoT 项目开发宪法 1.6.0

## 1. 事件命名裁决

平台功能计划 1.5.0 使用 `device.alarm.created.v1`。因此统一告警首次创建事件固定为 `device.alarm.created.v1`，不再同时发布历史同义事件。重复发生使用 `device.alarm.occurrence-recorded.v1`，避免消费者把 occurrence 当成新 alarmId。

领域事件集合：

- `device.alarm.created.v1`
- `device.alarm.occurrence-recorded.v1`
- `device.alarm.recovered.v1`
- `device.alarm.status-changed.v1`
- `device.alarm.escalated.v1`
- `device.alarm.suppression-decided.v1`

输入来源合同为内部 `device.alarm.source-event.v1`，`eventType` 只允许 `RAISED/RECOVERED`。Topic 名和 consumer group 在 transport 评审时冻结；业务 Schema 不绑定 broker 物理名称。

## 2. Envelope

所有事件包含：

| 字段 | 类型 | 规则 |
|---|---|---|
| `eventId` | UUID string | 全局唯一 |
| `eventVersion` | string | 当前为 `1.0` |
| `eventType` | string | 完整事件名称或来源动作 |
| `tenantId` | decimal string | 不接受 JSON number |
| `occurredAt` | ISO 8601 offset string | 来源发生时间 |
| `recordedAt` | ISO 8601 offset string | 平台记录时间 |
| `source` | string | 生产模块/适配器身份 |
| `correlationId` | string | 业务追踪；不得携带凭据 |
| `traceId` | string/null | 可选链路追踪 |
| `payload` | object | 按事件版本校验、限制大小 |

ID 在 JSON 中全部使用字符串，时间必须带 offset；消费者忽略未知可选字段，但拒绝未知主版本和缺失必填字段。

## 3. 来源事件必填事实

`payload` 至少包含 `sourceType/sourceId/cycleKey/sourceObjectId/siteId/deviceId/severity/occurredAt/payloadHash`，规则来源另含 `propertyCode/ruleId/ruleVersion/quality`。`messageId` 使用 envelope `eventId`；同 ID 同 hash 为重复，不同 hash 隔离。

`tenantId/siteId/deviceId` 必须由受认证入口与设备权威事实核对，不能只信任 VIDEO/AI 或请求正文。

## 4. 领域事件最小 payload

- created：`alarmId/status/severity/sourceType/sourceId/cycleKey/siteId/deviceId/propertyCode/ruleId/ruleVersion/firstOccurredAt/occurrenceCount`。
- occurrence-recorded：`alarmId/status/occurrenceCount/lastOccurredAt/sourceMessageId`。
- recovered：`alarmId/fromStatus/status/recoveredAt/version`。
- status-changed：`alarmId/action/fromStatus/status/operatorId/reasonCode/version`；敏感自由文本只放受控引用。
- escalated：`alarmId/status/fromLevel/toLevel/policyId/policyVersion/escalatedAt/version`。
- suppression-decided：`alarmId/status/decision/maintenanceContextId/policyId/policyVersion/reasonCode/decidedAt/version`；`decision` 只能为 `SUPPRESSED`、`NOT_SUPPRESSED` 或 `REEVALUATED`，维护上下文、策略和原因在不适用时可为空；通知域只执行该决策，不自行评估告警。

输出事件不携带通知接收人、手机号、媒体 URL、原始大 payload 或规则完整 DSL。

## 5. Schema 存放与兼容

设计候选 Schema 位于 `assets/td006-events/`。实现时必须按宪法复制/拆分到生产者 `iot-device-api/src/main/resources/events/{event-name}/v1.json`，并对当前和上一主版本执行生产者/消费者合同测试。

v1 允许新增可选字段；删除/改类型/收紧必填/改变枚举语义必须创建 v2，执行消费者先行、双发、对账、清零积压和回滚。

## 6. capability key 与 quota key

固定复用 ADR-011 已登记的：

- `power.alarm.core`
- `power.alarm.advanced`

core quota key 冻结为：

- `maxRulesPerTenant`
- `maxRulesPerSite`
- `maxActiveAlarmsPerTenant`
- `maxAlarmQueryDays`
- `maxRuleEvaluationsPerSecond`
- `maxAlarmConsumerConcurrency`

advanced quota key 冻结为：

- `maxCompositeRulesPerTenant`
- `maxRuleLeafConditions`（不得高于协议 16）
- `maxRulePoints`（不得高于协议 8）
- `maxRuleWindowSeconds`（不得高于协议 86400）
- `maxMaintenanceContextsPerTenant`

具体 standard/full 数值必须来自目标规模和压测。未冻结前不得修改正式 manifest，也不得以草案值做销售承诺。

## 7. capability 依赖候选

- core requires：`iot-device`、`iot-sink`、`postgresql`、`kafka`、`power.device.model`。
- advanced requires：core + `power.telemetry.history`。

依赖名必须与安装器/manifest 可识别的稳定标识对齐后才能写入正式 JSON；任何依赖缺失均 fail-closed，不返回伪成功。
