## 1. 结论

C1P 已交付可评审的 Proposed ADR-019，任务要求的字段权威矩阵、确定性 identity、THRESHOLD 周期状态机、DEVICE_EVENT allowlist Schema、来源 Outbox 主路径、失败/通知 owner 矩阵和 C1 四项 OPEN 映射均已写入同一决策文档。

本轮只接受“架构草案完整，可进入前置缺口收敛”的结论，不接受 ADR 转为 `Accepted`，也不关闭 C1。仓库核对命中任务单停工条件：阈值规则尚不可版本化、DEVICE_EVENT 没有产品批准 allowlist，且设备事件原始 identity/time/历史 route 和两类 source outbox 合同仍不完整。按宪法要求，这些缺口保持 OPEN，不能用当前状态、随机 ID、默认 tenant/site、`now` 或 latest OPEN 补齐。

## 4. 停工事实与前置拆分

| 停工条件/事实 | 当前证据结论 | 必须先完成的前置包 |
|---|---|---|
| 阈值无不可变 rule identity | `device_property_threshold` 只有可变当前行；无法重放历史语义 | `C1P-G1-THRESHOLD`：rule revision、活动周期状态和既有行迁移/回滚合同 |
| DEVICE_EVENT 无产品 allowlist | 仓库未发现批准条目，不能把全部 thing event 当告警 | `C1P-G1-EVENT`：产品负责人提供版本化 raised/recovered 清单和闭合语义 |
| DEVICE_EVENT 原始身份/时间不稳定 | 当前后端生成 ID、允许 `tenant=0/now` 回退 | `C1P-G1-ROUTE`：原始 message identity、occurredAt 与历史 assignment resolver 合同 |
| 来源与统一入口不能同事务 | 告警入口为 `REQUIRES_NEW`；旧阈值写后直发 Kafka | `C1P-G1-OUTBOX`：两类 source outbox、relay、ACK/offset 和终态合同 |
| THRESHOLD siteId 不在 Envelope | 可由不可变 release 设计解析，但现成 resolver/唯一性测试未冻结 | 合并进 `C1P-G1-ROUTE`，禁止当前 assignment fallback |

前置工作按 [C1P-G1 任务单](./P02-M2-02C1P-G1-来源合同缺口收敛任务单.md) 管理。该任务单当前只批准文档/合同收敛；任何 DDL、Java 实现、数据库执行或生产接线仍需新的独立白名单。
