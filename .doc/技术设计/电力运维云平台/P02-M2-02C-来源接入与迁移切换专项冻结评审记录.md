## 1. 评审结论

P02-M2-02C **不批准来源接入、双写、backfill、对账或切读实现**。仓库静态画像已经足以证明五类来源不是同一个技术边界，直接在旧链上增加 listener/producer 或双写会把现有身份缺口、跨库非原子写和旧通知副作用带入统一告警主事实。

本轮只做两项冻结：

1. 冻结来源、旧存储、旧查询和通知旁路的仓库现状及迁移分段；
2. 批准 [P02-M2-02C0 告警来源清单与迁移防漂移门禁](./P02-M2-02C0-告警来源清单与迁移防漂移门禁任务单.md)进入本地静态实现。

C0 只建立机器可读清单和静态校验，不修改业务代码。C1 来源适配、C2 算法来源 transport、C3 backfill/对账和 C4 API 切读全部保持 `CLOSED`，必须逐段复审和授权。

2026-08-25 的 [C1 前置门禁核对](./P02-M2-02C1P-C1来源接入前置门禁核对记录.md)已确认 M1 canonical telemetry identity/route 存在已提交合同基础，因此该单项改为 `CLOSED-CONTRACT / RUNTIME OPEN`；tenant/site/device 完整权威、阈值周期、设备事件映射及旧写/新入口原子或补偿仍 OPEN。C1 继续关闭，只批准 [C1P 架构决策任务](./P02-M2-02C1P-来源身份周期与补偿决策任务单.md)，不批准 adapter。

本评审只读取仓库文件，没有读取 `.env`、连接数据库、调用 Docker、执行 V011/U011、访问 broker 或统计生产调用量。

## 2. 仓库静态来源画像

| 来源 | 当前入口与旧事实 | 当前身份/时间语义 | 统一告警阻断项 | 裁决 |
|---|---|---|---|---|
| `THRESHOLD` | `PropertyUpstreamReportListener`、`SubPropertyUpstreamReportListener` 在遥测落储后 Feign 调用 `/device/threshold/evaluate`；`DeviceThresholdAlarmServiceImpl` 写 `device_threshold_alarm` 并直接向 `iot-alert-notification-send` 发通知消息 | 上游 `message.id` 未进入 `PropertyThresholdEvaluateParam`；请求只有设备、名称、属性；新告警 `tenantId=0`、`createTime=now`；恢复按“最新 OPEN”选择 | 无可重放 `messageId`、权威 tenant/site、事件时间/质量、稳定 `cycleIdentity`；旧落库与直发 Kafka 非 Outbox 原子链 | `NOT READY`；C1 前必须先冻结身份和原子性方案 |
| `DEVICE_EVENT` | `DeviceEventSubscriber` 从通用设备消息总线筛选 `thing.event.post`，`DeviceEventHandler` 写 `device_event` | `message.id` 仅用于日志；tenant 缺失回退 `0`；时间缺失回退 `now`；事件严重度从自由字段归一 | 没有 `RAISED/RECOVERED` 语义、规则身份、周期身份、告警映射和统一主事实；消费异常在 subscriber 捕获后不向上抛 | `NOT READY`；与 THRESHOLD 分属不同 adapter 合同 |
| `VIDEO` | 实时、抓拍、巡检算法通过 `algo_mqtt_bus.py` 发布 `mqtt/iot-alert-notification` / `mqtt/iot-snapshot-alert`；`iot-sink` 解析、补通知配置并写 VIDEO 库 `alert`；WEB/APP 读取 `/video/alert/**` | 每次发布重新生成 UUID `msgId`；tenant 默认环境值 `default`；`correlation_id` 可空；旧 `alert` 无 tenant/site/status/cycle 唯一约束 | 重试不能保持同一消息身份；MQTT、旧 Kafka hook、Kafka 失败直连落库等路径共存；来源事实、通知和媒体副作用耦合 | `NOT READY`；C2 前必须决定唯一 transport 和稳定来源身份 |
| `AI` | 本轮对 `AI/` 静态搜索未发现独立向统一告警或现有算法告警 Topic 发布的实现；现状更接近由 VIDEO/RUNTIME 承接检测输出 | 独立 `sourceId`、`cycleIdentity`、tenant/site 和 producer owner 均未形成仓库证据 | 不能把“算法模型输出”静默等同于独立告警来源，也不能与 VIDEO/RUNTIME 重复建告警 | `OPEN`；产品/架构责任人先确认是否保留独立 `AI` 来源 |
| `RUNTIME` | `Detech.cpp` 调用 `AlgoMqttBus::publishAlert`，进入与 VIDEO 相同两个 MQTT Topic，再由 `iot-sink` 写 VIDEO `alert` | 每次发布重新生成 UUID `msgId`；tenant 缺失回退 `default`；device/task/correlation 字段可空；等待 QoS 1 PUBACK | transport 关闭或全部 broker 失败时直接丢弃；没有可重放来源/周期身份和站点权威；与 VIDEO 可能重复表达同一检测 | `NOT READY`；必须与 VIDEO 共用一次去重/归属决策 |

另有 `/device/alarm` 边缘网关入口只记录日志并返回成功，未形成任何告警事实。该入口不得作为 C1/C2 的兼容适配点；后续只能显式废弃或改为严格合同入口，且必须在独立任务中处理。

## 3. 旧读写与通知边界

| 边界 | 当前事实 | 迁移要求 |
|---|---|---|
| 阈值旧写 | `device_threshold_alarm`，`OPEN/CLEARED`，`kafka_sent` | 保留为迁移期来源证据；禁止扩表伪装统一告警，禁止以 `kafka_sent` 替代 Outbox |
| 视频/算法旧写 | VIDEO 库 `alert`；Python 和 `iot-sink` 均存在落库路径 | 迁移前必须选定唯一 writer；旧表保留媒体/算法来源证据，不再承担统一主状态 |
| 设备事件旧写 | `device_event` | 仍是设备事件事实；只有满足已批准映射的事件才产生统一告警，不能全量事件即告警 |
| 阈值旧读 | WEB 调用 `/device/threshold/alarms/open` | 统一查询 API 验收并完成对账前不得切换；旧 API 至少保留一个发布版本 |
| 视频旧读 | WEB/APP 调用 `/video/alert/page`、count、statistics、delete/clear 和媒体查询 | 先拆分“告警主状态动作”与“媒体证据查询”；切读后禁止继续用 delete/clear 表达确认、恢复或关闭 |
| 通知旁路 | 阈值直发 `iot-alert-notification-send`；算法总线在 `iot-sink` 落库后再发同类通知 Topic | 通知只能消费已提交的统一领域 Outbox 事件；迁移观察期必须防止新旧链重复通知 |

## 4. 已冻结的迁移原则

1. `iot-device` 继续是统一告警主记录、状态机、动作历史和来源映射的唯一责任模块；VIDEO、RUNTIME、AI、iot-sink 只提供来源事实和证据定位。
2. 来源适配器必须保留稳定的 `sourceType + sourceId + cycleIdentity + sourceMessageId`。不得用接收时间、当前时间、数据库自增 ID 或重试时新 UUID 猜测周期。
3. tenant、site、device 必须由已冻结的设备/产品路由身份解析；`0`、`default` 或空值只能被隔离，不能成为统一告警事实。
4. `eventOccurredAt` 与 `observedAt` 分离；来源时间缺失或不可信时必须携带质量事实并按策略隔离/降级，不能静默写 `now`。
5. 双写期的“新写”只允许调用 P02-M2-02B 的事务应用入口；旧表不增加统一状态字段，新表不回写旧 `kafka_sent`。
6. 跨数据库链路不能宣称原子双写。必须以稳定来源事件 + Inbox 重放 + 对账收敛；源侧成功而统一侧失败时可发现、可补偿，不能返回伪成功。
7. 通知与媒体归档不参与告警主事务；统一事件提交后由 Outbox 驱动。观察期内同一告警周期只允许一个通知 owner。
8. backfill 只建立来源映射和历史/活动事实，不伪造确认、恢复、关闭、误报或通知送达事实。
9. 切读前先完成 API 兼容、消费者清单、全量与增量对账、观察窗口和回滚演练；切读与停旧写不是同一开关。
10. standard/full 共用合同和数据模型；mini 不得装配告警 adapter、consumer、relay、API、任务或迁移资产执行路径。

## 6. C1 前必须形成的身份决策表

| 来源 | `sourceId` 候选 | `cycleIdentity` 候选 | 当前缺口 |
|---|---|---|---|
| THRESHOLD | tenant/site/device/rule/property 的稳定规则实例标识 | 由规则状态机产生的显式周期 ID | 旧请求没有 rule version、messageId、site、event time/quality；不得用“最新 OPEN”代替 |
| DEVICE_EVENT | thing-model event identity + device + producer event instance | 只对已批准可恢复事件使用来源提供周期 ID | 事件是否告警、严重度、恢复事件和周期字段均未冻结 |
| VIDEO | task + device + detection source instance | producer 持久化并跨重试复用的检测周期 ID | correlation 可空且 msgId 每次重建；tenant/site 未绑定 |
| RUNTIME | workload/task + device + runtime event instance | RUNTIME 在首次检测时生成并跨重试复用 | 仅有临时 envelope msgId；失败直接丢弃 |
| AI | 待产品/架构确认 | 待产品/架构确认 | 未发现独立 producer，须避免与 VIDEO/RUNTIME 重复 |

以上均为候选，不是实现授权。最终字段来源、生命周期、最大长度、冲突处理和历史兼容规则必须在 C1/C2 任务单中逐项冻结。

## 7. 生产画像与切换 OPEN 项

- 旧三类事实表的行数、租户分布、站点映射缺失、`tenant_id=0/default`、活动周期、重复和孤儿数据数量；
- 五类来源的峰值/均值速率、重试率、乱序窗口、消息大小、积压、故障恢复目标和证据保留期；
- 物理 Topic、producer/consumer owner、消费组、分区键、acks、重试、DLQ、权限和监控；
- 旧 WEB、APP、内部 Feign、第三方集成和运维脚本的真实调用量与责任人；
- backfill 批次、节流、暂停/恢复、差异阈值、批准差异、观察窗口、发布版本、回滚和签字人；
- standard/full 目标规模及可重复压测证据。

这些输入缺失时，仓库设计可以继续细化，但不得声明生产容量、生产可用、迁移完成或允许切读。

## 8. 本轮仓库证据

- THRESHOLD：`PropertyThresholdEvaluateParam` 不含 `messageId/tenantId/siteId/eventOccurredAt/quality`；`DeviceThresholdAlarmServiceImpl` 存在 `tenantId(0L)`、`LocalDateTime.now()`、旧表插入和直发 Kafka；旧 Mapper 查询没有显式 tenant 条件。
- DEVICE_EVENT：`DeviceEventHandler` 将缺失 tenant 回退 `0L`、缺失时间回退本机当前时间；`DeviceEventSubscriber` 捕获处理异常后只记录日志。
- VIDEO/RUNTIME：两套 MQTT publisher 均向相同 Topic 发布，并在每次发布时生成新 UUID `msgId`；tenant 缺失回退 `default`。
- iot-sink：`IotAlgoBusMqttHandler` 接收算法 Topic、跨库补通知配置、调用 `AlertService` 写 VIDEO `alert`，随后直接向通知 Kafka Topic 转发；旧 `alert` 模型没有 tenant、site、统一状态或周期唯一键。
- 旧读：WEB/APP 仍读取 `/video/alert/**`，WEB 还读取 `/device/threshold/alarms/open`；VIDEO API 提供 delete/clear，不是统一告警动作语义。
- AI：对 `AI/` 的仓库静态搜索未发现直接告警 Topic publisher；该结论只是当前仓库快照，不代表生产部署事实。

上述证据关闭的是“仓库现状未知”问题，不关闭生产画像、物理 transport、来源身份或迁移切换门禁。
