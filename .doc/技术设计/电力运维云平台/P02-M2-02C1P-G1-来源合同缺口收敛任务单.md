## 1. 目标

关闭 ADR-019 接受前的四类合同输入缺口，不实现 adapter。输出必须能够让 Sol 判断 ADR-019 是否可转 Accepted；不能通过扩大白名单、假造产品事件或读取当前状态来制造“已关闭”结论。

## 2. 工作包

### G1-THRESHOLD：规则 revision 与周期状态

只形成候选设计：

- 不可变 rule revision 的字段、发布/退役/回滚、完整 predicate/severity/quality policy 快照；
- 每个规则实例单活动周期状态、CAS/version、firstSourceMessageId/cycleKey、乱序水位；
- 既有 `device_property_threshold` 当前行如何 expand、快照、歧义隔离和回滚；
- 既有 OPEN/CLEARED 数据如何只生成迁移清单而不按 latest OPEN 猜周期；
- 中文 DDL 注释和索引/唯一约束要求清单，但本包不编写或执行 SQL。

若无法无歧义迁移，明确规定历史只读、从新 revision 生效点启用 C1，不得伪造历史周期。

### G1-EVENT：产品 allowlist 输入

由产品负责人提供并签署：

- product/model scope；
- `alarmTypeKey`、raised/recovered eventIdentifier 与 payload predicate；
- 固定 severity、correlation/occurredAt JSON Pointer；
- lifecycle、mappingVersion、生效时间和回滚版本；
- 一次性事件闭合策略；无明确策略时保持 `REJECT`。

仓库执行者只提供空模板和校验规则，禁止猜测任何生产事件名称、等级或恢复关系。

### G1-ROUTE：历史 route 与原始事件身份

形成两个 resolver 合同：

1. THRESHOLD：`tenantId + siteCode + configVersion + deviceIdentification` 精确定位唯一已应用 immutable release，并返回 `siteId/product/workload/release/payloadSha256`；
2. DEVICE_EVENT：原始 message identity + 带 offset occurredAt + canonical product/device，经权威注册解析 tenant，再按 `[valid_from,valid_to)` 精确定位唯一历史 assignment。

必须列出零匹配、多匹配、边界时刻、迁站、跨租户、重复身份和同 ID 异 payload 的稳定错误与负向矩阵。不得把当前 assignment、接收时间、后端生成 ID 或 tenant=0 作为 fallback。

### G1-OUTBOX：来源 Outbox 合同

形成两类来源本地事务边界和候选 Schema 字段清单：

- THRESHOLD evaluator 状态 CAS + source-event outbox 同事务；
- DEVICE_EVENT legacy fact + source-event outbox 同事务；
- claim/lease、重试退避、终态隔离、message/hash 冲突、relay ACK/offset、对账游标；
- 与告警 Inbox、`AlarmSourceTransactionService.REQUIRES_NEW`、通知 owner XOR 的责任矩阵；
- 明确独立迁移编号需求，不修改 V011，不复用 `kafka_sent`。

本包不写 SQL、relay、scheduler、listener、Spring Bean 或 transport。

| 工作包 | 主要责任 | 允许仓库内完成 | 外部输入 |
|---|---|---|---|
| G1-THRESHOLD | Sol/产品规则 owner | 候选模型、迁移决策、测试矩阵 | 既有规则保留/启用策略确认 |

## 4. 可写白名单

仅允许新增/修改：

- 本任务单和对应评审/处置记录；
- ADR-019（仅根据已取得证据修订，保持 Proposed 直至所有门禁关闭）；
- 新增 C1P-G1 文档附件、空 allowlist 模板和纯 Markdown/JSON Schema 候选；
- PRD-02-SDD 进度与需求包导航。

禁止修改或新增生产代码、测试代码、SQL、runner、数据库 Schema、Spring 装配、Kafka/MQTT、配置、Compose、capability、WEB/APP 和 `.env`。若需要上述资产，必须先完成本任务评审，再建立独立实现任务和精确文件白名单。

## 5. 停工条件

- 产品负责人仍未提供 DEVICE_EVENT allowlist；该包保持 `WAITING-EXTERNAL`，不阻断其他三个文档包，但阻断 ADR Accepted；
- 上游协议无法证明原始 event identity 在重试中稳定，或无法提供可信 occurredAt；DEVICE_EVENT adapter 保持关闭；
- 既有阈值无法无歧义版本化；选择“历史只读、新版本起算”并交决策所有者，不做推测 backfill；
- 需要执行数据库、Docker、broker、读取凭据或改 V011/`REQUIRES_NEW`；立即停止并另行评审；
- ADR 编号或上游 Accepted 决策发生冲突；先做事实核对。

## 6. 验收标准

- 四工作包均有明确状态、责任人、证据和未关闭项；
- 每个 route/identity/rule/cycle/outbox 字段只有一个权威来源和稳定缺失错误；
- 版本、并发、重放、乱序、迁站、跨租户、hash 冲突和通知 XOR 均有正反矩阵；
- 不使用当前状态、默认值、随机数、接收时间、latest OPEN 或自由严重度；
- mini 无任何运行/迁移残留；
- 外部 allowlist 有明确签署证据，不以仓库示例代替；
- `git diff --check`、Markdown 链接检查通过，且工作区其他任务改动未被暂存；
- 验收结论只能是“ADR-019 具备接受条件”或“保持 Proposed + 列明 OPEN”，不自动授权 C1A/C1B/C1C。
