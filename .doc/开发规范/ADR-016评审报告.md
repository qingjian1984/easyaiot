> 双基线：[平台功能计划 1.5.0](../架构设计/平台功能计划.md) / [EasyAIoT 项目开发宪法 1.6.0](EasyAIoT项目开发宪法.md)

## 1. 总体结论

ADR-016 把已实施的「EDGE 退役 + RUNTIME 接管边缘执行 + 媒体统一归档」收敛为正式架构决策，方向正确、边界清晰、与代码事实高度一致。核心价值在于：

1. **明确了三条职责边界**——电力采集链（NODE→iot-sink collector→outbox→ACK）、视觉执行（RUNTIME）、控制面事实（iot-device）三分离，禁止在执行层复制 Poller、点表、ACK 状态机或告警处置状态。
2. **代码事实准确**——4 个被引用的 commit 全部核实无误（见 §2），决策与实现一致。
3. **回滚严格**——明确不得恢复 EDGE、不得把采集迁入 RUNTIME，回退路径仅限关闭视觉能力或回退 VIDEO/Python 执行器。

1.0.0 仍有 **4 项 MEDIUM、5 项 LOW** 缺口，均为「已声明归属但未定义契约/关系」类问题，无架构阻断。完成 §3 整改后建议转 Accepted。Accepted 只冻结事实归属与边界，不授权任何目标实例执行变更。

## 3. 发现与处置

| ID | 级别 | 发现 | 处置建议 |
|---|---|---|---|
| M-01 | MEDIUM | **来源记录与告警主记录的关联/同步契约未定义**。决策 4 声明「iot-device 维护统一告警事实和状态机；iot-sink 的来源记录仅作为证据」，但未定义 iot-sink 来源记录 → iot-device 主记录的同步通道、关联键、幂等与去重策略。决策 5 的 `alarmId/sourceType/sourceId` 只覆盖「告警↔媒体证据」关联，不覆盖「来源↔主记录」关联 | 引用 ADR-010 的 `alarm_record` 主记录归属；显式定义来源记录的表归属、关联键、是否异步投影、幂等样本键与 ADR-003 inbox 去重的关系 |
| M-02 | MEDIUM | **与 ADR-014（Outbox 事件 Transport 与消费者 Inbox）的关系未说明**。RUNTIME 算法告警经 MQTT 总线（`mqtt/iot-*`）进入 iot-sink `IotAlgoBusMqttHandler`，但是否纳入 ADR-014 的 inbox 幂等/ack 契约未明确。若纳入，则 RUNTIME 侧 publish 与 iot-sink 侧 inbox 的 QoS/重试/去重需对齐 ADR-014；若不纳入，需说明为何独立 | 显式声明 RUNTIME 算法消息是否走 ADR-014 的 inbox 消费契约；若是，引用 ADR-014 的 transport/幂等条款；若否，说明独立通道的可靠性与去重保证 |
| M-03 | MEDIUM | **RUNTIME 生命周期管理与 ADR-007 NODE 工作负载契约的关系未说明**。决策 3 称 RUNTIME「由 VIDEO/NODE 管理生命周期」，但 RUNTIME 是 C++ 二进制（executor=cpp），与 ADR-007 的容器化 collector 工作负载（Compose + 结构化白名单 + 状态机）是否复用同一契约未定义。部署、启停、健康检查、版本回滚是否纳入 NODE 工作负载状态机 | 说明 RUNTIME 是否作为 NODE 工作负载的一类纳入 ADR-007 契约；若是，标注执行器类型差异（原生进程 vs 容器）带来的状态机与回滚差异；若否，定义独立的受控生命周期契约 |
| M-04 | MEDIUM | **NFS/MinIO 不可用时的降级行为未定义**。决策 5 的归档链依赖 NFS 共享媒体根，验收项（第 56 行）提到「NFS/MinIO 不可用降级」，但决策正文未定义降级语义：告警图/录像是丢弃、本地暂存还是阻塞推理？这与硬件层「RUNTIME 不落本地业务盘」原则存在张力 | 明确 NFS 不可用时的分级降级：推理是否继续、告警是否带 `image_path` 但媒体延迟归档、录像是否丢片或回退本地暂存；定义媒体归档的最终一致性窗口与告警可追溯性保证 |
| L-01 | LOW | **「版本化消息」契约未定义**。决策 4 / Mermaid 图 BUS 节点称「版本化算法消息」，但「版本」指向（envelope `version`、`msgType`、任务 `configVersion`？）未说明。代码中 envelope 含 `version:"1.0"` 与 `msgType` | 引用或定义消息版本契约，或显式委托给后续 Spec/TD 冻结 |
| L-02 | LOW | **RUNTIME 心跳通道未提及**。代码事实为「告警走 MQTT、心跳仍走 HTTP→VIDEO」（双通道），ADR 只描述了算法结果通道，未提心跳，读者可能误以为 RUNTIME 全走 MQTT | 补一句说明心跳仍走 HTTP→VIDEO，与告警 MQTT 总线分离 |
| L-03 | LOW | **full 专属能力与功能计划 1.5.0 的交叉引用缺失**。决策 6 列出 full 独有「事故前后录像冻结、预置位联动、事故追忆、规模与保留期」，未引用功能计划 1.5.0 的对应能力条目 | 交叉引用功能计划 1.5.0 中这些能力的具体章节，便于追溯 |
| L-04 | LOW | **历史 ADR 中 EDGE 相关条款的统一回溯标注建议**。ADR-001 已回溯改写（第 29 行），但其他历史 ADR/基线文档若仍含 EDGE 为「当前模块」或「M2 评估」表述，应统一标注为历史审计语义 | 排查并统一标注历史文档中的 EDGE 引用（注：架构设计文档已于 2026-08-12 升级至 V9.18.0，完成 EDGE 退役对齐） |
| L-05 | LOW | **决策时序为事后追认**。代码于 2026-08-11 删除 EDGE，ADR 于 2026-08-12 撰写追认。ADR 正文诚实记录了代码事实，但理想流程是先 ADR 后实施。建议确认宪法对架构级变更的决策时序要求 | 建议未来模块退役/边界变更类重构，先写 ADR 或在实施同期补 ADR；本次既成事实建议补记例外说明 |

## 6. Accepted 后仍为 OPEN（门禁）

以下为实现/验证门禁，不影响 Accepted 状态，但未关闭前不得宣称对应能力已落地：

1. **CI/文档门禁**：现行模块清单不得出现 `EDGE/`、`TASK/` 实施路径；RUNTIME 至少完成 CMake 构建或最小推理样例。
2. **来源-主记录同步契约**（M-01）：iot-sink 来源记录 → iot-device `alarm_record` 的关联键、同步通道与幂等样本键冻结。
3. **RUNTIME 消息可靠性**（M-02）：RUNTIME 算法 MQTT 消息与 ADR-014 inbox 契约的对齐方式冻结。
4. **RUNTIME 生命周期契约**（M-03）：RUNTIME 与 ADR-007 NODE 工作负载状态机的关系冻结。
5. **NFS/MinIO 降级验收**（M-04）：NFS 不可用时的推理/告警/录像降级行为与可追溯性验证。
6. **采集验收**：24 小时断网补传、应用 ACK、重复消息幂等、容量保护、数据完整率。
7. **视频联动验收**：算法消息、统一告警映射、媒体归档、权限签发、NFS/MinIO 降级、证据可追溯。
8. **历史文档对齐**（L-04）：排查并标注历史 ADR/基线中残留的 EDGE「当前模块」表述。

> 注：架构设计系列文档已于 2026-08-12 升级至 V9.18.0，完成 EDGE 退役 + NFS + MQTT 总线对齐；本 ADR 与之保持一致。
