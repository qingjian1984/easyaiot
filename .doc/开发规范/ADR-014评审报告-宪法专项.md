# ADR-014 宪法专项评审报告

> 评审日期：2026-08-06
> 评审对象：[ADR-014：Outbox 事件 Transport 与消费者 Inbox 1.0.0（Proposed）](../架构决策/电力运维云平台/ADR-014-Outbox事件Transport与消费者Inbox.md)
> 评审基线：[EasyAIoT 项目开发宪法 1.5.0](EasyAIoT项目开发宪法.md) + [平台功能计划 1.4.0](../架构设计/平台功能计划.md)
> 评审方法：逐章核对宪法 MUST/SHOULD 条款，每条给出证据位置与 PASS / PARTIAL / MISSING / VIOLATION 判定；MUST 未满足即阻断 Proposed → Accepted

## 1. 结论

| 判定 | 数量 |
|---|---:|
| VIOLATION（违反 MUST） | 0 |
| MISSING（MUST 要求未覆盖） | 8 |
| PARTIAL（有候选但未冻结/未闭环） | 7 |
| PASS（有证据合规） | 10 |

**总体结论：不予转 Accepted。** ADR-014 方向（Kafka transport + 消费者 Inbox 幂等）与宪法 §5.4 语义一致，核心合规点（Outbox 一致性、双版本窗口、消费者幂等、DDL 中文注释）均有证据；但目标用户/角色、档位行为、事件 Envelope 冻结、Schema 入 API 模块、CI 合同门禁、配置清单、积压监控、文档同步 8 项 MUST 缺口未关闭。最小闭环见 §5。

### 3.3 §5.4 Kafka 与异步事件（核心章节，逐条 MUST）

| # | 宪法 MUST | 判定 | 证据与缺口 |
|---|---|---|---|
| K-07 | 事件必须有稳定名称、版本、事件 ID、发生时间、来源和关联业务 ID | **MISSING → M-03** | 4 个事件 V1 Schema 资产已存在（`assets/td005-migration/events/power-model-template-published-v1.json` 等）并通过 Ajv 校验，但 ADR-014 未引用该目录、未冻结 Envelope 公共字段清单（eventId/occurredAt/source/aggregateType/aggregateId/tenantId）；ADR 内只有 topic 名与 Key 格式 |
| K-08 | 消费者必须可幂等处理重复消息 | PASS | L42 消费者 Inbox `event_id` 全局唯一，同 ID 同 hash 返回 DUPLICATE，同 ID 异 hash 隔离 + critical |
| K-09 | 必须明确重试、死信、积压监控和失败恢复方式 | PARTIAL → P-02 / **MISSING → M-07** | 重试/死信：OUT-001～004 覆盖 retryable/final 错误与 lease 竞争，但重试次数上限、退避参数、DLQ topic 命名与保留期未冻结（P-02）。积压监控：L51 只有"10,000 条 backlog 恢复 ≤ 15 分钟"容量候选，无运行期积压指标、告警阈值与看板（M-07，同时违反 §8"关键业务必须记录成功率、失败率、耗时、队列积压指标"） |
| K-10 | 事件发布与数据库提交一致性（Outbox） | PASS | L40"数据库事务提交前不发送"；与 TD-005 migration §4.6 同事务 Outbox + 提交后异步投递一致 |
| K-11 | 事件 Schema 必须进入生产者 API 模块并版本化 | **MISSING → M-04** | Schema 当前仅是 `.doc` 评审资产，未落入 `iot-device-api`（或约定的生产者 API 模块）；ADR 未声明落模块路径与版本化方式 |
| K-12 | 破坏性升级：消费者先行、生产者双发、逐消费者切换、对账；旧版积压和死信清零后方可停止 | PASS | L44 + 回滚节 L57"消费者全部退出且旧积压/死信清零后才能停 V1 topic" |
| K-13 | CI 必须对当前和上一主版本运行生产者/消费者合同测试与 Schema 兼容检查 | **MISSING → M-05** | OUT-005～008 定义了 V1 additive、当前/上一主版本 fixture、双发对账、未知主版本隔离的验证意图，但未声明进入 CI 门禁；当前仓库无对应合同测试任务 |

2. 前端不消费 Kafka，架构边界合规（K-03）；
3. 混合版本/未知主版本兼容策略完整（K-05）；
4. 消费者 eventId 幂等 + 异 hash 隔离（K-08）；

8. 状态枚举 CHECK、TIMESTAMPTZ、tenant_id NOT NULL（K-15）；
9. 超时验证意图 OUT-009（K-19）；
10. 回滚节与 §5.4 对齐：停发布器保留 Outbox、不删已处理事件（L53-57）。

### 4.4 VIOLATION

无。

## 5. 最小闭环（Proposed → Accepted 前必须完成）

合并后 9 项：

1. **M-01 + M-02**：补"目标用户与角色"节与"档位行为"节（mini 关闭验证方式、standard/full 同 topic 同契约、capability manifest 联动关闭）；
2. **M-03**：ADR 引用 `assets/td005-migration/events/` 4 个 V1 Schema，冻结 Envelope 公共字段清单（eventId/eventType/occurredAt/source/aggregateType/aggregateId/tenantId/payload）；
3. **M-04**：声明事件 Schema 落入生产者 API 模块（建议 `iot-device-api`）的路径与版本化机制；
4. **M-05**：声明 CI 门禁：当前 + 上一主版本生产者/消费者合同测试与 Schema 兼容检查；
5. **M-06**：补配置清单表（topic、消费者组、max-payload-bytes、acks/retries、保留期、配额、载体与示例）；
6. **M-07**：定义积压/成功率/失败率/耗时指标、告警阈值与对账看板责任；
7. **M-08**：补文档同步计划（`.doc/架构设计/`、模块 README、部署文档、env.example）；
8. **P-02 + P-03 + P-04**：冻结重试/DLQ 参数；Inbox 落库绑定 ADR-013 runner；给出保留值与清理任务；
9. **P-05 + P-06**：核实并声明 Kafka 安全态势；处置双 UNIQUE 冗余（说明或收缩）。

P-01（压测）与 P-07（消费者实现）按既有门禁继续保留 OPEN，不阻断 Accepted 评审，但转 Accepted 后仍不得接生产传输（与 ADR-014 L61 自述一致）。
