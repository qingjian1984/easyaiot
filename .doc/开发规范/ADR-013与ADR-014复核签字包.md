## 4. 重点复核项（DBA / owner 视角）

1. **并发安全**：会话级 advisory lock（key 913005）+ `lock_timeout`/`statement_timeout` 有界值是否满足贵方运维规范；
   M15 `CREATE INDEX CONCURRENTLY` 非事务步骤与事务步骤分离的边界是否认可。
2. **完整性门**：history 表 `UNIQUE(migration_id)` + SHA-256 两阶段先校验后执行；篡改阻断路径（§3.3）是否符合预期。
3. **失败处置**：有界重试（3 次 / 1s / 4s）、FAILED 行脱敏摘要、强制备份（BACKUP_DIR）是否满足恢复要求。
4. **回滚语义**：U001 仅空表卸载、保留 `power_idempotency_record`（TD-004 资产）与 history——保留语义是否符合运维约定。
5. **幂等表契约**：`UNIQUE(tenant_id, principal_type, principal_id, operation, key_hash)` 跨副本首插争抢、
   409 `IDEMPOTENCY_KEY_REUSED`、24h 默认保留、8 项 CHECK——与 TD-004 §7.12 逐项一致（DDL 与已评审候选逐字一致）。
6. **权限最小化**：roles 候选中 `power_model_write` / `power_model_readonly` / `migration_executor` 的授权范围
   （含幂等表 DELETE 仅用于到期清理）是否认可。
7. **ADR-014 附带复核**：事件 Envelope 冻结、双 UNIQUE 收缩、Kafka PLAINTEXT 安全态势声明是否接受
   （消费者/Inbox 实现仍在 Accepted 之后）。

## 6. 签字后动作（OPEN 边界）

本签字关闭「DBA/代码 owner 复核签字」一项。转 Accepted 仍须关闭（不受本签字影响、机器无法代办）：

1. **standard 最低规格压测**（环境到位后按 ADR-013 资源预算执行，结果入证据表）；
2. **完整 12 表画像生产重跑**（`productionRerunRequired=true`，需生产窗口与审批，只读事务执行）。

三项全部关闭后：ADR-013 / ADR-014 转 Accepted → TD-005 冻结门禁推进
（事件消费者 / transport / Inbox 实现、CI 双主版本门禁接线）。
