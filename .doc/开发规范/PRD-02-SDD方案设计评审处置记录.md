## 1. 处置结论

评审报告作为历史输入保留，不回写其原始判断。本记录承载最终裁决和修订证据：报告列出的 12 项建议中，8 项直接采纳、4 项调整后采纳、0 项完全拒绝。

本轮只关闭已识别的产品/设计/候选合同一致性问题，不等于批准数据库迁移、生产接流、外部通知渠道、真实设备遥控、capability 启用或完整事故证据冻结。SPEC-005～008、TD-006～009 仍保持 `In Review`；所有未取得生产画像、容量证据、供应商联调、安全签字或迁移演练的门禁继续为 OPEN。

## 2. 报告口径校正

1. 报告摘要写“1 项 HIGH”，但正文列出 H-01、H-02 两项 HIGH。处置后 H-01 保持 HIGH；H-02 被确认是 PRD 图触发说明歧义，调整为 MEDIUM。
2. 报告摘要一处把 P02-M2-02 前置写成 H-02、M-01、M-03，而 §七/§八写成 H-01、M-03。最终裁决以 H-01、M-03 为 P02-M2-02 的本轮设计前置。
3. 复核发现报告未列出的更直接基线冲突：PRD-02 1.2.1 图中存在 `PROCESSING → CLOSED`，与 SPEC-005、TD-006 冻结矩阵和已验收纯状态机的“恢复后才能关闭”规则冲突。该边在 PRD-02 1.2.2 删除，固定为 `PROCESSING → RECOVERED → CLOSED`。

## 3. 逐项裁决

| 编号 | 裁决 | 最终落地 |
|---|---|---|
| H-01 | 调整后采纳 | 不采用仅比较 `ignored_from_status` 的弱方案；引入单调递增 `ignoreGeneration/ignore_generation`。到期任务携带代次快照，CAS 同时校验状态、版本、截止时间和同一次忽略代次。 |
| H-02 | 调整后采纳 | 保留 `IGNORED + ACK → ACKNOWLEDGED`；PRD 明确该边既可表示原状态恢复，也可表示人员主动确认并解除忽略。问题降为 MEDIUM，不否定 P02-M2-01。 |
| M-01 | 采纳 | TD-008 删除持久化 `PRECHECKED`，与 SPEC-007 的状态集合、待审批过期和批准执行窗口过期两条分支对齐。预检通过只写审计事实。 |
| M-02 | 采纳 | 新增正式领域事件 `device.alarm.suppression-decided.v1`；告警域负责抑制裁决，通知域只执行裁决。 |
| M-03 | 调整后采纳 | 选择方案 a：增加同租户同规则仅一个 `PUBLISHED` 的部分唯一索引；保留 content hash 唯一。回滚在同一事务中退役当前版本并重新激活历史版本，不复制相同内容行、不修改已发布内容。 |
| M-04 | 采纳 | 维护开始/结束不切割告警周期；结束重评估只能沿同 cycle occurrence 路径追加事实，显式恢复后才允许新周期。 |
| L-01 | 采纳 | TD-007 的旧 `raised` 命名统一为 `created`，与平台计划和告警事件合同一致。 |
| L-02 | 采纳 | 告警来源 Inbox 与通知/回调 Inbox 明确为不同模块、不同表和独立迁移资产，只通过版本化事件交接。 |
| L-03 | 采纳 | 通知提交状态与真实送达状态拆为正交属性；无回执时保持 `SUBMITTED + UNKNOWN`，禁止伪造 `DELIVERED`。 |
| L-04 | 调整后采纳 | 不把 `sequence_no` 直接拼入幂等键；冻结上游 `sourceEventId` 为唯一事实，`sourceSequence` 只参与同源排序。两次升级必须拥有不同事件 ID。 |
| L-05 | 采纳 | 事故在线窗口使用独立结果 `EVIDENCE_TELEMETRY_ASYNC_REQUIRED`；超限转异步并返回任务 ID，不复用通用遥测配额错误。 |
| L-06 | 采纳 | TD-008 数据模型补入 `control_risk_catalog_version`，申请固定引用已发布风险目录版本。 |
