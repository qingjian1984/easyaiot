## 一、复核方法

按宪法 16 章顺序，对每条 **MUST** 强度条款：
1. 在 TD-005 v0.1.0 中寻找直接对应文字；
2. 给出章节号和/或原文引用；
3. 判定为 `PASS`（有明确对应且合规）、`PARTIAL`（有提及但不充分）、`MISSING`（未对应或证据缺失）、`VIOLATION`（违反）；
4. MISSING/VIOLATION 必须进入本节末尾的"宪法 MUST 违反清单"。

对 SHOULD/MAY 仅做观察性标注，不阻塞。

## 七、复核与最终处置（2026-08-06）

### 7.1 评估结论

本报告对 v0.1.0 的主要缺口判断合理，但需要两项口径修正：

1. C-09 不构成宪法违反。宪法 §1.1 定义 MUST/SHOULD/MAY 的效力，没有要求每条设计语句重复英文强度标识；为减少歧义，目标设计增加全局强度约定，但不接受“未逐条标英文即违规”的结论。
2. C-06 所指 HTTP API 已由 TD-005 主设计定义，本子设计不新增路由；但版本/绑定事务确实增加 API 成本，因此部分采纳，在子设计中补充继承 API 的候选吞吐、P95/P99、大小和超时预算，最终仍需主 TD/接口合同同步。

专项评审只以宪法为核对对象是合理的评审切面，但项目实施结论仍必须同时遵循《平台功能计划》1.4.0。本次处置已复核 standard/full 单一实现、mini 排除和模块归属，没有形成双基线冲突。
