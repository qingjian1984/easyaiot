# ADR-001～016 基线对齐评估报告

> 评估日期：2026-08-12
> 评估基线：[EasyAIoT 项目开发宪法 1.6.0](EasyAIoT项目开发宪法.md) / [平台功能计划 1.5.0](../架构设计/平台功能计划.md) / 架构设计 V9.18.0
> 评估范围：ADR-001 ～ ADR-016（电力运维云平台架构决策系列）
> 评估维度：V9.18.0 架构一致性 · 基线版本时效 · 跨 ADR 契约边界
> 触发原因：2026-08-11 重构（删 EDGE / Ceph→NFS / 告警 HTTP→MQTT 总线）与最新基线发布后，需判定哪些 ADR 需更新

## 1. 评估结论

**无任何 ADR 的决策本体与最新基线冲突**——V9.18.0 重构在决策层的「硬残留」为零。问题集中在两类：

1. **基线版本号过时**（13 份 ADR 头部仍引用 1.4.0/1.5.0，需机械升级到 1.5.0/1.6.0）
2. **个别契约留白**（ADR-010 / ADR-014 / ADR-016 构成「告警链路契约三角」，需协同补齐）

| 类别 | 数量 | ADR |
|---|---|---|
| 🔴 需实质性更新（决策内容要改） | 2 | ADR-010、ADR-014 |
| 🟡 已在评审跟踪（待 1.1.0） | 1 | ADR-016（M-01～M-04，见 [ADR-016评审报告](ADR-016评审报告.md)） |
| 🟠 需轻量回溯注记 | 2 | ADR-001（EDGE 叙事脚注）、ADR-002（`EDGE_DELIVERY` 命名注记） |
| ⚪ 仅基线版本号升级 | 13 | ADR-001~004、006~011、013~015（与上重叠，机械低风险） |
| ⚪ 无需更新 | 2 | ADR-005（Superseded）、ADR-012（纯数据模型，与重构正交） |

## 4. 需实质性更新（告警链路契约三角）

### 4.1 ADR-010（统一告警模型迁移）

- **问题**：决策正文只描述了 `AlarmRaised`/`AlarmRecovered` 事件契约，**完全未描述来源事件的物理接入通道**。V9.18.0 已把 AI/RUNTIME 告警上行从 HTTP `AlarmCallback` 切换为 MQTT 算法总线（`mqtt/iot-*` → iot-sink `IotAlgoBusMqttHandler`），ADR-010 停留在旧链路认知。
- **需补**：
  1. 来源事件接入通道段（MQTT 总线三对 topic + 心跳 HTTP→VIDEO + `AlarmCallback` 废弃）；
  2. 告警/录像媒体 NFS→MinIO 归档链路；
  3. 迁移节补 HTTP→MQTT 的 `sourceType` 映射；
  4. 关联 ADR-016。

### 4.2 ADR-014（Outbox 事件 Transport 与消费者 Inbox）

- **问题**：ADR-014 冻结的是 `power-model-release` 事件（Kafka transport + inbox），候选方案 B（MQTT）已被否决。但 V9.18.0 下 RUNTIME 算法告警走独立 MQTT 总线，**不在 ADR-014 的 inbox 幂等契约覆盖内**——边界留白。对应 ADR-016 评审 **M-02**。
- **需补**：
  1. 声明作用域边界（本契约仅覆盖 Kafka power-model 事件）；
  2. RUNTIME 算法 MQTT 消息的可靠性/去重归属——与 ADR-016 1.1.0 协同关闭。

### 4.3 ADR-016（已在评审跟踪）

按 [ADR-016评审报告](ADR-016评审报告.md) §3 处置（版本 1.1.0）：M-01 来源→主记录同步契约、M-02 与 ADR-014 关系、M-03 与 ADR-007 NODE 契约关系、M-04 NFS 降级。无架构阻断，不阻塞 M1。

> ⚠️ **ADR-010 / ADR-014 / ADR-016 三者契约留白需协同补齐**，不应各自独立修改。建议作为一次专注的「告警链路契约三角」更新。

## 5. 需轻量回溯注记

- **ADR-001**：L29 已回溯「EDGE 按 ADR-016 退役」；L13「EDGE 当前定位为轻量算法运行时」属现状误述，建议改为「EDGE 已按 ADR-016 退役（原定位为轻量算法运行时）」；L37/43 为被否决方案历史叙事，可保留。
- **ADR-002**：`EDGE_DELIVERY` 为 gap stage 命名常量（与 ADR-003 `CENTER_PROJECTION` 配对），与已退役的 EDGE 模块无关，建议补一句说明避免歧义。

## 7. 评估边界与后续建议

### 7.1 评估边界
本次评估主要覆盖 **V9.18.0 架构一致性 + 基线版本时效**两个维度。**未逐条核对宪法 1.6.0 相对旧版本的每个新增/修改条款**对 ADR 的潜在影响（需版本 diff，成本高）。结论「无 ADR 决策本体与基线冲突」基于 ADR 决策与现状的一致性核对，而非条款级合规审计。

### 7.2 后续建议
1. **本轮处置**：批量基线版本号升级（13 份，低风险）+ ADR-001/002 轻量注记。
2. **单独安排**：ADR-010 / ADR-014 / ADR-016「告警链路契约三角」协同更新（涉及契约决策，需一次专注处理）。
3. **可选**：如需深度宪法合规复核，建议单独做一轮「宪法 1.6.0 专项评审」（类似历史上的宪法专项评审报告）。
