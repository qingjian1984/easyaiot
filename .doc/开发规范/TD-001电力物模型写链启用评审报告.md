## 1. 结论

代码与部署资产已具备进入受控灰度窗口的前置条件，但本报告不构成实际环境启用授权。当前仓库和运行
环境继续保持默认关闭。实际启用必须由 owner 独立批准，并提供密钥注入、Kafka 可达、消费者健康、
Outbox/DLQ 初始零积压和回滚责任人证据。

## 2. 冻结的配置事实

| 事实 | 环境变量 | 安全默认 |
|---|---|---|
| 绑定写 API | `EASYAIOT_POWER_MODEL_BINDING_APPLY_API_ENABLED` | `false` |
| 第四协调端口 | `EASYAIOT_POWER_MODEL_COLLECTOR_RELEASE_PORT_ENABLED` | `false` |
| Outbox/Kafka 事件链 | `POWER_MODEL_EVENTS_ENABLED` | `false` |
| 幂等 HMAC secret | `EASYAIOT_POWER_MODEL_IDEMPOTENCY_HMAC_SECRET` | 空；API 开启时启动失败 |

启动硬门禁：任一激活仅允许 standard/full 且 `power.device.model` capability enabled；事件链开启必须先
有第四端口；API 开启必须同时具备事件链、第四端口和不少于 32 UTF-8 字节的 secret。mini 或配置漂移
直接终止启动，不创建伪支持入口。

## 3. 灰度与回滚顺序

1. 保持 API=false，仅开启第四端口，确认应用健康。
2. 开启事件链，确认四处理器注册、Kafka 可达、Outbox/DLQ 初始为 0。
3. 注入运行 secret 后开启 API，执行单租户单 workload canary。
4. 验证 PUBLISHED、ACTIVE 投影、Inbox PROCESSED、协调审计和业务计数。

回滚必须先关闭 API；等待 PENDING/PUBLISHING Outbox 排空后关闭事件链，最后关闭第四端口。禁止先关
消费者导致已提交 Outbox 滞留。
