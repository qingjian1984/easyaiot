## 1. 目的

在现有 ProductProperties、ProductEvents、ProductServices 和命令模型上，定义可版本化、可继承、可导入、可校验的电力行业模板。

## 2. 设计边界

- 复用 `iot-device` 的产品和物模型能力。
- 本 Spec 不创建独立物模型服务。
- 模板是产品创建和升级的输入，不成为运行时遥测的第二套事实来源。
- 厂家模板通过标准模板派生，不直接修改系统标准模板。
- 模板能力仅在 standard/full 启用，两档复用同一模板、SemVer、导入校验和产品实例化实现；full 可增加模板包和规模配额，但不得复制模板服务。
- mini 不初始化电力模板、不开放导入发布 API，也不创建空壳电力产品。

## 3. 模型组成

### 3.1 属性

每个属性 MUST 包含：

| 字段 | 说明 |
|---|---|
| `propertyCode` | 稳定标识，符合 SPEC-001 |
| `propertyName` | 显示名称 |
| `dataType` | BOOL、INT、UINT、FLOAT、DOUBLE、STRING、ENUM、BITMAP |
| `accessMode` | R、W、RW |
| `unit` | 标准单位代码 |
| `precision` | 小数精度 |
| `min/max` | 合法值范围，可为空 |
| `enum/bitmap` | 枚举或位定义 |
| `semanticType` | 遥测、遥信、累计量、设定值、状态等语义 |
| `sampleHint` | 建议采样周期和变化上报策略 |
| `required` | 模板实例化时是否必须绑定 |

运行数据额外携带质量码和时间，不在属性定义中保存实时值。

- `FLOAT/DOUBLE` 只描述设备源值或协议解码宽度，不授权业务层使用二进制浮点保存事实。数值属性 MUST 定义 `precision`；归一化后按该精度和模板声明的舍入模式转换为规范十进制表示，默认舍入模式为 `HALF_UP`。
- 累计量、计量和费用上游属性 MUST 使用 SPEC-004 的十进制字符串编码；其他数值在兼容期可读取 JSON number，但服务端进入事实存储前必须转为十进制值。`precision` 是允许的小数位和校验/规范化规则，不改变 FLOAT/DOUBLE 的源字节宽度。

### 3.2 事件

事件 MUST 定义事件编码、名称、默认等级、输入参数、是否需要确认及推荐告警策略。设备主动事件与平台规则告警 MUST 使用不同来源字段，但可进入统一告警中心。

### 3.3 服务

服务 MUST 定义服务编码、风险等级、输入、输出、超时和幂等语义。分合闸类服务 MUST 标记为 `HIGH_RISK`，并强制进入安全遥控流程。

## 4. 标准模板目录

首期 MUST 提供：

| 模板 | 核心属性示例 | 核心事件/服务示例 |
|---|---|---|
| 高压柜 | 三相电压/电流、频率、功率、开关状态 | 跳闸、保护动作；分/合闸 |
| 综保装置 | 保护定值摘要、告警字、动作状态 | 保护动作、装置异常 |
| 变压器 | 三相绕组温度、负荷率、风机状态 | 超温、风机故障；风机控制 |
| 直流屏 | 母线电压、电池电压、充放电状态 | 电池故障、绝缘异常 |
| 低压柜 | 电压、电流、功率、开关状态 | 越限、跳闸；分/合闸 |
| 电容柜 | 投切状态、柜温、功率因数 | 过温、功率因数异常；投切 |
| 电表 | 正反向有功、无功、需量、功率因数 | 表计异常 |
| 电流互感器 | 变比、一次/二次额定电流、相别、状态 | 断线、过流、变比异常 |
| 电压互感器 | 变比、一次/二次额定电压、相别、状态 | 断线、失压、变比异常 |
| 环境监测 | 温湿度、SF6、烟雾、水位、入侵 | 环境越限、烟雾、水浸、入侵 |

互感器模板为 M1 SHOULD 项：标准点位可随首批模板交付；若排期裁剪，必须保留独立模板类型和变比字段契约，不得把互感器参数硬编码在电表模板中。完整点位字典在 Technical Design 阶段以版本化 JSON/Excel 资产维护。

## 5. 单位与语义

- 单位 MUST 使用平台统一字典，例如 V、A、kW、kWh、Hz、℃、%、ppm。
- 累计电量 MUST 标识是否可回绕、倍率和方向。
- 开关状态 MUST 使用统一枚举，不以厂家原始值直接暴露给业务层。
- 三相数据 SHOULD 使用一致后缀 `-a`、`-b`、`-c`。
- 三相交流属性 MUST 使用 `-a/-b/-c`；单相设备只使用实际相别后缀，直流、总量、线电压和无相别语义按标准字典编码，不强行添加三相后缀。任何例外必须由模板 schema 校验，而不是厂家自由命名。
- 厂家私有属性 MUST 使用 `x-vendor-` 前缀或明确命名空间。

## 6. 模板版本

```text
DRAFT → PUBLISHED → DEPRECATED → RETIRED
```

- 发布版本不可原地修改。
- 新版本 MUST 记录基线版本和差异。
- 已绑定产品默认保持原版本，升级需预览影响并确认。
- 厂家模板升级标准基线时 MUST 执行三方差异：旧标准基线、厂家当前版本、新标准基线。无冲突的兼容新增可自动进入候选草稿；冲突项必须由用户逐项选择，不得用新标准静默覆盖厂家扩展。
- 回滚 MUST 恢复产品升级前的精确模板版本和绑定快照；按新版本产生的遥测不删除，继续以模板/配置版本解释。
- `DEPRECATED` 由模板管理员对仍可运行但不建议新用的已发布版本手动设置；默认禁止新建产品绑定，但现有产品可继续运行和升级。`RETIRED` 仅在无新增绑定、替代版本与迁移说明已发布且完成影响确认后设置；已绑定产品不强制自动迁移，运行时仍可解释历史版本。
- 删除属性属于破坏性变化，必须先废弃并经过兼容期。
- 属性更名 SHOULD 保持原 `propertyCode`，只修改显示名称；语义改变必须创建新属性。

## 7. 导入与校验

- 支持 JSON 和 Excel 模板导入。
- 导入流程为上传、解析、校验、差异预览、确认、发布。
- 校验 MUST 检查编码、重复、数据类型、单位、范围、枚举、服务参数和风险标签。
- 错误 MUST 定位到工作表、行、列或 JSON Path。
- 导入不得自动覆盖已发布模板。

### 7.1 产品实例化校验

- 从模板创建产品或将模板版本应用到产品时，系统 MUST 校验全部 `required=true` 属性已实例化且定义完整。
- 必选属性缺失、类型不兼容、单位不兼容或重复绑定时 MUST 阻止发布，并返回模板属性、产品属性和错误原因。
- 非必选属性 MAY 跳过，但差异预览必须展示。
- 已发布产品升级模板时同样执行校验，不得因旧版本已运行而绕过。
- 校验失败 MUST 返回可机器处理的错误数组，至少包含 `code`、`templateVersion`、`propertyCode/path`、`productPropertyCode`、`message` 和 `severity`；一次返回全部可判定错误。批量导入还必须提供工作表/行/列并支持下载，不得只返回首个字符串错误。

## 8. 需求清单

| ID | 规范要求 |
|---|---|
| TM-001 | 标准模板 MUST 版本化且不可原地修改已发布版本 |
| TM-002 | 厂家模板 MUST 记录继承的标准模板版本 |
| TM-003 | 属性 MUST 具有稳定 propertyCode 和明确语义 |
| TM-004 | 高风险服务 MUST 标记风险等级并进入审批控制 |
| TM-005 | 模板导入 MUST 先校验和预览差异 |
| TM-006 | 产品升级模板 MUST 展示设备与点位影响范围 |
| TM-007 | 运行时值 MUST 继续由设备影子/时序系统管理 |
| TM-008 | 模板访问 MUST 执行租户权限，系统模板只读 |
| TM-009 | 产品实例化或模板升级 MUST 校验全部必选属性，校验失败不得发布 |
| TM-010 | 厂家模板升级标准基线 MUST 进行三方差异并人工处理冲突 |
| TM-011 | 模板回滚 MUST 恢复精确版本和绑定快照，不得删除新版本期间的数据 |
| TM-012 | 数值属性 MUST 定义 precision，累计量/计量值 MUST 使用规范十进制表示 |
| TM-013 | DEPRECATED/RETIRED MUST 遵守新增绑定、存量运行和迁移影响规则 |
| TM-014 | 实例化/升级校验 MUST 返回稳定错误码和完整错误数组 |

## 9. 验收场景

### 场景 A：创建厂家模板

```gherkin
Given 系统已发布标准变压器模板 1.0.0
When 实施工程师创建厂家模板并增加私有油温点位
Then 厂家模板记录基线版本 1.0.0
And 私有点位通过命名空间校验
And 标准模板保持不变
```

### 场景 B：破坏性升级

```gherkin
Given 产品正在使用模板 1.0.0 的 propertyCode=current-a
When 新模板删除 current-a
Then 系统将其识别为破坏性变化
And 阻止直接覆盖产品
And 展示受影响设备、采集点和看板绑定
```

### 场景 C：高风险服务

```gherkin
Given 模板包含 close-switch 服务
When 模板发布校验执行
Then 服务必须具有 HIGH_RISK 标识
And 缺少风险标识时发布失败
```

### 场景 D：导入错误

```gherkin
Given Excel 中存在重复 propertyCode 和非法单位
When 用户执行模板导入
Then 系统不写入发布版本
And 返回可下载的逐行错误清单
```

### 场景 E：必选属性缺失

```gherkin
Given 变压器模板将 winding-temp-a 标记为 required=true
When 用户从模板创建产品但未实例化 winding-temp-a
Then 产品发布被拒绝
And 错误明确指出缺失的模板版本和 propertyCode
```

### 场景 F：厂家模板基线升级冲突

```gherkin
Given 厂家模板 1.2.0 继承标准模板 1.0.0 并修改了 temperature 的范围
And 标准模板 1.1.0 也修改了 temperature 的范围
When 用户发起厂家模板基线升级
Then 系统展示旧标准、厂家当前和新标准三方差异
And 在用户处理冲突前不得发布新厂家模板
And 其他租户不可读取该厂家私有模板
```

### 场景 G：废弃模板与精度校验

```gherkin
Given 模板 1.0.0 已标记 DEPRECATED 且存在使用它的运行设备
When 用户创建新产品并选择模板 1.0.0
Then 系统拒绝新增绑定并提示替代版本
And 现有设备继续运行且历史数据可解释
Given 累计量属性使用 DOUBLE 但未定义 precision
When 用户发布模板
Then 发布被拒绝并返回稳定错误码和 propertyCode
```

## 10. 兼容要求

- 现有物模型 API 和数据库模型优先扩展，不破坏旧产品读取。
- 旧产品未绑定行业模板时继续工作，但标记为“自定义模型”。
- 前端对未知扩展字段 MUST 忽略，不应渲染失败。

## 11. 已冻结决策

- 对外版本采用语义版本 `MAJOR.MINOR.PATCH`；数据库仍可使用数值主键，二者不得互相替代。
- M1 不强制采用 IEC 61850 命名，预留可选 `standardMappings` 扩展字段保存标准、版本和外部语义标识。
- M1 提供统一导入入口，内部按“物模型模板”和“RTU 点表绑定”两个工作表/数据段校验；两类数据分别版本化、同一发布单原子校验，禁止将寄存器地址写入标准物模型模板。
- capability 只决定电力模板能力是否启用及配额，不改变模板 ID、属性/事件/服务编码、SemVer 或必选属性校验语义。

模板 JSON Schema、Excel 列定义和标准点位全集在 Technical Design 阶段产出；它们必须遵守本 Spec，不能改变上述语义决策。

版本化模板资产的仓库目标目录固定为 `.doc/规格/电力运维云平台/assets/model-templates/`；Technical Design 冻结 JSON Schema、Excel 模板、点位字典及内容摘要，发布包必须记录对应 Git commit 和文件哈希。
