## 2. 已冻结合同

### 2.1 主状态与等级

- 状态：`ACTIVE/ACKNOWLEDGED/PROCESSING/RECOVERED/CLOSED/IGNORED/FALSE_ALARM`。
- 等级：`INFO/NORMAL/IMPORTANT/EMERGENCY`。
- `ESCALATED` 不是主状态；升级动作不改变主状态。
- `FALSE_ALARM`、`CLOSED` 为终态。

### 2.2 领域动作

`SOURCE_RAISED`、`SOURCE_RECOVERED`、`ACK`、`START_PROCESSING`、`CLOSE`、`IGNORE`、`IGNORE_EXPIRED`、`UNIGNORE`、`PROPOSE_FALSE_ALARM`、`APPROVE_FALSE_ALARM`、`REJECT_FALSE_ALARM`、`ESCALATE`。

完整允许/拒绝行为以 [状态转换与并发矩阵](../../技术设计/电力运维云平台/TD-006-状态转换与并发矩阵.md)为准。

状态机必须是无 Spring、无数据库、无系统时钟读取的确定性函数；幂等键、乐观锁和 Inbox 重复裁决由后续应用层负责。因而：

- `ACKNOWLEDGED + ACK` 在纯状态机中拒绝；同幂等请求应在进入状态机前被重放。
- `RECOVERED + SOURCE_RECOVERED` 可以返回明确 no-op，供不同但语义重复的恢复事件安全收敛。
- `SOURCE_RAISED` 从 RECOVERED 返回 `ALARM_SOURCE_CYCLE_CONFLICT`，不能重开旧周期。
- 误报批准/拒绝必须显式输入“存在待复核”和“复核人独立”事实。

### 2.3 事件合同

领域事件固定为 `device.alarm.created.v1`、`device.alarm.occurrence-recorded.v1`、`device.alarm.recovered.v1`、`device.alarm.status-changed.v1`、`device.alarm.escalated.v1` 和 `device.alarm.suppression-decided.v1`。最后一个事件只承载告警域已经作出的 `SUPPRESSED/NOT_SUPPRESSED/REEVALUATED` 决策，通知域不得自行评估告警。

来源 Schema 中 `RAISED/RECOVERED` 是内部来源动作，不是对外领域事件名称，不构成 `raised.v1` 同义事件。

Envelope 必须验证：小写规范 UUID、`eventVersion=1.0`、正整数 tenantId 字符串、带 offset 的时间、固定 source `iot-device`、非空 correlationId、已知事件类型和 payload 防御性复制。

## 4. 验收门禁

- 状态矩阵的允许、拒绝、终态、紧急忽略和误报分权均有参数化测试。
- 所有非法转换返回稳定告警错误码，不泄漏空指针或随意异常文本。
- Event Envelope 覆盖 UUID、版本、tenant、offset time、事件类型、source、payload 防御复制。
- 无 Spring Context 即可测试；不得新增依赖。
- 执行受影响模块编译和目标 JUnit；必须显式 `-Dmaven.test.skip=false`。
- Diff 只包含冻结目录和测试，不夹带旧链重构。
