## 1. 评审结论

SPEC-005～008 已覆盖 PRD-02 的告警、通知、安全遥控和事故证据边界，职责分配、分档原则、安全默认值和迁移方向未发现与双基线冲突，可进入 Technical Design 草拟。

本结论**不等于 Approved / Frozen，也不授权生产代码、数据库迁移或 capability 启用**。冻结前仍须关闭本文和各 Spec 中列出的 OPEN 门禁；其中高风险遥控、外部通知渠道、完整事故冻结继续 fail-closed。

## 3. 跨 Spec 冻结决策

1. **单一告警事实**：处置状态只存在于 `iot-device.alarm_record`；`device_threshold_alarm`、`iot-sink.alert`、`iot-message.alert`、VIDEO/AI 告警均为迁移来源或不可变证据。
2. **升级正交**：升级使用 `escalationLevel` 与追加事件，不进入主状态枚举。兼容 API 如保留 `ESCALATED`，只能由主状态和升级级别派生。
3. **事务边界**：告警状态变化、通知意图、证据意图和控制状态变化使用本地事务 + Outbox；跨服务消费者各自使用独立 Inbox，不能复用 power-model Inbox 冒充告警 Inbox。告警首次创建事件按平台功能计划统一命名为 `device.alarm.created.v1`，重复发生使用 `occurrence-recorded.v1`。
4. **维护模式**：规则和告警事实持续产生，只抑制被策略选中的通知；结束时不得补发已过期通知。
5. **安全遥控**：所有受控服务/属性最终经 `/api/v1/device/control/**`；高风险不能豁免操作票、独立审批、联锁、二次确认、回执和审计。
6. **证据失败隔离**：媒体、归档和报告失败不得回滚告警；以缺口码、重试和追加审计表达。
7. **档位一致性**：standard/full 共用模型、API 和安全语义；full 只增加高级能力或配额。mini 不注册电力菜单、API、消费者、任务和初始化数据。

## 4. ADR-010 1.1.0 专项复核

ADR-010 1.1.0 将 `ESCALATED` 从告警主状态移为正交级别/事件，并明确维护模式保留规则评估与告警事实。该修订消除了“升级后是否还能确认/恢复”的状态组合歧义，也避免维护结束时制造新告警周期，方向与 PRD-02 1.2.1 一致。

评审结论：**Accepted for downstream design**。最终实现仍必须由告警 TD 冻结持久化字段、事件 Schema、兼容派生和迁移对账；本记录不单独批准 DDL。

## 7. 冻结与开发准入

每份 Spec 只有同时满足以下条件才可改为 `Approved / Frozen`：

- 关联 TD 通过接口、数据、状态机、安全、幂等、容量、迁移和回滚评审；
- 所有 MUST/ MUST NOT 都有测试或验收映射；
- DDL 含中文注释、升级/回滚脚本、画像与演练证据；
- capability manifest 的依赖、配额、启停和 mini 无残留检查已冻结；
- 跨服务事件当前/上一主版本合同、Inbox 冲突和死信路径可验证；
- 高风险功能的现场/安全责任人批准项已关闭，或明确从当前交付范围移除且保持关闭。

在此之前，仅允许无生产副作用的设计验证、测试夹具和隔离 Spike；不得以草案为依据接入真实控制设备、执行生产 DDL或开启外部通知/完整证据冻结。
