## 一、4A 架构总览

### 1.1 什么是 4A 架构

4A 是企业架构（Enterprise Architecture）的经典框架，将架构拆分为四个正交视角：

| 架构层 | 英文 | 核心问题 |
|--------|------|----------|
| **BA — 业务架构** | Business Architecture | 平台为谁解决什么问题？业务流程如何运转？ |
| **AA — 应用架构** | Application Architecture | 软件如何拆分？模块如何协作？接口如何定义？ |
| **DA — 数据架构** | Data Architecture | 数据如何存储、流转、治理？ |
| **TA — 技术架构** | Technology Architecture | 使用什么技术栈？如何部署？如何运维？ |

## 二、业务架构 (Business Architecture)

### 2.1 平台定位与愿景

**EasyAIoT** = AI + IoT 深度融合的**云边端一体化智能算法应用平台**。

核心价值主张：**让 AI 零门槛触达全球** —— 通过三档部署规格（mini/standard/full），同一套代码可运行于 4GB 边缘盒子到 20GB+ 企业级一体机。

### 2.3 核心业务流程

#### 2.3.1 AI 全链路闭环

```
数据采集 → 数据标注 → 模型训练 → 模型导出 → 模型部署 → 实时推理 → 告警通知
   │          │          │          │          │          │          │
   ▼          ▼          ▼          ▼          ▼          ▼          ▼
iot-dataset  SAM自动    AI train   AI export  AI deploy  VIDEO/    iot-sink
YOLO/COCO    标注       YOLO微调   ONNX/TRT   集群调度   TASK     邮件/IM
ImageFolder  Worker     SAM/LLM    OpenVINO   负载均衡   RUNTIME   钉钉/飞书
                                  + AlgoMqttBus (MQTT 信封 → iot-sink)
```

#### 2.3.2 视频智能分析流水线

```
摄像头接入 → 流拉取 → 帧提取 → AI 推理 → 结果排序 → 告警/存储
    │           │        │        │         │          │
    ▼           ▼        ▼        ▼         ▼          ▼
GB28181/     SRS/ZLM   FFmpeg   YOLO     去重+最优   NFS(录像/告警图)
ONVIF/RTSP   流媒体    解码      ByteTrack 帧选择     AlgoMqttBus(告警)
海康/大华    中转                          + Kafka(事件)   iot-sink→Kafka
                                                       MinIO(归档)/Milvus(人脸)
```

#### 2.3.3 IoT 设备数据流

```
传感器/RTU采集器
    │
    ├─ Modbus TCP/RTU ─┐
    ├─ OPC UA ─────────┤
    ├─ MQTT → EMQX ───┤
    ├─ TCP 长连接 ─────┤
    └─ HTTP 上报 ──────┤
                       ▼
              iot-sink (协议适配层)
                ├─ Redis (设备影子实时刷新)
                ├─ TDengine (时序历史数据)
                └─ Kafka (告警/后处理事件)
                       │
                       ▼
              WEB 仪表盘 / APP
              实时曲线 / 历史查询 / 告警
```

### 3.2 Java 微服务模块详解

#### 3.2.1 API/BIZ 双层分层模式

所有业务模块遵循标准 **api / biz 双层** 架构：

```
iot-xxx/
├── iot-xxx-api/               ← Feign 接口 + DTO + 常量 (对外暴露)
│   └── src/main/java/.../
│       ├── Remote*.java       ← @FeignClient 接口
│       ├── domain/            ← DTO/VO/BO/QO
│       ├── enums/             ← 枚举常量
│       └── factory/           ← FallbackFactory 降级工厂
│
└── iot-xxx-biz/               ← 业务实现 (不对外暴露)
    └── src/main/java/.../
        ├── controller/        ← REST Controller (admin/app)
        ├── service/           ← 业务接口 + impl/
        ├── dal/
        │   ├── dataobject/    ← DO (MyBatis-Plus Entity)
        │   └── pgsql/         ← Mapper (MyBatis-Plus)
        ├── convert/           ← MapStruct 转换器
        ├── framework/         ← 模块级安全/RPC/文件配置
        └── mq/                ← 消息消费者/生产者
```

### 3.4 C++ TASK 推理引擎

```
main.cpp → Manage (Server) → ConfigParser (INI 配置)
         → Yolov11Engine (ONNX Runtime 封装)
         → Yolov11ThreadPool (每线程独立 Session, 默认 3 线程)
         → Detech (核心检测引擎, ~44KB)
         → Draw (绘制检测框)
         → RTMPEncoder (H.264 编码 + RTMP 推流)
         → AlgoMqttBus (MQTT 告警信封发布，取代旧 HTTP AlarmCallback)
```

**告警标准链路（C++ → iot-sink）：**

> RUNTIME/TASK 检测到告警 → 写告警图到共享 NFS 的 `ALERT_IMAGES_DIR`，
> 经 `AlgoMqttBus` 发布 MQTT 信封到 `mqtt/iot-alert-notification`（msgType=`alert.notification`）
> → iot-sink 的 `IotAlgoBusMqttHandler` 订阅、落库、从 VIDEO 库补齐通知配置后转发 Kafka 通知；
> 录像由 SRS/ZLM `on_dvr` Hook 命中 iot-sink `MediaHookController` → `DvrUploadService`
> 从 NFS 读盘上传 MinIO 并回填 `playback`/`alert.record_path`。
>
> MQTT 信封：`{version,msgId,msgType,tenant,ts,payload}`；三对 topic/msgType：
> `mqtt/iot-alert-notification`/`alert.notification`、`mqtt/iot-snapshot-alert`/`alert.snapshot`、
> `mqtt/iot-post-process-request`/`post_process.request`；iot-sink 用 `$share/algo-sink/` 共享订阅组消费。
>
> 总开关 `ALGO_BUS_TRANSPORT`：默认空=MQTT；`http/off/0/false/no`=关闭回退 HTTP（旧 AlarmCallback，已废弃）。
> 心跳仍走 HTTP→VIDEO（`/video/algorithm/heartbeat/{realtime,patrol}`）。

**线程模型 (6 类线程)：**

| 线程 | 数量 | 职责 |
|------|------|------|
| 主视频循环 | 1 | FFmpeg 解码 → 显示 → 推理提交 → 绘制 → 推流 |
| YOLO Worker | N (默认 3) | ONNX Runtime 并行推理（独立 Session） |
| 告警发送 | 1 | 消费告警队列，MQTT publish 到 AlgoMqttBus（QoS1） |
| HTTP 控制 | 1 | 运行时启停推流的 REST API + 心跳上报 VIDEO |
| 等待退出 | 1 | 10ms 轮询检测退出信号 |
| 信号处理 | 1 (系统) | Ctrl+C / SIGTERM |

| **消息解耦** | Kafka 异步事件流（告警/后处理/匹配） |

### 4.4 MyBatis-Plus 数据层增强
